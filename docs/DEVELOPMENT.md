# Руководство разработчика

Как устроена работа над игрой: запуск, тесты, консольные проверки, демо-карта, параметры адреса, отладка в браузере, графика в Blender и выкладка. Об устройстве кода (модули, инварианты, данные) подробно написано в [CLAUDE.md](../CLAUDE.md), план и долги — в [ROADMAP.md](ROADMAP.md), сверка с оригиналом — в [S4-PARITY.md](S4-PARITY.md) и [S4-AUDIT.md](S4-AUDIT.md), времена и пропорции — в [TIMINGS.md](TIMINGS.md) и [PROPORTIONS.md](PROPORTIONS.md), стиль графики — в [ART-STYLE.md](ART-STYLE.md), обучение — в [TUTORIAL.md](TUTORIAL.md).

## 1. Установка и запуск

- **Node.js 20.19+** (столько требует Vite 8; сборка на GitHub Actions идёт на Node 22).
- `npm install`. Зависимость у игры одна, PixiJS 8; инструменты разработки — TypeScript, Vite, Vitest и tsx.
- `npm run dev` запускает dev-сервер Vite. Адрес он печатает сам, по умолчанию http://localhost:5173/ (порт в `vite.config.ts` не задан; если он занят, Vite берёт следующий).
- `npm run build` — проверка типов и production-сборка в `dist/`. `npm run preview` раздаёт собранный `dist/`.
- `npm run typecheck` — только `tsc --noEmit` (строгий режим, `noUnusedLocals`/`noUnusedParameters`).

Для графики дополнительно нужны **Blender 5.x** в `PATH` и **Python 3 с Pillow** (см. раздел 7). Для игры и тестов они не нужны: готовые картинки лежат в репозитории.

### Структура проекта

```
src/sim/        симуляция: чистый TypeScript без DOM и Pixi, детерминированная, 10 тиков в секунду
src/render/     рендер на PixiJS: изометрия, чанки, атлас, 3D-спрайты и процедурные художники, эффекты
src/audio/      звук на WebAudio: синтез эффектов, музыка, громкость и панорама
src/ui/         HTML-интерфейс (левая панель, окна), ввод мышью и клавиатурой, общее состояние; i18n.ts — языки
src/i18n/       словари интерфейса: ru.ts (основной, задаёт ключи), en.ts, de.ts
src/dev/        демо-карта ?demo (showcase.ts)
src/net/        сетевая игра (фаза 6, docs/NETWORK.md): транспорт (PeerJS, петля в памяти), lockstep; проверка — nettest.html
src/tutorial/   обучение: миссии (данные), условия, якоря, автомат шагов, панель целей (docs/TUTORIAL.md)
src/main.ts     точка входа: параметры адреса, создание мира, игровой цикл
tests/          тесты Vitest (*.test.ts)
tools/          консольные проверки: probe.ts, bench.ts, aivsai.ts (+ общие помощники scenario.ts)
art/            Blender: модели и рендер (art/blender), фактуры земли (art/textures), ужатие PNG (art/tools)
public/art/3d/  готовые 3D-спрайты и их описания (*.json); попадают в сборку как есть
docs/           план (ROADMAP), сверка с S4 (S4-PARITY, S4-AUDIT), тайминги, пропорции, стиль графики, обучение, это руководство
```

Зависимости слоёв односторонние: `ui → render → sim`. В `src/sim` нельзя импортировать DOM или Pixi — иначе симуляция перестанет работать в тестах и консольных проверках.

## 2. Тесты

```bash
npm test                                     # все тесты (vitest run)
npx vitest run tests/world.test.ts           # один файл
npx vitest run -t "builds a site"            # тесты, в названии которых есть строка
npx vitest tests/trade.test.ts               # режим наблюдения: перезапуск при изменениях
```

`vitest.config.ts`: таймаут теста 60 с (часовые экономики и партии ИИ на загруженной машине не укладываются в стандартные 5 с; отдельные тесты задают свой, например `{ timeout: LONG }` в `ai.test.ts`); папка `.claude/` исключена — там лежат рабочие копии параллельных агентов (раздел 8), их тесты здесь запускаться не должны.

**Что проверяют тесты** (по группам, файлы в `tests/`):
- **Детерминизм и сохранение.** `save.test.ts`: мир, сохранённый посередине и загруженный, продолжает побайтно так же, как исходный (`saveWorld(b)` равно `saveWorld(a)` после ещё 3000 тиков); сохранение чужой версии отвергается. Такие же проверки «сохранить посреди процесса → продолжить одинаково» есть для ИИ, боя, лазарета, животных, земляных работ и тумана (`ai`, `army`, `army-s4`, `animals`, `digging`, `fog`), а «тот же сид — та же партия» — в `ai.test.ts`.
- **Инварианты.** `world.test.ts`: счётчики резервирований никогда не уходят в минус, доски и камень сохраняются (не появляются и не пропадают), здания не замуровывают единственный проход, носильщик, отрезанный от цели, кладёт груз на землю, а не теряет его; на стопке на земле никогда не обещано больше, чем лежит.
- **Экономика и мир:** `economy`, `food`, `mining`, `tools`, `workArea`, `idle`, `trade` (рынки, ослы, куски земли), `storage` (вместимость складов), `ground` (товары на земле), `stop` (остановка зданий), `beds` (кровати и забастовка), `jobless` (безработные рабочие), `territory` (земля по влиянию), `walk` (пути по своей земле), `timings`, `s4-economy`, `s4-growth`, `s4-supply`, `s4-items`, `s4-leftovers` (правила S4 по аудиту), `terrain`, `rivers`, `biomes`, `regions`, `pathfinding`, `digging`.
- **Война и ИИ:** `military`, `army`, `army-s4`, `garrison`, `combat`, `field`, `control`, `allies`, `specialists`, `specialist-orders`, `intruders`, `ai`, `ai-tactics`, `aiField`, `fog`.
- **Рендер, звук и интерфейс без браузера:** `anim` (выбор кадров и направлений), `rocks` (раскладка камней гор), `audio-mix` (затухание, панорама, ограничение частоты), `selection` (выбор юнитов по правилам S4), `setup` (настройка партии и параметры адреса), `i18n` (словари трёх языков).
- **Обучение:** `tutorial.test.ts` — каждая готовая миссия проходится без браузера «игроком» из `SOLUTIONS` (`tests/tutorialPlay.ts`) в отведённое время, якоря находятся (`spot` — когда шаг начинается: у каждого показанного шага все стрелки на карте), сохранение посреди миссии продолжается так же, тексты заполнены на трёх языках; `tutorial-engine.test.ts` — каждый вид условия, настройки, проверки интерфейса и якоря (да/нет), блокировки и их наследование, автомат шагов (пропуск сделанного, но не «Дальше»), пополнение, отметки о прохождении, `?tutorial`.
- **Демо-карта:** `showcase.test.ts` — в `?demo` есть каждое здание, замороженные этапы стройки, кучи товаров, специалисты, рынок, отряд и т. д. (раздел 4).

**Как добавить тест.** Новый файл `tests/<тема>.test.ts` или новый `it(...)` в подходящем. Мир создаётся напрямую: `new World(seed, { size, players, ai, teams, start })`, двигается циклом `world.step()`, здания ставятся через `world.canPlace`/`world.placeBuilding` (поиск места рядом — `placeNear` из `tools/scenario.ts` или локальный помощник, как `findSpot` в `world.test.ts`). Время в тиках: `TICKS_PER_SECOND` из `config.ts` (10). Если фича добавляет состояние симуляции, добавьте проверку «сохранить посередине → загрузить → продолжить одинаково». Новое здание, ресурс или видимое состояние должно появиться и в демо-карте, а её тест — это проверять.

## 3. Консольные проверки (headless)

Запускаются через `tsx` без браузера; параметры — после `--`, в виде `--имя=значение`. **Одновременно запускайте только одну тяжёлую задачу** (проверку, полный прогон тестов, рендер Blender): параллельные прогоны мешают друг другу, и замеры скорости становятся бессмысленными.

### `npm run sim:probe` — здоровье экономики

Стандартное начало партии (каменотёс, три лесоруба на лесопилку — как требуют темп и цены Settlers 4, два лесничих — деревья сами не сеются, дома, первый склад сразу — он забирает стартовые товары с земли, еда, башня, шахты, плавильня, инструментальщик, ещё два склада — по расписанию в минутах; на каждом складе инструмент отмечает все товары, иначе новый склад, как в S4, ничего не принимает) на нескольких картах; здание без места пробует снова каждую минуту, а через 10 минут ищет место в радиусе 24 клеток вместо 12. Печатает производство по окнам, итог по зданиям и поселенцам, запас складов вместе с занятыми стопками (`piles 22/24`: склад держит 8 стопок по 8), что осталось лежать на земле (`on the ground N in K piles`), потерянные товары (`lost`), здания с недостижимой дверью (`blocked doors`) и мс/тик.

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `--seeds=` | `42,7,123,999` | сиды через запятую |
| `--minutes=` | `60` | длительность партии |
| `--size=` | `64` | размер карты |
| `--window=` | `20` | ширина окна сводки производства, минуты |

**Когда:** до и после любого изменения экономики или баланса. Здоровый результат — все 28 зданий достроены, `lost 0`, `blocked doors 0`, производство не падает по окнам. Ориентир скорости: час игры на 64×64 ≈ 0,02 мс/тик. Размер по умолчанию остаётся 64 (как у `sim:ai`), хотя в браузере партия по умолчанию идёт на 128×128: так замеры сравнимы с прежними.

### `npm run sim:bench` — скорость симуляции

Большая карта целиком отдана игроку, на ней кластеры производства (лесоруб, лесничий, лесопилка, каменотёс) и заданное число поселенцев; инструментов хватает на все рабочие места. Печатает среднее и худшее мс/тик и статистику A* (поисков за тик, доля неудачных, узлов на поиск).

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `--size=` | `256` | размер карты |
| `--settlers=` | `1000` | число поселенцев |
| `--ticks=` | `3000` | длительность замера (после 600 тиков разогрева) |
| `--seed=` | `42` | сид |

**Когда:** до и после всего, что меняет работу за тик. Ориентиры (Apple Silicon): 256×256 с 1000 поселенцев ≈ 0,6 мс/тик, 3000 поселенцев ≈ 1,1 мс/тик (с шагом S4 поиски пути реже); `--size=1024` (12 тыс. зданий, 1000 поселенцев) ≈ 3 мс/тик. Бюджет при 10 тиках в секунду — 100 мс, но работа за тик должна расти с числом активных объектов, а не с площадью карты.

### `npm run sim:ai` — компьютер против компьютера

Партии ИИ против ИИ (или против пассивного игрока 1). Каждые несколько минут печатает по игрокам здания, поселенцев, бойцов (лучники, с уровнем, командиры), землю и статистику ИИ (поставлено зданий, атак, послано бойцов, геологов, полевых обороны, торговли); в конце — каждый выбывший с минутой выбывания, победитель и мс/тик.

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `--seeds=` | `42,7,123` | сиды |
| `--minutes=` | `150` | длительность, минуты игры (в темпе S4 партии идут 60–120 минут) |
| `--size=` | `64` | размер карты |
| `--players=` | `2` | число игроков |
| `--passive=1` | выкл. | игрок 1 без ИИ (проверка, что ИИ побеждает бездействующего) |
| `--teams=1,1,2,2` | нет | команды по игрокам; партия кончается, когда победила одна сторона |
| `--levels=easy,hard` | все `medium` | сложность ИИ по игрокам (`AI_LEVELS`; `medium` в точности равен таблице `AI`) |
| `--every=` | `10` | интервал сводки, минуты |
| `--cost=1` | выкл. | дополнительно: доля ИИ в цене тика — партия до 20-й минуты, затем 3 минуты с ИИ и без него (лучшее из 3) |

**Когда:** после любого изменения ИИ, экономики или боя — видно, растут ли компьютерные игроки и доводят ли партии до конца. Обычный набор для сравнения «до/после» (см. итоги в ROADMAP): 64×64 на сидах по умолчанию, `--passive=1`, 96×96 на сидах `11,12,8`, 128×128 на сидах `42,7` и с `--players=4`.

## 4. Демо-карта `?demo`

`?demo` (например, http://localhost:5173/?demo или https://dik-garri.github.io/settlersga/?demo) открывает не обычную партию, а витрину для разработки: `buildShowcase()` из `src/dev/showcase.ts` (модуль подгружается лениво, только с этим параметром). Карта 128×128, сид 7 (`SHOWCASE_SEED`), второй — пассивный — игрок далеко. Мир сам обстраивается за пару секунд:
- стартовая малая башня; рядом склад со всеми отмеченными товарами и большим запасом, свободные мечники и лучники (каждая готовая башня зовёт одного), носильщики и землекопы; два кольца башен расширяют землю, потом их заполняют приказом «Заполнить»; в казарме заказаны два мечника и лучник 3-го уровня — они выходят и стоят у неё;
- каждое здание, которое можно строить, стоит готовым и с работником, рабочие работают;
- ряд строек, замороженных на каждом этапе (`STAGE_PROGRESS`: нерасчищенная, 10%, 42%, 75%), для каждого типа;
- двор склада с товарами и готовые хижины с кучами всех товаров (по четыре вида у двери, количество от 1 до 12 — видно, как куча делится);
- олени у охотника, геолог на горе и поле его табличек (все руды с одним, двумя и тремя знаками), первопроходец у границы, вор у склада второго игрока, протоптанные тропы, болтающие группы носильщиков;
- отрезанная застава с рынком, куда ослы с рынка у старта везут доски и камень на стройку, и товары, лежащие на земле рядом с ней (там их никто не заберёт);
- полевой отряд вокруг командира и раненые, идущие в лазарет;
- остановленные игроком лесопилка и стройка (значок паузы над крышей) и лесоруб без работы, ждущий новую хижину (добавленным носильщикам даны кровати, поэтому забастовки нет).

Замороженные объекты помечены `unreachableUntil = Number.MAX_SAFE_INTEGER`: логистика, строители и землекопы их пропускают. Это инструмент разработчика: витрина лезет во внутренности симуляции (прямое создание поселенцев, готовые здания без стройки), обычная игра так никогда не делает.

Туман в демо по умолчанию выключен (`?fog=on` включает); `?art=classic` работает и здесь. Остальные параметры партии (`?seed`, `?size`, `?players`…) демо игнорирует.

**Как добавить что-то в витрину:** допишите шаг в `buildShowcase()` (по образцу соседних: место ищут `placeNear`/`placeFor`/`openGround`, `run(w, ticks)` проматывает время) и проверку в `tests/showcase.test.ts`. Правило: новое здание, ресурс или видимое состояние должно быть в витрине — тест следит, что каждое строимое здание там есть готовым.

## 5. Параметры адреса

Без параметров страница открывает заставку (при каждом запуске, если она не выключена в настройках) и главное меню; любой параметр партии из таблицы ниже запускает игру сразу, минуя меню (`launchOf` и `devWorldArgs` в `src/ui/setup.ts`, тесты — `tests/setup.test.ts`). Пример: `http://localhost:5173/?seed=42&size=128&players=4&teams=1,1,2,2`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `?seed=N` | случайный | сид карты; текущий сид пишется в консоль браузера («add ?seed=… to replay this map») |
| `?size=N` | `128` | размер карты (играбельно до 1024; в меню «Новая игра» — 64, 96, 128, 160, 192, 256, 320, 384, 512; по умолчанию и там 128) |
| `?players=N` | `2` | число игроков; игрок 1 — вы, остальные под управлением компьютера |
| `?ai=off` | ИИ включён | соперники пассивны (ничего не делают) |
| `?teams=1,1,2,2` | все против всех | команда каждого игрока по порядку: союзники не нападают друг на друга, побеждают вместе и делят туман войны |
| `?start=low\|medium\|high` | `medium` | запас на старте («Мало / Средне / Много», `START_CONDITIONS`) |
| `?levels=easy,hard` | все `medium` | сложность компьютера по игрокам (`AI_LEVELS`), как `--levels` у `sim:ai` |
| `?fog=off` | туман включён | выключить туман войны (в `?demo` наоборот: `?fog=on` включает) |
| `?art=classic` | 3D-графика | старые процедурные спрайты вместо 3D из Blender |
| `?lang=ru\|en\|de` | выбор в настройках, иначе язык браузера (en/de), иначе `ru` | язык интерфейса на эту страницу (выбор в настройках не меняется; параметр сохраняется при выходе в меню, загрузке и «Новой игре» с экрана итогов). Партию не запускает: `?lang=de` — это меню по-немецки |
| `?load=1` | — | загрузить последнее сохранение (`?load=<id>` — ячейку с этим id; так грузит меню игры); параметр сразу убирается из адреса, чтобы обновление страницы не загружало снова |
| `?demo` | — | демо-карта для разработки (раздел 4) |
| `?tutorial=<id>` | — | миссия обучения (`forest`, `logistics`, `bread`, `metal`, `trade`, `battle`; см. `MISSIONS` в `src/tutorial/missions.ts`); `&step=<n>` — начать с шага n (с 1): товары предыдущих шагов выдаются, их блокировки открываются. Туман — как в миссии, `?fog=off` его выключает. Готовой миссии нет — открывается меню |
| `?menu` | — | открыть главное меню, даже если есть другие параметры, и без заставки (`?menu=new` — сразу экран «Новая игра»; так возвращаются из партии); параметр сразу убирается из адреса, так что обновление страницы — обычный запуск с заставкой |

**Меню и сохранения в браузере** (`localStorage`, всё под try/catch):
- `settlers.prefs` — оформление (3D/классика), `lang` (язык, выбранный в настройках; нет — по `?lang`/браузеру) и `showIntro` (показывать ли заставку при запуске; по умолчанию да, старые поля `intro`/`introSeen` больше не читаются). Заставку можно посмотреть и кнопкой «Показать заставку» в настройках меню.
- `settlers.setup` — последняя настройка партии экрана «Новая игра».
- `settlers.tutorial` — пройденные миссии обучения (`{ done: { <id>: { at, minutes } } }`, лучшее время); прогресс миссии посреди игры лежит не здесь, а в описании ячейки сохранения (`SlotMeta.mission`).
- `settlers.saves` — список сохранений (название, дата, размер, игроки, тик), сами партии — `settlers.save.<id>`, сжатые gzip (`CompressionStream`, префикс `gz:`; партия 256×256 — около 150 КБ вместо 2 МБ JSON); `settlers.save.auto` — автосохранение каждые 5 минут игры; старая единственная ячейка `settlers.save.v1` показывается в списке, пока её не удалят.

Партия из меню начинается без перезагрузки страницы: сцена меню (`TitleScene`) снимается со сцены Pixi, атлас остаётся. Загрузка из меню игры и выход в главное меню перезагружают страницу (`?load=<id>`, `?menu`). В меню `window.scene` и `window.menu`, в игре — как раньше `world`, `state`, `renderer`, `camera`, `audio` плюс `pause` (меню игры) и `tutorial` (вид миссии обучения, `null` в обычной партии; `tutorial.runner.model(world)` — текущий шаг, цели, метки).

### Обучение: как добавить миссию или шаг

Устройство — в [TUTORIAL.md](TUTORIAL.md) (§3). Миссия — запись `MissionDef` в `src/tutorial/missions.ts`, без кода:
1. **Карта и старт:** `world` (сид, размер, игроки, стартовый уровень — общий `start` или по игрокам `starts`, туман; противник не в `ai` — пассивный) и, если нужно, `scenario` — готовые здания (`near` — сдвиг от старта, место ищется по спирали `canPlace`; `worker: true` — с готовым рабочим, `tag` — имя для якоря `building … scenario`, `garrison`/`archers` — бойцы внутри, `founding: true` — застава на ничьей земле, `piles` — товары у её двери), стопки товаров, люди, число кроватей (`src/sim/scenario.ts`).
2. **Что открыто:** `unlock` (здания, главные меню, поручения специалистов); открытое наследуется следующими миссиями (`locksFor`), шаг может открыть ещё (`StepDef.unlock`).
3. **Шаги:** `text`/`more`/`hint` — ключи словарей (`tut.<миссия>.<шаг>`, `.more`, `.hint`), `params` — что подставить в `{…}` (`building`, `res`, `prof`, `n`, `label` — подпись кнопки по ключу, `key` — клавиша-модификатор, как её называет клавиатура игрока: ⌘ на Mac, Strg по-немецки); `ui` — цепочка меток `data-ui` для подсветки (тип `UiTarget` в `src/ui/uiTarget.ts`; новой метке — `tag(el, id)` на элементе); `camera`, `marker`, `ring` — якоря (`src/tutorial/anchors.ts`, не координаты); `done` — условие (`src/tutorial/conditions.ts`); `grant` — товары при входе.
4. **Цели** (`objectives`) — список в панели; миссия выиграна, когда пройдены все шаги и выполнены все цели.
5. **Тексты** — во все три словаря (`src/i18n/ru.ts`, `en.ts`, `de.ts`); названия зданий и товаров не пишутся, а подставляются; в русском — в кавычках и в именительном падеже («Постройте «{building}»»), чтобы не ломать падежи.
6. **Решение для теста:** запись в `SOLUTIONS` в `tests/tutorialPlay.ts` — что сделал бы игрок на каждом шаге (публичные команды и поддельный интерфейс). Тест проверяет, что все якоря находятся, миссия выигрывается не дольше `minutes × 1,5`, прогресс переживает сохранение и загрузку, а каждый `{…}` в текстах заполнен. Сид подбирают так, чтобы тест проходил.

Новый вид условия, якоря, настройки или проверки интерфейса — одна запись в таблице (`CONDITIONS`, `ANCHORS`, `SETTINGS`, `UI_CHECKS`; компилятор требует запись для каждого вида) и пример «да/нет» в `tests/tutorial-engine.test.ts`. Отладка: `?tutorial=<id>&step=<n>` и `world.step()` в цикле из консоли (автомат проверяет условия каждый кадр).

### Языки интерфейса

Интерфейс есть на русском (основной), английском и немецком. Все тексты, которые видит игрок, лежат в словарях `src/i18n/ru.ts`, `en.ts`, `de.ts`; в коде их нет. Словарь — плоский объект «ключ → строка», ключи с префиксом по месту (`menu.new`, `info.status`, `doing.toSite`…); названия того, что есть в симуляции, — по id: `building.<тип>`, `prof.<профессия>`, `res.<товар>`, `msg.<вид сообщения>`, `category.*`, `group.*`, `start.*`, `ai.*`, `race.*`, `order.*`. Симуляция языка не знает: в `config.ts` нет названий, сообщения (`World.messages`) хранят вид и параметры, а текст собирает интерфейс (`src/ui/messageText.ts`, `src/ui/names.ts`).

- **Текст в коде:** `t('ключ', { параметры })` из `src/ui/i18n.ts`; названия — `buildingName(type)`, `profName(kind)`, `resName(res)` / `resLower(res)` (название внутри фразы: строчными по-русски и по-английски, по-немецки как есть — `lower()`), `categoryName`, `groupName` и др. из `src/ui/names.ts`.
- **Подстановки** — `{имя}`; числа форматируются по языку (`num`: разделители тысяч с пяти цифр). **Множественное число** — формы через `|`, выбор по параметру `n`: по-русски три (`'{n} клетка|{n} клетки|{n} клеток'`: 1 / 2–4 / 5+), по-английски и по-немецки две (`'{n} tile|{n} tiles'`).
- **Новая строка:** ключ и русский текст в `ru.ts` (он задаёт тип `Key`), перевод в `en.ts` и `de.ts` — без этого не пройдёт `npm run typecheck` (словари типа `Record<Key, string>`: ни лишних, ни недостающих ключей). `tests/i18n.test.ts` дополнительно сверяет подстановки и число форм, ищет кириллицу в en/de и в коде симуляции, проверяет, что у каждого здания, профессии, товара и сообщения есть название. Новое здание или товар без названия в словаре не соберётся (`buildingName` и т. п. принимают только существующие ключи).
- **Новый язык:** словарь `src/i18n/<код>.ts` типа `Record<Key, string>`, код в `Lang`, `LANGS`, `DICTS`, `LANG_NAMES`, `LOCALES` и `PLURAL_FORMS` (`src/ui/i18n.ts`), правило в `pluralIndex`, если формы иные.
- **Выбор языка:** `?lang`, иначе выбор в настройках (`settlers.prefs`), иначе язык браузера, если он английский или немецкий, иначе русский (`pickLang`). В настройках язык меняется сразу: `setLang` шлёт событие `langchange`, главное меню и меню паузы перерисовывают свой экран, мини-карта и кнопки звука — подсказки, а в партии левая панель строится заново (`main.ts`: `Hud.dispose`, новая `Hud` с `memo()` старой — открытое меню, статистика, показанные сообщения, экран итогов). Заголовок страницы и `<html lang>` — из словаря; описание и Open Graph в `index.html` статичны и остаются русскими.
- **Вёрстка:** немецкие слова длинные — проверяйте левую панель и меню на немецком, в обычном и узком окне; длинные названия в строках заказов (`.eco-name`) и заголовке окна переносятся с дефисами (`hyphens: auto` по `<html lang>`).

## 6. Отладка в браузере

В консоли DevTools доступны объекты живой игры (`Object.assign(window, …)` в конце `main.ts`):
- `world` — экземпляр `World` (всё состояние и публичные команды);
- `seed` — сид карты;
- `state` — состояние интерфейса (`speed`, `paused`, `selected`, `selectedSettler`, `selectedUnits`, `groups`, `placing`, `fog`…);
- `renderer` — `GameRenderer`, `camera` — `Camera`, `audio` — `AudioEngine`.

Полезные приёмы:

```js
// Промотать 10 игровых минут (10 тиков в секунду)
for (let i = 0; i < 6000; i++) world.step();

// Скорость и пауза
state.speed = 4; state.paused = true;

// Поставить здание (игрок 1 по умолчанию) и посмотреть, можно ли
const c = world.homeOf(1); // дверь стартовой башни
world.canPlace('sawmill', c.x + 6, c.y + 2) && world.placeBuilding('sawmill', c.x + 6, c.y + 2);

// Что выбрано и что с ним
world.buildings.get(state.selected);
world.getSettler(state.selectedSettler);

// Товары на земле (клетки со стопками), статистика, население; склад принимает товар только после отметки
world.stacks.size; world.stats.produced; world.stats.lost; world.settlers.length;
// Бои по игрокам (убитые и павшие по видам, взятые и потерянные здания) и сообщения с местом на карте
world.stats.war; world.messages.filter((m) => m.player === 1);
world.setAccepts(skladId, 'plank', true);

// Камера на клетку (x, y): экранные координаты = ((x - y) * 32, (x + y) * 16)
camera.centerOn((c.x - c.y) * 32, (c.x + c.y) * 16);

// Обстановка у ИИ (игроки 2…): состояние и статистика его решений
world.ai.map((a) => [a.player, a.stats]);
```

**Проверка сети** (фаза 6, [NETWORK.md](NETWORK.md)): `npm run dev`, затем http://localhost:5173/nettest.html в двух вкладках — «Host» в одной, код и «Join» в другой; «Send»/«Ping» (время туда-обратно), «Lockstep» у хоста — ходы по 100 мс, хэш хода в обеих вкладках, рассинхронизация пишется в журнал; закрытая вкладка у хоста видна как `leave … closed` и «seat N left». Страница есть только у сервера разработки (сборка берёт один `index.html`); `window.nettest` — транспорт, lockstep и журнал. Соединение идёт через публичный брокер PeerJS, нужен интернет.

Для воспроизводимых ошибок: запомните сид из консоли и откройте `?seed=N` с теми же `size`/`players`; или сохраните партию (Esc → «Сохранить») и вернитесь к ней через `?load=1` (последнее сохранение). Симуляция детерминирована, поэтому одинаковые действия на одном сиде дают одинаковый результат; то же в консольных проверках и тестах удобнее, чем в браузере.

## 7. Графика: Blender и конвейер 3D-спрайтов

Вся графика по умолчанию — заранее отрендеренные картинки в `public/art/3d` (около 9,4 МБ, из них ≈ 3,3 МБ — полноцветные фактуры земли: 295 PNG плюс `settlers.json`, `wares.json`, `icons.json`, `ground.json`, `signs.json`). Модели строятся кодом на Python (bpy), рендер — ортографической камерой с проекцией игры, на прозрачном фоне с тенью. Процедурные художники в `src/render/sprites.ts` и `settlerArt.ts` остаются для `?art=classic` и как запасной вариант.

**Что нужно:** Blender 5.x в `PATH` (на macOS, например, `brew install --cask blender`), Python 3 с Pillow (`pip3 install Pillow`) для ужатия.

| Команда | Что делает |
|---|---|
| `npm run art:render` | рендерит всё из `art/blender/build.py`: поселенцев, кучи товаров у дверей и на земле, товары в руках, значки товаров для меню, крылья мельницы, знаки геолога и все одиночные спрайты (здания со стадиями стройки, залежи камня, деревья, мелочи, камни гор, пепелища) |
| `npm run art:render -- sawmill tower` | только перечисленное. Имена: тип здания (`woodcutter`, `sawmill`, `fortress`…, всё из таблицы `SINGLE`), `deposit` (три размера), `trees`, `props`, `piles` или `piles:fish,coal`, `stacks` или `stacks:fish,coal` (товары, лежащие на голой земле: полосы `stacks-<товар>.png`), `ruins` (пепелища `ruin1`…`ruin4` по размеру площадки, `art/blender/ruins.py`), `rocks` (камни гор: `rock-small0..3`, `rock-medium0..2`, `rock-large0..3`, `art/blender/rocks.py`; рендер на процессоре, секунды), `wares`, `icons` или `icons:axe,saw` (значки товаров в меню), `millsails`, `signs` (знаки геолога: полоса `signs.png` + `signs.json`, `art/blender/signs.py`), `settlers` |
| `npm run art:quantize` | после любого рендера: ужимает все 3D-PNG (кроме фактур земли) до 256 цветов, в несколько раз меньше при том же виде |
| `npm run art:render -- settlers:add` | только группы поз, которых ещё нет в `settlers.json` (новое движение или наряд), дописанные на последнюю страницу листа; старые кадры не трогаются, полный перерендер (15 минут) не нужен. Затем ужать эту страницу: `python3 art/tools/quantize.py public/art/3d/settlers-<последняя>.png` |
| `npm run art:settlers` | фигуры поселенцев и солдат (на CPU, около 15 минут; группы поз кэшируются в `art/.tmp/settlers-cache`, прерванный рендер продолжается) и сразу их ужатие |
| `npm run art:animals` | листы животных и большие портреты для окна поселенца (осёл) и их ужатие; выборочно — `-- deer donkey duck chicken portraits` |
| `npm run art:ground` | бесшовные фактуры всех видов земли, полосы полей и троп (`art/textures/ground.py`, Blender нужен ради numpy и записи PNG) |

**Один Blender на машине.** Рендер тяжёлый; если над графикой работают несколько человек или агентов, запускайте Blender только под общей блокировкой:

```bash
until mkdir /tmp/settlers-blender.lock 2>/dev/null; do sleep 5; done
npm run art:render -- sawmill; status=$?
rmdir /tmp/settlers-blender.lock   # освобождать всегда, и при ошибке тоже
```

**Новое здание в 3D:** модель — функция в `art/blender/buildings.py`, строка в `SINGLE` в `build.py` (холст и якорь = `BUILDING_CANVAS` в `sprites.ts`), та же строка в `ART3D_BUILDINGS` в `src/render/art3d.ts`; стадии стройки помечаются тегами (`lib.tag`), дым и знамя записываются при рендере (`note_fx`, `note_banner`) и переносятся в `ART3D_FX`/`ART3D_BANNERS`. Новый товар — запись в `GOODS` и в `ICONS` в `art/blender/goods.py` (значок для меню: лежит кучкой или стоит наискосок, при надобности — своя модель покрупнее), затем `art:render -- piles:<товар> stacks:<товар> wares icons` и `art:quantize`. Новая профессия обычно ничего не требует, если не приносит новый инструмент или движение; новое движение — запись в `ACTIONS` в `animConfig.ts` и в `figures.py` (с наклоном корпуса — ещё `BEND`), затем `art:render -- settlers:add`. Подробности соглашений — в CLAUDE.md, раздел «3D art».

**Снимки оригинала и оригинальность.** Внутриигровые снимки Settlers 4, по которым сверяется стиль, лежат только локально в `examples/` (папка в `.gitignore`, например `examples/ref-<type>.png`): графика принадлежит Ubisoft, снимки никогда не публикуются и не копируются в игру. Берём приёмы, тип здания, силуэт, материалы и пропорции, а модели, детали, эмблемы и значки — свои; в интерфейсе тоже ничего не вырезается из снимков. Что именно берём из оригинала и что уже сделано — в [ART-STYLE.md](ART-STYLE.md).

**Значки в интерфейсе.** Значки товаров в меню (окно склада и рынка, меню товаров, распределение, строка запасов, цены в меню строительства, статистика) берутся из `icons.png`: по квадрату 96×96 на товар, отрендеренному крупно (брёвна, камень, уголь, руда, слитки — кучкой, инструменты и оружие — стоя наискосок, рабочей частью вправо вверх). Значки рисуются в canvas с плотностью экрана (`devicePixelRatio`), большие картинки уменьшаются ступенями по половине, маленькие не растягиваются: портрет поселенца и картинка здания не увеличиваются больше своего размера, у осла есть отдельный крупный портрет. Без `icons.png` значки берутся из товаров в руках, в `?art=classic` — из процедурных художников.

После рендера проверьте результат в игре (обычная карта и `?demo`) и в `?art=classic` — классический режим не должен сломаться.

## 8. Порядок работы

1. **Перед новой фичей** загляните в [ROADMAP.md](ROADMAP.md) (фаза, долги) и, если механика есть в Settlers 4, в [S4-PARITY.md](S4-PARITY.md).
2. **Проверка изменения:**
   - `npm run typecheck` и `npm test` — всегда;
   - `npm run build` — если меняли сборку, ассеты или импорты;
   - `sim:probe` до и после — экономика и баланс; `sim:bench` до и после — всё, что работает каждый тик; `sim:ai` — ИИ, экономика, бой;
   - проверка в браузере (`npm run dev`, обычная карта и `?demo`) — если менялись рендер или интерфейс.
3. **Документация в том же коммите:** `README.md` (для игрока, по-русски) и его переводы `README.en.md`, `README.de.md`, `CLAUDE.md` (устройство кода), это руководство (команды, параметры проверок и адреса), ROADMAP и S4-PARITY (что сделано и что дальше), TIMINGS и PROPORTIONS (времена и размеры против S4), ART-STYLE (графика).
4. **Коммит и push в `main`.** Каждый push в `main` запускает `.github/workflows/pages.yml`: `npm ci`, `npm run build` на Node 22 и публикацию `dist/` на GitHub Pages — https://dik-garri.github.io/settlersga/. Тесты выкладку не останавливают, поэтому запускайте их до push. `vite.config.ts` задаёт относительный `base: './'`, чтобы сборка работала из подпапки сайта.

**Сохранения и `SAVE_VERSION`.** Всё новое состояние симуляции добавляется в `SaveData` (`src/sim/save.ts`) и должно оставаться простыми данными (без классов, замыканий, функций). Если старые сохранения больше не загрузятся, увеличьте `SAVE_VERSION` (сейчас 32); тест в `save.test.ts` проверяет, что загруженный мир продолжает побайтно так же.

**Превью ссылки и иконка.** `index.html` задаёт заголовок, описание, Open Graph и Twitter-карточку (абсолютные адреса на GitHub Pages — мессенджеры требуют полный путь к картинке). Картинка превью — `public/og-image.jpg` (1200×630, снимок `?demo` без боковой панели), иконка вкладки — `public/favicon.svg` (наш щит с башней). Если внешний вид игры заметно изменился, переснимите `og-image.jpg`: окно 1200×630, скрыть `.side`, `.strip`, `.hint`, `.ticker`, навести камеру на поселение. Мессенджеры кешируют превью, поэтому новая картинка появится не сразу.

**Масштабируемость — обязательное требование** (подробно — в CLAUDE.md):
- новое здание, профессия, ресурс или рецепт — запись данных в `config.ts` (и спрайт), а не ветка `if (type === …)` в логике;
- всё, что кому-то принадлежит, несёт `owner`; логика никогда не предполагает одного игрока;
- никаких зашитых размеров карты и численности; работа за тик растёт с числом активных объектов, а не с площадью карты или квадратом числа объектов; в симуляции только сидированный `Rng`, никакого `Math.random`.

**Параллельная работа в git worktree.** Несколько задач (людей или агентов) можно вести одновременно в отдельных рабочих копиях: `git worktree add .claude/worktrees/<имя> -b <ветка>` (папка `.claude/worktrees` в `.gitignore`, а Vitest её не запускает). Каждая копия коммитит в свою ветку; в `main` ветки вливаются по одной, после rebase или merge на свежий `main` и повторной проверки (тесты, нужные `sim:*`). Типичные конфликты:
- `SAVE_VERSION`: если обе ветки подняли версию, итог — на единицу больше большего из двух, а `SaveData` должна включать поля обеих;
- документы (README, CLAUDE.md, ROADMAP, S4-PARITY): объединяйте текст обеих веток, а не выбирайте одну сторону;
- готовые PNG в `public/art/3d`: перерендерите конфликтующие спрайты на итоговом коде, а не сливайте картинки.

Не используйте общий `git stash` из нескольких копий сразу — стек у них общий; временные изменения лучше сохранить WIP-коммитом в своей ветке. Тяжёлые прогоны (тесты целиком, `sim:*`, Blender) — по одному на машину.
