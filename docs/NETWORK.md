# Сетевая игра (фаза 6)

План сетевой игры: модель lockstep, транспорт, лобби, выход игроков, контрольные суммы, детерминизм в разных браузерах, шаги фазы 6. Написан 10 октября 2026 года вместе с первым кодом (`src/net/`). Сводный план проекта — [ROADMAP.md](ROADMAP.md), фаза 6.

**Решение владельца проекта (10 октября 2026 года):**
- сеть по **lockstep**: по сети идут только команды игроков, каждый браузер сам считает одну и ту же детерминированную симуляцию;
- транспорт — сначала **вариант A**: прямые каналы WebRTC между браузерами, знакомство через бесплатный публичный брокер PeerJS (без учётной записи и ключей) и публичные STUN-серверы;
- **вариант B** — свой релей на WebSocket на Cloudflare Workers (бесплатный план, учётная запись владельца) — отдельным проходом позже, если A окажется ненадёжным. Транспорт заменяемый: игра видит только интерфейс `Transport`.

**Пометки источников** (как в [S4-AUDIT.md](S4-AUDIT.md)):

## 2. Модель lockstep

**Ходы.** Игровое время режется на ходы по `N` тиков (предложение: `N` = 2, то есть 200 мс при 10 тиках в секунду и скорости ×1). Каждый человек за каждый ход сдаёт ровно один пакет команд — возможно, пустой. Пакет, собранный, пока играется ход `t`, исполняется на ходу `t + k`, где `k` — задержка ввода (предложение: `k` = 2, задержка отклика 200–400 мс; для партий через океан — 3–4). Ходы `0 … k−1` пусты у всех и известны заранее, поэтому партия стартует сразу.

**Порядок решает хост.** Клиенты шлют свои пакеты хосту; хост, когда у него есть пакеты всех действующих мест на следующий ход, «запечатывает» ход и рассылает его: пакеты по возрастанию номера места, внутри пакета — в порядке, в каком игрок их отдал, плюс список мест, которые с этого хода играет компьютер. Каждый браузер, хост тоже, играет только запечатанные ходы и только по порядку. Поэтому порядок команд одинаков у всех по построению, а спорные случаи решаются один раз: две команды одного хода на одну клетку — раньше та, у кого номер места меньше; на каком ходу ушедший игрок сменяется компьютером — решает хост.

**Остановка.** Пока следующий ход не запечатан, игра стоит у всех (рендер и интерфейс живут, тики нет). Медленный или пропавший игрок держит всех — как в S4. Хост знает, чей пакет не пришёл (`waitingFor`); через секунду ожидания интерфейс пишет «Ожидание игрока X», через 30 секунд хост может его отключить (раздел 6).

**Что не передаётся.** Компьютерные игроки думают внутри `World.step` детерминированно, поэтому каждый браузер считает их сам — по сети их команды не идут. Обучение по сети не играется.

**Цикл игры в браузере.** Сейчас `main.ts` копит реальное время и делает до 20 тиков за кадр. В сетевой партии тик `i` принадлежит ходу `⌊i / N⌋`; перед первым тиком хода цикл берёт запечатанный ход (`Lockstep.next()`), применяет его команды через слой команд (6.1) на границе тика и считает `N` тиков; нет хода — ждёт. Отставший браузер догоняет теми же 20 тиками за кадр. После хода — `checksum` каждые `C` ходов и сдача своего следующего пакета (`submit`).

**Скорость** умножает число ходов в реальную секунду; меняется командой хоста, которая начинает действовать на её ходу у всех. Темп партии всё равно держит самый медленный браузер: хост не запечатает ход без его пакета.

## 3. Топология: звезда через хоста

| | Звезда (хост — узел) | Полная сеть |
|---|---|---|
| Соединений при 4 игроках | 3 | 6 |
| Задержка между двумя клиентами | клиент → хост → клиент (два плеча) | одно плечо |
| Кто решает порядок | хост, без договорённостей | нужен общий порядок: сортировка по месту — да, но выход игрока и сохранение всё равно требуют одного решающего |
| NAT | каждому клиенту нужен канал только до хоста | каждой паре нужен канал; одна неудачная пара ломает партию |
| Вариант B (релей) | ложится прямо: релей — тот же узел | релей всё равно превращает её в звезду |
| Нагрузка на хоста | ничтожна: ход — десятки байт, 5 раз в секунду на игрока | — |

**Рекомендация — звезда.** Мест не больше четырёх (`MAX_SLOTS`), трафик крошечный, лишнее плечо задержки покрывается задержкой ввода. Цена — выход хоста: без узла партия у клиентов останавливается (раздел 6).

## 4. Лобби

Экран уже есть: «Сетевая игра» в главном меню — тот же `setupForm` над `GameSetup` с местами «Игрок по сети» (`remote`), кнопка «Начать» пока неактивна (`setupProblem` → `setup.problem.network`). Поток:

1. **Создать.** Хост жмёт «Создать игру»: `peerProvider().host()` регистрирует у брокера id `settlersga-<код>` (код — 6 знаков без похожих символов, `randomCode`). Экран показывает код и ссылку `…/?join=<код>` (новый параметр адреса, добавить в `launchOf`) — их отправляют друзьям.
2. **Войти.** Друг открывает ссылку или вводит код в «Сетевая игра → Войти» (`normaliseCode`). Первым сообщением шлёт версию сборки (хэш коммита из Vite `define`) и `SAVE_VERSION`; при несовпадении хост вежливо отказывает — разные сборки разойдутся с первого хода.
3. **Места.** Хост сажает пришедшего на первое свободное место `remote` (или открывает закрытое). Хост меняет всё; игрок, как в S4, — своё место: команду, расу (пока только римляне), позже цвет. Каждое изменение хост рассылает целиком (`GameSetup` — маленький JSON, `parseSetup` проверяет его на приёме). Пинг каждого игрока — цветом, как в S4. Хост может выгнать (`kick`). Галочка «Готов» у каждого; чат лобби.
4. **Начать.** Когда все готовы и `setupProblem` молчит, хост выбирает сид (если в настройке случайный), назначает места (место = номер игрока, `seat` в `Lockstep`) и рассылает `{ setup с сидом, места, N, k }`. Каждый браузер строит мир `new World(worldArgs(setup).seed, …opts)`, ставит своего локального игрока на своё место и сверяет сумму начального мира на ходу 0 — это ловит расхождения генерации карты (раздел 7) ещё до первой команды. Короткий отсчёт — и ход 0.

**Что поменять в интерфейсе** (шаги 6.4–6.5): `LOCAL_PLAYER` сейчас константа 1, а в сети у каждого браузера свой игрок — нужен `localPlayer` в `GameState`, и рендер, туман, миникарта, окна и сообщения должны брать его оттуда; места `remote` в `worldArgs` — люди, не ИИ (уже так: в `ai` идут только места `ai`).

## 5. Контрольные суммы и рассинхронизация

- **Что считается.** `stateChecksum(world)` (слой команд, 6.1). Чтобы находить, где разошлось, сумма по разделам: состояния ГСЧ (мир, бездельники, животные), поселенцы, здания, игроки и экономика, ИИ, слои карты. Дешёвые разделы — каждый ход, слои карты (O(площади)) — раз в несколько секунд или скользящим хэшем по изменённым чанкам.
- **Как сравнивается.** Каждые `C` ходов (предложение: 5, то есть раз в секунду) каждый отдаёт сумму `Lockstep.checksum`; клиенты шлют её хосту, хост сравнивает со своей и между собой; при первом расхождении рассылает `desync` — у всех вызывается `onDesync` с номером хода и суммами по местам. Совпавшие суммы хост сразу забывает.
- **Что делать.** В отличие от S4, который пишет «DESYNC» и играет дальше, мы ставим партию на паузу у всех и показываем окно на трёх языках: «Партия разошлась на ходу T» — «Скачать отчёт», «Выйти». Позже (6.7) — «Восстановить с хоста»: хост рассылает снимок, все загружают — та же механика, что переподключение.
- **Отчёт** (JSON, сжатый, файл на скачивание) у каждого игрока: сборка, браузер (`navigator.userAgent`), настройка партии и сид, места; последний снимок, на котором суммы ещё совпали (`saveWorld`, держим в памяти каждые M ходов), и журнал команд от него (а без снимка — с начала); суммы по разделам на ходах вокруг расхождения. Инструмент `tools/replay.ts` (6.4): проигрывает журнал без браузера и печатает суммы по разделам по ходам; два отчёта рядом показывают первый тик и раздел расхождения, дальше — поиск по тикам внутри хода.

## 6. Пауза, скорость, сохранение, выход, переподключение

- **Пауза** (≈ отличие от S4): команда любого игрока «пауза» / «продолжить» действует у всех с её хода, на экране — кто остановил. В браузере уйти из вкладки легче, чем из игры на ПК, а без паузы ушедший держит всех молча.
- **Скорость:** настройка лобби (×1 по умолчанию, как в S4) и команда хоста в игре.
- **Сохранение:** команда «сохранить» (любой игрок, не чаще раза в минуту — как `CanSave` в S4) — на её ходу каждый браузер пишет сохранение в свои ячейки; описание ячейки (`SlotMeta`) получает сетевую настройку, места и своё место. Состояния у всех одинаковы, поэтому и сохранения тоже. Автосохранение — у каждого своё, как сейчас (по тикам игры, значит, на том же ходу).
- **Загрузка:** в лобби хост выбирает сетевое сохранение; хост рассылает его клиентам (сжатое, кусками — `PeerTransport` режет длинные сообщения сам), игроки садятся на свои прежние места; кого нет — того играет компьютер.
- **Выход игрока:** у хоста транспорт сообщает `leave` (закрытая вкладка прощается сразу — `pagehide`, оборванная связь видна через 10 с без сердцебиения); хост вызывает `Lockstep.drop(место)`, и первый же запечатанный после этого ход несёт `dropped: [место]`. На этом ходу каждый браузер отдаёт место компьютеру (команда слоя команд вроде `aiTakeover(игрок)`: `World` должен уметь включить ИИ игроку посреди партии со свежим `AiState`) — как `SetPlayerControl` + `ActivatePlayerAI` в S4.
- **Ожидание:** если чей-то пакет не приходит дольше секунды — «Ожидание игрока X» у всех (хост знает кого, клиентам он рассылает это раз в секунду); через 30 секунд у хоста кнопка «Отключить» — дальше как выход.
- **Выход хоста:** без узла партия у клиентов стоит (`onHostLost`). Каждый может сохранить партию на последнем сыгранном ходу (у всех одинаково) и продолжить её потом с новым хостом через загрузку в лобби. Передачу роли хоста на лету не планируем.
- **Переподключение** (6.7): выпавший игрок входит по тому же коду; хост объявляет ход-снимок, шлёт `saveWorld` на нём и все запечатанные ходы после; игрок загружает, догоняет без отрисовки и с хода, объявленного хостом, снова управляет своим местом (компьютер отдаёт).
- **Задержка и пинг:** в 6.4 задержка `k` постоянная, её выбирает хост по пингам лобби: `k = ⌈(наибольший RTT + 100 мс) / длина хода⌉`, не меньше 2 и не больше 6. Подстройка на ходу (6.7) — увеличение `k` хост делает пустыми ходами-вставками, уменьшение — пропуском приёма пакетов на один ход; обе — команды хоста с номером хода.
- **Фоновая вкладка** — главный риск ровности: в скрытой вкладке `requestAnimationFrame` не вызывается, а таймеры урезаются до раза в секунду (в Chrome после нескольких минут — ещё реже) [оценка по документации браузеров]. Спрятавший вкладку игрок не должен останавливать остальных: в сетевой партии цикл продолжает считать тики от таймера (до 10 ходов за пробуждение, без отрисовки), а дальше — симуляция в Web Worker, у которого таймеры не урезаются так сильно [оценка].

## 7. Детерминизм в разных браузерах

Внутри одного движка JavaScript симуляция детерминирована (тест сохранения: загруженный мир продолжает побайтно так же). Между движками — V8 (Chrome, Edge, Node), SpiderMonkey (Firefox), JavaScriptCore (Safari) — гарантированно одинаковы только операции IEEE 754 с точным округлением: `+ − × ÷` и `Math.sqrt` (везде — аппаратная инструкция с правильным округлением; спецификация называет «приблизительными» именно трансцендентные функции), а также `Math.floor/ceil/round/trunc/abs/min/max/sign/imul/fround/clz32`, типизированные массивы и преобразование чисел в строку и обратно (кратчайшая запись — по спецификации). Объединять умножение и сложение в одну операцию (FMA) движки JavaScript не вправе. Всё из `Math.sin/cos/tan/atan2/exp/log/pow/hypot/cbrt` и оператор `**` спецификация отдаёт на усмотрение движка — результат может отличаться в последнем бите.

**Что нашлось в `src/sim`** (поиск 10 октября 2026 года):

| Где | Что | Чем грозит | Замена |
|---|---|---|---|
| `map.ts` `addRidges` | `Math.pow(1 − |2n − 1|, 6)` для каждой клетки карты от 192×192 | **Генерация карты:** бит разницы в высоте может перевернуть порог горы/скалы — карты разойдутся ещё до первого хода | `const r = …; const r2 = r * r; ridge = r2 * r2 * r2` |
| `world.ts` `startPositions` | `Math.cos`, `Math.sin` угла старта, затем `Math.round` | Старт может сместиться на клетку, если значение попадёт на ровно .5 ± бит — маловероятно, но тогда весь мир другой | Таблица синусов/косинусов для нужных углов (кратных π/4 и 2π/игроков — игроков до 4, то есть всего 8 углов) литералами или детерминированный полином (только `+ − × ÷`) после приведения угла |

Других источников расхождения не видно: `Math.random`, `Date`, `performance` в `src/sim` не используются; кеши на `WeakMap` по миру детерминированны; порядок обхода `Map`/`Set` — порядок вставки по спецификации. Остаётся проверить **сортировки** (35 вызовов `.sort` в `src/sim`): с 2019 года сортировка везде устойчива, но если сравнение непоследовательно (возвращает `NaN` или не задаёт строгий порядок), разные алгоритмы (TimSort в V8, слияние в SpiderMonkey и JSC) дадут разный порядок — такие места надо найти и дополнить сравнением по id.

**Как закрепить** (шаг 6.3):
1. `src/sim/fmath.ts`: `dist`, `dist2`, `dsin`/`dcos` (полином на `+ − × ÷`), без трансцендентных функций движка; заменить все вызовы выше. Это может сдвинуть исход игр на бит — после замены прогнать `sim:probe` и `sim:ai` и обновить эталоны, тест сохранения проверит остальное.
2. Тест-запрет (как проверка «нет кириллицы в sim» в `tests/i18n.test.ts`): в `src/sim` нет `Math.hypot|sin|cos|tan|atan|atan2|asin|acos|exp|expm1|log|log2|log10|log1p|pow|cbrt|sinh|cosh|tanh` и оператора `**`.
3. Проверка на разных движках: `tools/determinism.ts` играет закреплённую партию (сид, 4 ИИ, 128×128, 20 минут) и печатает суммы по разделам каждую минуту; её же — dev-страница `determinism.html`. Расхождение — найти раздел, проиграть, заменить функцию.

## 8. Безопасность

Играют друзья, которые доверяют друг другу: защиты от читов, кроме контрольных сумм, нет. Сумма ловит любое изменение состояния (подправленные товары, лишние бойцы), но не подглядывание: у каждого браузера весь мир в памяти, туман войны — только в отрисовке (так устроен любой lockstep, и S4 тоже). Что всё же делаем:
- команда принимается от места, от которого она пришла: слой команд проставляет `player` по месту отправителя, а не из содержимого; команды проверяются самим `World` (свой ли игрок, можно ли строить) — у всех одинаково;
- всё, что пришло по сети, — недоверенный JSON: проверять форму (`parseSetup` уже так делает), не падать на мусоре;
- войти может любой, кто знает код, пока партия не началась; позже — пароль, как в S4 [рук. 4.3.1];
- брокер PeerJS видит id и адреса участников, а WebRTC открывает собеседникам IP-адреса друг друга — обычное дело для P2P, упомянуть в справке.

## 9. Транспорт и lockstep в коде (`src/net/`)

- `transport.ts` — **`Transport`**: `self`, `host`, `isHost`, `code`; `peers()`, `send(to, msg)`, `broadcast(msg)`, `kick(peer)` (хост), `on('message' | 'join' | 'leave' | 'error', …)`, `close()`. Сообщения — JSON, надёжно и по порядку внутри соединения; оборванное соединение — `leave` с причиной `closed` / `lost` / `kicked` и больше не возвращается (переподключение — новый вход). Звезда: у хоста — все клиенты, у клиента — только хост. **`TransportProvider`**: `host(code?)`, `join(code)`. Коды: `randomCode`, `normaliseCode`, `CODE_ALPHABET`.
- `peer.ts` — **`PeerTransport`**, вариант A: `peerjs` (загружается лениво, `import('peerjs')`, в основной сборке его нет), брокер по умолчанию — облако PeerJS (`0.peerjs.com`), ICE — STUN Google и Cloudflare плюс публичный TURN проекта PeerJS на крайний случай (`DEFAULT_ICE`); всё меняется через `PeerTransportOptions.peer` (свой сервер PeerJS, свои STUN/TURN). Каналы надёжные и упорядоченные (`reliable: true`), JSON; сообщения длиннее ~4000 символов режутся на куски (у JSON-канала PeerJS предел ~16 кБ); сердцебиение раз в секунду, тишина 10 с — `lost`; закрытая вкладка прощается (`pagehide`); хост переподключается к брокеру, если потерял его, чтобы новые игроки могли войти (идущие каналы брокеру не нужны). `peerProvider(opts)`.
- `loopback.ts` — **`LoopbackTransport`** / **`LoopbackNetwork`**: та же звезда в памяти для тестов; задержка, разброс, потери (потерянное сообщение приходит повторно через `resend` мс и держит за собой следующие — как поток SCTP), отдельные условия для одного игрока, обрыв (`disconnect`), прощание после сообщений в пути, `VirtualClock` для тестов.
- `lockstep.ts` — **`Lockstep`**, без зависимости от `World`: `submit(cmds)` (пакет на `inputTurn` = ход игры + `delay`; `canSubmit`), `next()` (запечатанный ход или `null` — ждать), `ready`, `buffered`, `waitingFor`, `drop(место)` (хост), `activeSeats`, `checksum(ход, сумма)`, `receive(место, сообщение)`; `onDesync`. Сообщения: `in` (пакет клиента), `turn` (запечатанный ход), `sum`, `desync`.
- `session.ts` — **`bindLockstep(transport, { seats, delay, onDesync, onHostLost, onSeatLeft })`**: места ↔ пиры, конверт `{ ch: 'ls', m }` (по тому же соединению пойдут лобби, чат и снимки — свои каналы `ch`), `leave` клиента → `drop` у хоста, `leave` хоста → `onHostLost` у клиента.
- `nettest.ts` + `nettest.html` — страница проверки для сервера разработки (в сборку не входит): две вкладки, хост и вход по коду, сообщения, пинг, прогон lockstep с хэшем ходов. Проверено 10 октября 2026 года в Chrome: две вкладки соединились через облако PeerJS (RTT ≈ 1 мс), 300+ ходов без расхождения, закрытая вкладка у хоста — `leave … closed` и место отдано на ближайшем ходу без остановки игры (до прощания через `pagehide` обрыв ловился сердцебиением через 10 с).
- Тесты — `tests/net.test.ts`: 2–4 игрока с задержкой и разбросом играют одни и те же ходы в одном порядке, у каждого хода пакеты всех мест ровно такие, как их сдали; потери с повтором; достаточная задержка ввода прячет пинг, малая — даёт остановки; медленный игрок держит всех, и хост знает, кого ждёт; ушедший игрок снимается с одного для всех хода, остальные играют дальше без остановок; клиент вышел сам, хост вышел — клиенты узнают; расхождение суммы находится на нужном ходу, у всех, один раз; совпавшие суммы не копятся.

## 10. Вариант B: свой релей на Cloudflare (позже, если A ненадёжен)

**Когда:** если у заметной доли пар WebRTC не соединяется (строгий NAT, корпоративные сети) или облако PeerJS недоступно. Признак — ошибки `join` с причиной ICE/брокер в журналах игроков.

**Как устроен:** Cloudflare Worker + Durable Object на каждую комнату (код комнаты — имя объекта). Хост и клиенты открывают WebSocket на `wss://<релей>/room/<код>?role=host|join`; объект держит сокеты (Hibernation API, чтобы простой не тратил время), пересылает кадры клиент → хост и хост → клиент(ы) и сообщает о входе и выходе. Lockstep, лобби и порядок по-прежнему у хоста-браузера — релей ничего не знает об игре, только пересылает. В коде — третья реализация `Transport` (`RelayTransport` на WebSocket) и выбор провайдера: сначала A; если канал не открылся за N секунд — B.

**Цена:** бесплатного плана Workers хватает с запасом (запросы считаются при открытии сокета, а не за кадр); Durable Objects доступны на бесплатном плане с хранилищем SQLite и суточными лимитами — проверить лимиты при подключении [оценка]. Трафик партии — килобайты в минуту.

**Что сделать владельцу:**
1. Завести учётную запись Cloudflare (бесплатную).
2. Либо один раз `npx wrangler login` на своей машине (откроет браузер) — и агент сможет выкладывать релей командой `npx wrangler deploy` из папки `relay/`;
3. либо для выкладки из GitHub Actions: создать API-токен (шаблон «Edit Cloudflare Workers») и положить в секреты репозитория `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` — тогда workflow с `cloudflare/wrangler-action` выкладывает релей при изменениях в `relay/`.
4. Адрес релея (`*.workers.dev` или свой домен) — в настройку сборки (`VITE_RELAY_URL`) и параметр адреса для проверки.
