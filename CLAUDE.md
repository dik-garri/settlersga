# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Browser prototype of a Settlers 3/4-style economy game: isometric 2D, sprites, TypeScript + Vite + PixiJS 8. The UI speaks Russian (the primary language), English and German: every player-facing string lives in the dictionaries of `src/i18n` (see Internationalisation below). Original prototype spec (historical, describes only the first version): `docs/superpowers/specs/2026-10-06-settlers-prototype-design.md`. Long-term plan toward Settlers 4 parity, with phases and known tech debt: `docs/ROADMAP.md` — check it before starting a new feature and keep it current. Feature-by-feature comparison with Settlers 3/4 (sourced; what matches, what deliberately differs, what needs fixing, what is excluded): `docs/S4-PARITY.md` — check it when designing a mechanic that exists in S4, and update it with the roadmap. Timings (walking, construction, digging, production) against the original, with sources: `docs/TIMINGS.md`. Proportions (tile vs settler vs building scale, footprints, territory and work radii, map sizes, building costs) against the original, with sources and proposed changes: `docs/PROPORTIONS.md`. Out of scope by decision: magic (temples, priests, mana — and with it wine, whose only S4 use is magic), the Dark Tribe, a map editor, seasons and weather; for now also ships and harbours, and war machines. The developer handbook (setup, tests, headless tools, `?demo`, every URL parameter, browser debugging, the art pipeline, the release workflow) is `docs/DEVELOPMENT.md` (Russian, for humans); keep it current when a command, tool flag or URL parameter changes.

## Workflow

Once a change is verified (tests and typecheck pass, and the game has been checked in the browser when rendering or UI changed), commit and push to `origin main` without asking. Update `README.md` (player-facing, in Russian), its translations `README.en.md` and `README.de.md` (keep all three saying the same) and this file in the same commit whenever the change affects them.

## Scalability is a hard requirement

The target is Settlers 4 scale, so every change must scale along three axes:
- **Content:** a new building, profession, resource or recipe is a data entry in `config.ts` (plus a sprite), never a new `if (type === ...)` branch in sim logic. If a feature cannot be expressed as data, extend the data model (a new `Behavior`, a new rule table) rather than special-casing a type.
- **Players:** everything that belongs to someone carries an `owner` (`PlayerId`); logic filters by owner and never assumes a single player. `LOCAL_PLAYER` is only a default for UI-facing calls.
- **Size:** no hard-coded map dimensions or population assumptions; per-tick work must stay roughly proportional to active entities, not to map area or to entities squared. Measure with the hour-long probe before and after.

## Deployment

Every push to `main` builds the game and publishes it to GitHub Pages (`.github/workflows/pages.yml`: `npm ci`, `npm run build`, deploy `dist/`) at https://dik-garri.github.io/settlersga/. `vite.config.ts` uses a relative `base` so the build works under the repo sub-path. Tests do not gate the deployment, so run them before pushing as described above.

```bash

npm run art:render     # Blender: re-render 3D sprites into public/art/3d (no names = everything; -- <building> deposit trees props piles piles:fish,coal stacks stacks:fish,coal ruins wares icons icons:axe,saw millsails signs settlers settlers:add)

npm run art:animals    # Blender: re-render the animal sheets and unit portraits into public/art/3d (-- deer donkey duck chicken portraits)
```

Long simulations need more than Vitest's 5 s default; `vitest.config.ts` sets a 60 s test timeout and excludes `.claude/` (agent worktrees). Run `sim:probe` before and after any change to economy logic or balance, and `sim:bench` before and after anything that touches per-tick work. Reference numbers (Apple Silicon): 256×256 with 1000 settlers ≈ 0.65 ms/tick (the bench supplies every profession's tool from a warehouse by the start tower so every workplace is staffed), 3000 settlers ≈ 1.1 ms/tick (both down from 1.0 / 2.9 since settlers walk at Settlers 4's pace and search paths less often); a 64×64 hour of play ≈ 0.02 ms/tick; a 512×512 map with 4 AI players generates in ≈ 0.2–0.4 s and plays at ≈ 0.4–0.6 ms/tick in its first minutes; 1024×1024 generates in ≈ 0.5 s, and `sim:bench -- --size=1024` (12k buildings, 1000 settlers) runs ≈ 3 ms/tick — since swamps became impassable, A* searches there explore ~10× more nodes (detours), still far within budget.

Run `sim:ai` after any change to the AI, the economy or combat (it shows whether computer players still grow and still finish games; at Settlers 4's pace games take 60–120 minutes, hence the 150-minute default; the usual set is 64×64 default seeds, `--size=96 --seeds=11,12,8`, `--size=128 --seeds=42,7`). Append `?seed=N` to the dev URL for a reproducible map (the seed is logged to the console) and `?size=N` for another map size (default 128, as a new game from the menu: `DEFAULT_MAP_SIZE` in `ui/setup.ts`; up to 1024; `sim:probe`/`sim:ai` and `new World` stay on 64); `?players=N` sets the number of players (browser default 2, every player but 1 computer-controlled; `?ai=off` keeps them passive); `?fog=off` hides the fog of war; `?load=1` restores the latest save (`?load=<id>` a given slot); `?start=low|high` picks the start level, `?teams=1,1,2,2` the teams, `?levels=easy,hard` the AI difficulty per player, `?art=classic` the procedural art, `?tutorial=<id>&step=<n>` a tutorial mission (from step n, 1-based), `?menu` forces the main menu (the full list is in `docs/DEVELOPMENT.md`). Without game parameters the page opens the intro (every start, unless turned off in the settings) and the main menu. `?demo` opens the dev showcase (`src/dev/showcase.ts`, loaded lazily): a 128×128 world (a second, passive player far away, for the thief) that builds itself up (extra soldiers, carriers and diggers spawned, two tower rings, every buildable type placed and fast-forwarded), then adds construction sites frozen at each stage, finished huts with goods piles of every resource, a pioneer at the border and a thief at a warehouse of player 2's, a field squad of fighters formed round a squad leader — frozen by `unreachableUntil = MAX_SAFE_INTEGER`, which logistics, builders and diggers skip; it defaults to no fog (`?fog=on`), a manned tower out on its own (land cut off from every warehouse) with a market to which donkeys carry planks and stone from the market by the start, goods lying on the ground next to that outpost, a stopped sawmill and a stopped site (pause badges) and a jobless woodcutter (its extra carriers get beds, so nobody strikes), and `tests/showcase.test.ts` keeps it complete. When you add a building, resource or visual state, make sure the showcase shows it. `window.world` (plus `state`, `renderer`, `camera`, `audio`) exposes the live game for poking from DevTools, e.g. `world.placeBuilding('sawmill', x, y)` or calling `world.step()` in a loop to fast-forward.

## Architecture

Three layers with one-way dependencies: `ui → render → sim`, plus `src/audio` (WebAudio, imports only render-side data types) wired up in `main.ts`. `src/sim` must stay free of DOM/Pixi imports so it runs headless in Vitest.

### Simulation (`src/sim`)
- `World` (`world.ts`) holds all state and the public API and advances with `step()` at a fixed 10 ticks/s (`TICKS_PER_SECOND`). Logic lives in sibling modules that take the world as first argument: `buildings.ts` (creation, workshop recipes, `claimsTerritory`), `territory.ts` (who owns the land), `settlers.ts` (task execution, per-behavior idle logic, `abort`), `logistics.ts` (dispatcher, demand), `nature.ts` (trees, planting, gather rules), `military.ts` (garrisons, recruiting, attacks, duels, conquest, `killSettler`), `combat.ts` (blows, shots and duel timing). Fields those modules mutate are public on `World` under "Internal state shared by the sim modules".
- It is deterministic: all randomness goes through the seeded `Rng` (`rng.ts`). Never use `Math.random` in sim code.
- Tile coordinates are integers, and a tile's center is the integer point. Settlers store float `x/y` plus `px/py` (the position at the previous tick) so the renderer can interpolate.
- `GameMap` (`map.ts`) is flat typed arrays indexed by `idx(x, y)`: `terrain`, `tree` (0 means none, 1..`TREE_MATURE` are growth stages, and any tree blocks movement), `stone` (units left in a deposit; blocks while > 0), `owner` (player id, 0 = nobody), `building`, and `door` (both hold building ids, 0 means none). `height` is different: one value per tile **corner**, (w+1)×(h+1), in screen pixels; vertex (vx, vy) is the corner at tile coordinates (vx − ½, vy − ½). Read it through `vertexHeight`, `heightAt` (bilinear, fractional tile coordinates; a tile center is the mean of its corners) and `heightRange`. Heights are generated from the terrain and the height noise (`elevate` in `map.ts`, no RNG use); at runtime only diggers change them, through `setVertexHeight`, which bumps the `heightVersion` of every chunk touching the corner.
- Every building has a **door tile** (`doorOf`: `(x+w-1, y+h)`, in front of the lower-left wall). It is walkable but not buildable. All pickups and drops happen there. For warehouses (`def.storage`, a `StorageDef`), `output` is the stock.
- **Settlers run a task queue** (`Settler.tasks`, union type `Task` in `types.ts`). `updateSettler` executes the head task each tick. An empty queue calls `idle()`, which switches on the profession's `Behavior` from the `PROFESSIONS` table (carrier, builder, digger, gather, plant, farm = harvest if ripe else sow, workshop, garrison, prospect, soldier). Workers are carriers converted by the `become` task — or ready-made workers (`isReadyWorker`: a workplace profession with no home — the start's `START_CONDITIONS.workers`, and, as in Settlers 4, any worker whose workplace was demolished or burnt: `removeBuilding` leaves him in his profession, tool kept, except a `transient` one, the recruit, who is a carrier again; S4 has no command to turn such a worker back into a carrier), whom `dispatchFor` sends to a workplace of their profession or `trade` (`canTakeUp`) before any carrier; meanwhile they wait in the idle crowd (`restIdle` from `idle()`) and flee like carriers.
- **Reservation invariant:** jobs reserve resources up front (`outReserved` on the source — `map.goodsReserved` for goods on the ground —, `inbound` on the destination, `reservedTargets`, `reservedPlots`, `builderIds`, `diggerIds`, `workerRequested`). Any job that can fail must go through `abort()`, which walks the *remaining* tasks and releases what they hold. When you add a task type that reserves something, add its release to `abort()`. `tests/world.test.ts` checks that counters never go negative (and that no ground stack has more promised than lies there) and that planks and stone are conserved, goods on the ground included.
- **Connectivity invariant:** anything that turns a walkable tile into a blocked one at runtime (forester planting, natural tree spread, building footprints via `canPlace`) must first pass `staysConnected` (`pathfinding.ts`): a conservative local check that blocking the tile does not cut any route. `regions.ts` relies on it: walkable regions are a union-find that never needs splitting, so `findPath` rejects unreachable goals in O(1) instead of flooding the map. Anything that makes a tile walkable at runtime must call `markWalkable` (harvest already does).
- **Terrain is data:** `TERRAIN` in `config.ts` holds per-terrain rules — `walkable`, `build` (`'ground'` for ordinary buildings, `'mountain'` for mines, or null), `plantable` (trees, fields, natural spread), `speed` (walking factor ≤ 1; A* charges `TERRAIN_COST` = 1/speed per entered tile — at least `GROUND.pathCost` on a tile with goods on the ground —, so the octile heuristic stays admissible; settlers spend their per-tick budget at that speed), `water` (wells, fish) and the minimap `rgb`. Sim code reads only the table: `map.isPassableTerrain`, `isBuildable(x, y, ground)` (a `Terrain` argument stands for the kind it accepts), `isPlantable`. **To add a terrain:** a `Terrain` code, a `TERRAIN` entry, a generation rule, and a ground sprite (`GROUND_COLORS`, `paintGround`, a place in `GROUND_PRIORITY` for transitions, `TERRAIN_KIND` in the renderer); `elevate` needs a height case.
- **Map generation** (`generateMap`): height/forest/ore noise from the main RNG, then features that use their own RNG streams so they never shift the rest of the generation: `addRidges` (mountain chains, strength grows with map size from nothing on 64×64) and `carveRivers` (`RIVERS_PER_64`, steepest descent with meander from high ground into water or a small lake, sandy banks, a `Terrain.Ford` — walkable shallow water — every `FORD_EVERY` tiles on a straight stretch, so rivers never cut land apart; they keep `RIVER_START_CLEARANCE` from every start), then `addBiomes` (its own RNG stream too: a moisture noise and a BFS distance to water turn dry grass far from water into `Terrain.Desert` and wet low ground near water into `Terrain.Swamp`, `BIOMES` thresholds, nothing within `startClearance` of a start). Start areas are prepared after that: `START_GUARANTEES` (data, the same for every start, offsets from the start position; the start area is still cleared for a 4×4 footprint) — a near coal/iron mountain inside the start tower's land, a far stone/gold/coal mountain just beyond it (lobes grow with the map via `guaranteeScale`, richer ore per tile, `oreAmount`), and quarries (the first from the main RNG as it always was, others from their own stream). Then `connectLand` keeps the land in one piece (swamp is impassable): two passes of `bridge` from the first start — across swamps by terrain (a dried 4-connected track to every sizeable stretch of land a swamp separates; pockets under `POCKET` tiles drown into the swamp), then across forests (a felled track to every sizeable clearing); boulders are left alone. No RNG, O(map); `tests/biomes.test.ts` checks that no land swamps alone separate stays cut off.
- **Digging:** every site except mines (`needsDigger`) is placed with `levelled = false`: a digger first clears it, `clearStrokes(b)` spade strokes (`CLEAR_STROKES_PER_TILE` per footprint tile) counted in `b.dug`, after flattening it if needed — sites whose footprint + door corners vary by more than `BUILD_MAX_SLOPE` (up to `BUILD_DIG_SLOPE`) get a `levelTo` height, flat ones `levelTo = −1` (`digging.ts`). Carriers deliver materials once a digger is on his way (see Logistics); builders and builder recruitment ignore uncleared sites. Players start with their start level's diggers; more come only as ordered (see Economy settings). As in Settlers 4 several diggers share a site: up to `diggersWanted` (one plus one per `DIG_STROKES_PER_DIGGER` strokes still to do, `strokesLeft`, at most `MAX_DIGGERS`) join its `diggerIds` and run the `dig` task, each moving one corner one pixel towards `levelTo` every `DIG_EVERY` ticks (`levelStep`), then sharing the clearing strokes. Builders likewise: up to `buildersOf(type)` (`SITE_BUILDERS`, Settlers 4's builder spots per building) in `builderIds`, every one adding a tick of `progress`. Both stand on `siteSpot` tiles along the front wall (door first, only tiles in the door's region). `abort` and `killSettler` release them with `leaveSite`.
- **Tile change tracking:** every runtime write to `map.tree`, `map.stone`, `map.crop` (stage changes included), `map.prospected`, `map.signAt`, `map.oreAmount` reaching 0, or `map.wear` crossing a path level must be followed by `map.touch(i)`, which bumps the tile's chunk version; the renderer re-scans only changed chunks.
- `findPath` reuses per-map scratch buffers (cost follows nodes explored, not map area) and counts work in `pathStats` for the bench.
- **Failure handling:** a `goto` with no route calls `routeFailed`: the job's target building gets `unreachableUntil` (logistics, builders and storage lookup skip it via `isReachable`), the job is aborted and the settler waits `PATH_FAIL_BACKOFF` ticks instead of retrying every tick. `abort()` puts goods in hand down on the ground where the settler stands (`carryBack` → `dropGoods`, as Settlers 4 drops a cancelled carrier's load); they are counted in `stats.lost` only if no tile within `GROUND.searchRadius` can take them. Builders without material for `BUILDER_STALL_TICKS` move to a site that has some.
- **Logistics:** `dispatch()` runs every `DISPATCH_EVERY` ticks, per player, and hands work only to that player's idle carriers on the same piece of land as the job (see Land pieces below), in this priority: worker requests, then demands (`demand()`: site materials from `cost`, workshop inputs from `recipe.inputs`; served one unit at a time in Settlers 4's order (`CEcoSector`): priority, then — for a good with several consumer types (`consumersOf`) — the type furthest behind its distribution weight (`distributionKey`, always on, `defaultWeight` unless set: Settlers 4's `DISTRIBUTION_DEFAULTS` — only bread 85 to the coal mine is sourced, the rest of a listed good shared equally — else equal `DEFAULT_WEIGHT`s), then finished buildings before sites, finished ones by `urgencyOf` (S4's `CalcUrgent`: 2 × `INPUT_CAP` − inbound − 2 × lying, over the distance to their nearest supply), sites least-stocked first; each from the nearest supply — a `Supply` is a building's pile at its door or a ground stack, picked up with `pickup` or `lift`, listed once per round (`supplyList`); a producer's pile (`isProductionPile`: a finished workplace, not a warehouse or market) counts at `PRODUCER_DISTANCE_FACTOR` 0.5 of its distance —; the carrier is the free one nearest the source), then producers' surplus and ground stacks carried to the nearest warehouse that accepts the good (a failed lookup is cached for the round, `storeFor`); demands and surplus go good by good in the player's **transport priority** (`Player.economy.transport`, default `TRANSPORT_PRIORITY` = Settlers 4's Roman list, `World.moveTransport(res, 'up'|'down'|'top'|'bottom')`, goods menu «Перевозка»; S4's one-transport-per-good-per-pass «coalbug» is deliberately not ported — Transport+). **Sites as in S4** (`SITE`): a site asks for a material only once a digger is on his way (`diggerIds`) or it is levelled, and only while `sitePile` (delivered, not yet built in — builders use materials in `RESOURCES` order) plus `inbound` stays under `SITE.pile` (8). **Priority** of a site is hard: while a prioritised site still needs a good (`siteNeeds`: cost − delivered − inbound), no other consumer on its piece of land gets any; `setPriority` allows at most `SITE.maxPriority` (10) prioritised sites per piece and the flag is cleared when the site is finished; a prioritised workshop (our extension) is only served first. **Carrier reserve** (`spareCarriers`: the player's carriers, busy or idle, minus those with a `become`/`retool` task, minus `Player.economy.minCarriers`, default and minimum `CARRIER_RESERVE` 5, `World.setCarrierReserve`): no carrier is turned into a worker, builder, digger, specialist (also `sendGeologist`'s on-the-spot geologist) or recruit (`recruitStep`) while none are spare; ready-made workers (`isReadyWorker`) are no carriers and take up their workplace regardless. Distances use straight lines; A* (`pathfinding.ts`, 8-way, no corner cutting, `adjacent` mode for blocked targets such as trees) runs lazily inside the `goto` task, and the route is recomputed when the next tile becomes blocked.
- **Buildings are data** (`BUILDINGS` in `config.ts`): `cost`, `worker`, `category` (build-menu tab), `storage` (warehouse), `recipe` (workshop inputs → outputs per `ticks`, run by `updateBuilding` while the worker is inside; with `outputChance` a finished cycle uses up its inputs but yields its outputs — or bred settler — only with that chance, world RNG: S4's pig farm 0.77, donkey ranch 0.25), `territory` (radius), `residence` (releases `capacity` carriers; the only source of population growth — only while the owner has fewer than `populationCap(players)` settlers of every kind, `POPULATION`: S4's 2500, or 10000 shared by 5+ players, counted by `populationOf` once per tick, and the house's door is on his land; else it retries after `POPULATION.retryTicks`). **Gatherers and planters** share code paths: a profession's `gather` def plus `GATHER_RULES` in `nature.ts` (which tile yields a resource and what taking it does), and a `plant` def plus `PLANT_RULES` (`tree` blocks and must pass connectivity, `grain` fields stay walkable). A new gathering/planting profession is a `PROFESSIONS` entry plus, for a new resource or planting kind, a rule. `GatherDef.missChance` (world RNG; S4's fisher 0.33) makes a finished attempt yield nothing and leave the tile as it was: the gatherer walks home empty-handed and the `store` task then puts nothing down.
- **Mining:** `Terrain.Mountain` is walkable and only accepts buildings with `terrain: 'mountain'` (`canPlace` passes the terrain to `isBuildable`); `Terrain.Rock` stays impassable. Ore lives in `map.ore` (kind code = `ORE_RESOURCES` index + 1, decode with `oreOf`) and `map.oreAmount`. A mine is a workshop whose recipe uses `inputsAnyOf` (any one food; each food has its own pile of up to `INPUT_CAP` in `demand()`) plus `def.mine` (`res`, `radius`, `favourite` food); `updateBuilding` hands it to `runMine` (Settlers 4 rules, `MINING`): eating a food stores `Building.attempts` — `favourite` buys 10, any other 2 —; every `recipe.ticks` one attempt picks a random tile within `mine.radius` (world RNG), ore or not — a tile without its ore (or worked out) is a miss, the attempt spent, as in S4 — and an ore tile yields a unit surely while it holds `sureAmount`+, else with `chancePerUnit` × units left; a worked-out mine goes on eating (the AI demolishes it). The geologist is an orderable specialist (see Specialists): `sendGeologist(x, y)` gives the nearest idle geologist the errand (`Settler.errand`), and his `prospect` behaviour (`geologistIdle`) turns it into one `goto`/`prospect` pair at a time, every unexamined walkable mountain tile on any land (`prospectable`), searched as S4 does (see Specialists) until none is left within `GEOLOGIST.reach` — the whole ridge —, then stays there; with no free geologist the free carrier nearest the hammer pile nearest the site fetches a hammer and `retool`s on the spot (the `retool` task carries the errand; the order grows by one, so he stays a geologist) — no hammer, no errand; a geologist turns back into a carrier (`toCarrier`, hammer put down on the ground) only when the player lowers the order below the geologists he has; unreachable tiles are skipped in `routeFailed` (`errand.skip`). What a player learns goes to the per-player bitmask `map.prospected` for good (the AI reads it); the visible sign is `map.signAt` (tick + 1) + `map.signBy` (saved layers, loaded only when present, so older saves still load): it comes down at `signEnds` (`GEOLOGIST_SIGN.lifetime` + a per-tile hash share of `spread`, after S2/S3 — S4 unverified), `prospectable` asks only for no live sign of the player's (`hasSign`), and `errand.since` keeps a geologist from signing a tile twice in one errand; `signLevel` turns the ore amount into 1–3 symbols (`GEOLOGIST_SIGN.levels`, S4's 1/2/3 signs).
- **Idle crowds** (`idle.ts`, `IDLE` in `config.ts`): free carriers, and builders/diggers without a site, call `restIdle` instead of walking into a warehouse. After `IDLE_GO_HOME_TICKS` each picks a gathering building (`idleAt`: nearest warehouse/house, `IDLE.gatherAt` — or a military building, `IDLE.fallbackAt`, while there is none, as at the start —, preferring one with fewer than `IDLE.groupSize` idle settlers) and stays outside near its door: every `IDLE.strollEvery` ticks it strolls to a free spot within `IDLE.radius` (walkable, owned, not a door, not water) or, with `IDLE.chatChance`, next to another idle settler of the group (`chatWith`, mutual; `chatPartner` validates it, so killed or busy partners need no clean-up; the renderer turns pairs to face each other). The stroll lives in `stroll` + `path`, never in `tasks`, so everything that treats `tasks.length === 0` as "idle" (dispatcher `take`, barracks, AI, geologist) is unchanged; `updateSettler` drops `stroll`, `path` and `chatWith` as soon as a task arrives. Settlers block no tiles, so crowds need no connectivity checks. Randomness comes from `World.idleRng` (saved), but where idle settlers stand changes which carrier the dispatcher picks, so the economy's outcome does shift (throughput measured, not identical).
- **Tools:** a profession's `tool` must be fetched before taking up the job: worker requests in `dispatchFor` add a `goto`/`pickup` of the tool from the nearest pile, and `become` (or `retool` for builders, diggers and specialists, recruited up to the player's orders) consumes it. A recipe with `outputChoice` (the toolsmith) makes whatever `chooseOutput` says is most awaited (`waitingFor`: staffing workplaces, ordered builders/diggers/specialists not there yet, garrison slots) or below `keepInStock`, and idles otherwise; with `orderable` the player's order queue goes first (`orderedOutput`, counted off by `toolMade`).
- **Player commands** live on `World` (`placeBuilding`, `sendGeologist`, `sendPioneer`, `sendThief`, `orderSpecialist`, `dismissSpecialist`, `setPriority`, `setStopped`, `demolish`, `attack`, plus the `availableAttackers` and `strengthOf` queries) and take a `player`. `priority` puts a building first in the fair demand ordering and in builders' and diggers' choice (hard for sites, see Logistics). `demolish` aborts every job referencing the building (goods in hands are put down), leaves its worker jobless in his profession (see Settlers), clears the tiles (with `markWalkable`), leaves the ruin's goods on the ground (`removeBuilding(b, 'demolish')`, see Goods on the ground) and lets the renderer drop the views on the next sync.
- **Stopping a building or site** (`stop.ts`, Settlers 4's `Switch`, `World.setStopped(id, on)`, `Building.stopped` saved; `canStop`: any site, a workplace, a warehouse, a market — not houses, whose S4 role ignores the flag, nor military buildings): `updateBuilding` starts no new cycle (one under way, `timer > 0`, is finished), the barracks is not updated and calls no recruit, gatherers/planters/hunters stay in (`idle`); `demand` is 0; `offered(b, res)` (= output + what a stopped building offers − `outReserved`: its input between cycles — a market's minus `trade.loading` —, a stopped site's `sitePile`) is the supply `nearestSupply`, the surplus loop and `available` use, and `takeOffered` (the `pickup` task) takes the output first, then the input or the site's `delivered`. Stopping aborts builders, diggers, donkeys coming to `load` and carriers with a `drop` there (their load goes down on the ground); a warehouse's carriers are redirected (`redirectDeliveries`) and a stopped warehouse is no destination (`nearestStorage`, `acceptedGoods`) but still a supply; `dispatchTrade` skips stopped markets at either end, and stopping a market turns donkeys bringing goods to it back to the market they loaded at (`turnBack`: the `unload` task's `from`; S4's `CancelIncomingDeliverTraders`), where they unload. Builders and diggers skip stopped sites. The renderer puts a pause badge (`stopped` atlas sprite) over local stopped buildings — over a site's current stage (`badgeTop`), like the `cutoff` marker; the info window has the switch.
- **Beds and strike** (`beds.ts`, `BEDS`, Settlers 4's `UpdateStrikeSettlers`): a player's beds are `Player.startBeds` (saved; `startBeds(carriers)` = 10 × ⌈start carriers / 10⌉ + 10) plus `bedsOf(def)` (= the residents it releases) of every finished house; only carriers need one, busy or free. Every `BEDS.checkEvery` ticks (`updateStrikes`, before the dispatch) carriers − beds − strikers > 0 puts that many free carriers on strike (`Settler.strike`, saved), < 0 calls the latest strikers back; strikers are skipped by `dispatchFor`'s idle list, `sendGeologist` and the AI; `houseBuilt` (from the `build` task) lets a new house count strikers as already released and settles the strike at once. `World.bedsOf(player)` for the UI. A test or tool that spawns extra carriers must give them beds (`startBeds`), as `sim:bench` and the showcase do.
- **Goods on the ground** (`ground.ts`, `GROUND`, Settlers 4's piles; there is no headquarters): map layers `goods` (`RESOURCES` index + 1), `goodsAmount` (≤ `GROUND.perStack` = 8) and `goodsReserved` (saved), plus the derived `World.stacks` (tile set, rebuilt on load; iterate `stackTiles`, index order, for determinism). A stack belongs to whoever owns the land it lies on (only that player's carriers take it), never blocks walking (so no connectivity checks; but A* charges `GROUND.pathCost` = 36/16 to enter its tile, Settlers 4's `SetPileId` move cost 7 against grass's 2 in `4 × bits + 8`, so routes step round a stack when that is cheaper) but makes the tile unbuildable and unplantable (`GameMap.isFree`; `canPlace` also refuses a door on one). `putGoods`/`dropGoods` lay goods on the nearest tiles that can hold them (walkable dry land, no door or field), topping up a stack of the same good, in a fixed spiral within `GROUND.searchRadius`; whatever finds no room is `stats.lost`. Every change `touch`es the tile; the renderer draws `stack:<res>:<n>` per tile (3D: the goods lying loose on a patch of trodden earth, `render_stacks` in goods.py, optional per resource — else the door pile `pile:<res>:<n>`; classic: wares on the `stack:shadow` blob) (`syncGoods`, an `addStatic` object, released in `unloadChunk`). Stacks are supplies for demands and tool fetching (`nearestSupply`, `toolPileNear`), count in `available` (`groundStock`) and the goods menu, and go to a warehouse only if one takes the good. They come from the start (`START_CONDITIONS[…].piles`, S4's Roman piles), ruins (`removeBuilding(b, ruin)` + `ruinGoods`: `demolish` gives back `GROUND.demolishShare` of the materials built in — a site's units used —, `burn` (conquest, defeat) `GROUND.burnShare`; with `keepsGoods` every good lying at the building — piles, stock, a site's unused materials — stays whole), a cancelled carrier's load and a dismissed specialist's tool (`carryBack`), and a donkey with no market left.
- **Surplus hauling:** producers' surplus goes to the nearest warehouse that accepts it and has room for it (see Warehouse capacity) unless the player already stores `RESOURCE_INFO[res].storeLimit` units (only water has one); then goods wait at the producer, its full pile pauses it, and carriers stay free. As in Settlers 4 (`CProductionPileRole::LogicUpdate`) a working producer keeps `SURPLUS_KEEP` (1) unit back for a consumer; a stopped one gives all.
- **Warehouse capacity** (`storage.ts`, Settlers 4): `BuildingDef.storage` is a `StorageDef` — `piles` piles of `perPile` (`STORE_PILE` = 8) units of one good each, a good may fill several (`pilesUsed`), and/or `units` in all; neither = unlimited. The warehouse holds 8 × 8 (S4's storage area); there is no other storage (S4 has no headquarters: the start goods lie on the ground). `storageRoom(b, res)` counts `output + inbound`, so a carrier is only sent where room is already reserved and carriers spread over warehouses; `nearestStorage(…, res)` skips warehouses without room (and refusing ones) unless `StoreRules` relax that. Goods in hand that lose their destination are put down on the ground (`carryBack`); `redirectDeliveries` turns carriers to another accepting warehouse. `storageFill` feeds the warehouse window («Заполнено», «Стопки», piles per good — `storageRows`/`stockText` in economyPanel.ts) and `syncYard` draws a 3D yard's real piles. The AI builds its first warehouse early (an `AI_PLAN` step: it takes the start goods off the ground), more only after `AI.storeAfter` (barracks), not while cramped, with fewer than `AI.storeFreePiles` free piles and up to `AI.maxStores` (or at once when it has none left), and ticks every good on each of its warehouses through `setAccepts`. Stock-panel groups and limits live in `RESOURCE_INFO` (names in the dictionaries, `res.<id>`); the HUD draws resource icons with the ware painters (`wareIcon`), so a new resource needs no UI changes.
- Nature rates are expressed per 64×64 of map and scaled by area (`scaled()` in `nature.ts`), so a bigger map is not a slower world. As in Settlers 4 trees do not spread by themselves (`TREE_SPREAD` 0: only foresters plant; trees still grow) and fish never restock (`FISH_RESTOCK` 0, `FISH_MAX` per open-water tile at generation), so the AI treats fish as `AI.exhaustible`. Fields (grain; the mechanism is per kind, ready for other races' crops) are `map.crop` (stage 1 sown … `CROP_RIPE`, then `CROP_STUBBLE`) + `map.cropKind` (`CROP_KINDS` index). **Growth is Settlers 4's deterministic timers** (`GROWTH` per `PlantKind`: `stageTicks`, `stubbleTicks`; `CPlant`/`CTree::LogicUpdate`): grain 3 × 660 ticks, stubble 660 (walkable, not plantable), trees 3 × 880, no RNG; grain is sown only where `rawness` (S4's `CalcRawness`: the tile's steepest corner difference in S4 height units over two S4 tiles, one unit = `S4_HEIGHT_PX` ≈ 0.78 of our height px) is at most `GrowthDef.maxSlope` (7, `SearchGrainSeedPos`; `PlantRule.fits`, checked on candidates and when sowing); ripe fields never rot. The ticks spent in the current stage are the saved layer `map.growth` (Uint16, steps of `GROW_EVERY`); `World.growing` (derived, `rebuildGrowing` at generation and on load) lists saplings, unripe fields and stubble, and only those are visited every `GROW_EVERY` ticks (`grow`), so cost follows plantings, not map area; anything that plants must add the tile (the plant rules do). Harvest rules (`GATHER_RULES`) decide what happens to the tile: grain becomes stubble (`reap`; a kind without `stubbleTicks` is cleared at once). The farmer (`farm` behaviour) reaps while his pile is below `OUTPUT_CAP`, else sows, with no cap on his fields (`CFarmBuildingRole`).
- **Players:** `new World(seed, { players })` gives every player, at its `startPositions` entry (map center for one player — identical to the single-player map — otherwise on a circle), what Settlers 4's start script does (`addPlayer`, `START_CONDITIONS`): no headquarters, one finished small tower (`building`) centred on the start, held by one swordsman (its first call for a fighter; the other start fighters stand free in front of it, `formationSpots`, and new towers call them in), the start people (the Roman ones of S4's script: carriers, builders, diggers, fighters, `geologists` waiting for orders — their order is the start's —, `donkeys` standing by, and ready-made `workers`: smiths, miners, a hunter), and the start goods lying round it pile by pile (`piles`, `dropGoods`); a computer player's Settlers 4 start help lies there too (`AI_LEVELS[…].bonus` goods, `people`). `Player.home` (saved) is that tower's door: `homeOf(p)` for the camera, `placeBuilding`'s path check, the AI's sense of home and the home piece of land; it stays put when the tower is lost. `generateMap` prepares the guaranteed start area (meadow, grove, quarry, coal/iron mountain, pond) around every start. Each player has its own settlers, dispatch round and territory.
- **Military** (`military.ts`): fighters are the professions with a `combat` def (`FIGHTERS`, `isFighter`; `soldier` = swordsman, `archer` with `combat.ranged`), each carrying a `level` (index into the profession's `combat.levels` — Settlers 4's hp and damage per level, read through `fighterLevel`/`hpOf`/`maxHp`, clamped to the last, so the one-level squad leader is always level 1 — and into `SOLDIER_LEVELS` for the `cost` in `LEVEL_RES` (gold) paid at recruitment; a recruit pays only for a level his profession has; levels never change afterwards — no promotion). Buildings with `def.garrison` hold them (`Building.garrison` ids; `garrisonInbound`/`garrisonArchersInbound` reservations released by `releaseJoin` from `abort` on `join`). The `GarrisonDef` is the whole defence rule set: `capacity`, `keep` (never given away to attack or to chase intruders; default `GARRISON_KEEP`; `spareSoldiers` respects it), `archers` (slots for ranged fighters; the other `capacity − archers` are for melee ones — slots have a kind, as in Settlers 4: `slotsFree(w, b, archer)` counts members and inbound of that kind, and `orderWarriors`, `joinTick` and `orderGarrison` respect it), `door` (Settlers 4's door: `hp` 50, one back every `regenEvery` while it stands; `Building.doorHp`, saved, absent = whole). **Garrisons are Settlers 4's** (`CMilitaryBuildingRole`, docs/S4-AUDIT.md item 1): `Building.wish` (saved; `{ melee, ranged }`, read through `wishOf`/`garrisonCounts`) is how many it calls in. Every `GARRISON_ORDERS.every` ticks a finished military building runs `throwOut` (one fighter beyond the wish — swordsmen first — steps out of the door, `stepOut`/`standNear`, only while no enemy fighter is within `GARRISON_ORDERS.enemyNear` of the door) and `orderWarriors` (while fewer of a kind are inside and coming than wished — or, empty with no wish, one at all: a swordsman if `findFreeFighter` finds one, else an archer, and the wish becomes that one — it calls the callable fighter of that kind with the highest level, then the nearest, within the rings `GARRISON_ORDERS.rings` round its door, one ring after the other, in its door's region — whatever he was doing is aborted, his post dropped (`sendToJoin`); an empty building with nobody coming warns its owner, `MESSAGES.noFighter`). **Callable** (`isCallable`) is S4's `OrderWarrior` rule: any outdoor fighter of the kind still `Selectable` — S4 clears that flag only when a soldier is attached to a building or vehicle (`CSoldierRole::ComeToWork`), not on move or attack orders —, so field units and attackers too, not one with a garrison or walking into one, nor one in a duel (our duels link both sides; [оценка]); `freeFighters` caches them per tick; the squad leader (`combat.fieldOnly`, `canGarrison` false) is never called. A fighter sent out by an order (`attack`, an intruder chase) leaves through `sendOut`, which lowers the wish of his kind (S4 `ThrowOutId`), so the building does not call him straight back; `isFreeFighter` (no post, idle) is only the army menu's «Свободны». Player commands: `World.fillGarrison` (wish = every slot), `changeGarrison(id, archer, ±1)` (−: S4's event 19 rule, never below one fighter in all — the last of a kind only while the other kind is wished and inside; +: up to the slots), `withdrawGarrison` (fighters on their way in turn back, the wish drops to one — a swordsman if one is inside); a fighter sent in by hand (`orderGarrison`) raises the wish to cover him (`raiseWish`), and `enterGarrison` keeps the wish at least at who is inside. Fighters never move between buildings by themselves. Free fighters stand where they are (`soldierIdle` → `freeIdle`: every `FIELD.scanEvery` ticks they take on an enemy fighter within `FIELD.engageRadius` — archers shoot within their range —, else an intruding specialist nobody chases yet). **Messages** (`messages.ts`, `MESSAGES`, S4's `AddWarningMsg`): `postMessage(w, kind, player, at, {b, res})` appends `{kind, player, x, y, tick, b?, res?}` to `World.messages` (ring of `MESSAGE_KEEP`, not saved, read by nothing in the sim; `World.warnings` is the same list), the same message (kind, player, building or good — any building with `perPlayer`) at most every `MESSAGES[kind].every`; written for an assault on a military building (`assaultTick`), a conquest (`lost`/`captured`), no free fighter or carrier, a missing tool (`dispatchFor`), a mine fruitless more than `MINING.emptyAfter` times running (`Building.misses`), ore found (`prospectTick`), a strike (`beds.ts`), a lookout's alarm. As in S4 there is no defence bonus for the building itself (the door guard's extra damage is 0 in S4): defenders are stronger only by their defence strength at home (`fieldFactor`) and by the tower archers' bonus. Fighters with `combat.captures` that can hold a garrison (swordsmen and archers, S4's warrior types 2 and 3) conquer an emptied building alone (`conquer`: the wish becomes him); the rest of the party stays outside, free; the squad leader's `assault` ends there. **New fighters come only from a barracks, by order** (`def.barracks: { ticks }`, no worker; Settlers 4's `CBarrackRole`, docs/S4-AUDIT.md item 4): the player's `EconomyState.recruitOrders[kind][level]` (saved; `World.orderRecruits` — a count, `ENDLESS`, 0 to clear; `reduceRecruits`; as in S4 an endless order counts as 100; none by default, so a barracks recruits nobody unasked). `demand` brings it weapons (`weaponsWanted`, every fighter's tool up to `INPUT_CAP`) and gold while an order takes some (`goldWanted`). Every `BARRACKS_EVERY` ticks, unless it is stopped (`stop.ts`), `updateBarracks` → `recruitStep` takes, of the orders whose goods lie on its pile (`recruitNeeds`: the tool, the profession's `kit`, `SOLDIER_LEVELS[level].cost` in `LEVEL_RES`), the one of the highest rank (`combat.rank`, default level + 1; the squad leader 4), kinds of one rank taking turns after the last one (`combat.alternate`, `Building.recruitClass`, S4's `m_uU0`); it calls the nearest idle carrier not on strike (`beds.ts`) on its piece of land while the player has carriers above his reserve (`spareCarriers`, `economy.minCarriers`, S4's `CarrierForJobOrderAvailable`; else a `noCarrier` warning), takes the goods off its pile at once and counts the order down (`recruitCalled`; endless stays). The carrier becomes kind `recruit` and walks to the door; the `recruit` task (it carries `paid`; `abort` → `releaseRecruit` puts the goods back on the pile, or on the ground if the barracks is gone, and turns him back into a carrier) keeps him inside `barracks.ticks` and lets him out as that fighter at that level, standing free by the barracks (`standNear`), counted in `stats.trained`. His walk is the training (S4 has no training time). Weapons come from the weaponsmith's `outputChoice`; `waitingFor` counts what recruit orders still wait for beyond the barracks' piles (`recruitsAwaiting`; an endless order a pile's worth). **Weapon shares:** `OUTPUT_SHARES` (data: default weights, e.g. sword 60 / bow 40) marks share-controlled outputs; `World.setShare(res, weight, player)` / `shareOf` hold each player's weights (`Player.shares`, saved). `chooseOutput` first checks that something is awaited at all, then, when every choice is share-controlled, makes — of what orders wait for beyond the stock, else of the reserve (`keepInStock`) — the one furthest below its share (`mostBehindShare`: holdings = units available plus fighters carrying it). `attack()` sends free fighters and idle field units within `ATTACK_RANGE` of the target (nearest first), then the spares of military buildings in range (alternating melee and ranged); at a held building with a door the attackers first break it (every attacker, archers too, strikes it at his cadence with `hitDamage(w, s, null)`; no defender is called out meanwhile), then the attacker's `assault` task calls out one defender at a time (swordsmen first; `opponent` links both; defenders stand and fight in `updateSettler`). **Blows** (`combat.ts`, Settlers 4's rules, sources in `docs/TIMINGS.md`): every attack lands — no hit chance — for `hitDamage` = the level's `damage` × `fieldFactor` (rounded, ≥ 1), plus the squad leader's share (`moraleOf` − 1, its fraction rounded up with that probability via the world RNG), minus the target's `combat.armor` (≥ 1). In a duel both fighters strike independently every `combat.every` ticks (`s4Ticks` of S4's cadence, fractional; `Settler.reload` counts down and `rearm` carries the remainder): one side's task drives it (`duelTick` from `assault`, `engage`, `chase`), `startDuel` gives each a random phase, and when both are due on one tick a coin (world RNG) picks who strikes first — a fighter killed by that blow does not strike back; an archer in a duel shoots point-blank at his own damage and cadence. Ranged damage (`shoot`, same rules) is applied instantly: attacking archers shoot defenders busy duelling within `ranged.range`, garrison archers shoot, from up to `ranged.towerRange` (S4's 20 tiles), any hostile fighter outdoors standing on land of their side or nobody's (`towerTargets`; looked for every tick while the building is assaulted — `assaultsByTarget`, built once per tick —, else every `FIELD.scanEvery` ticks) with `ranged.tower` extra damage, `ranged.towerDoor` at an enemy at the door; an intruding specialist shot down counts in `stats.intrudersKilled`; `World.shots` is a visual-only list (not saved, pruned after `SHOT_TICKS`). **Infirmary** (`infirmary.ts`, `def.infirmary: { radius, heal, every, scanEvery }`, Settlers 4's healer's hut): worker `healer`; while he is inside, every `scanEvery` ticks `updateInfirmary` (from `World.step`) calls the most wounded fighter of its owner or an ally standing idle outdoors (free, or a field unit at his post: `mayBeCalled`) within `radius` of its work centre (`workArea.ts`, movable) to its door — one patient at a time (`Building.patient`, saved) —, where the `heal` task gives him `heal` hp every `every` ticks while the healer is in, until whole (`releaseHeal` from `abort`); nobody is called out of a building, patients are not callable by towers (`isCallable`). Nobody heals elsewhere. **Lookout tower** (`lookout.ts`): worker `watchman`; `def.vision` (sight radius, with or without him, no garrison or land); with him inside, every `alarm.every` ticks a hostile outdoor fighter within `alarm.radius` raises `MESSAGES.alarm` once until none is left (`Building.alarm`). **Teams:** `WorldOptions.teams` (per player index) → `Player.team`; `World.allied(a, b)` gates `attackable`, `distancesToEnemy`, foreign land at conquest, `outcome` (allies win together) and the AI (`knownEnemies`, foreign land in sight); `?teams=1,1,2,2`, `sim:ai --teams=`. An empty enemy building is conquered: owner flips, and its disc is settled again (`claimChanged`, see Territory): it takes only the land its former owner covers no more, and his buildings on land that changed hands burn (`World.removeBuilding`).
- **Direct army control** (`field.ts`, `FIELD` in `config.ts`, as in Settlers 3/4): a fighter with `Settler.post` (`FieldPost`: a tile, optionally `leader` + offset `dx`/`dy`) is a **field unit** — `soldierIdle` hands him to `fieldIdle` (a free fighter, with no post, gets `freeIdle`); a military building wishing more than it holds may call any of them in (`isCallable`, as S4), and `enterGarrison` clears the post. Player commands on `World` (the AI may use them too, with its own id): `releaseFighters(b, n)` (spares above `keepOf`, swordsmen first, to spots below the door; the building's wish drops to who is left), `orderMove(ids, x, y)` (a formation from `formationSpots`: a walkable, door-free spiral; the leader in the centre, then swordsmen, then archers; with a leader in the order, the others' posts follow him by offset — `postOf`), `orderHold`, `orderAttack(ids, building)` (post at the target's door, then `goto` + `assault` as in `attack`), `orderGarrison(ids, building | null)` (into that building if it has a slot of their kind, raising its wish; with null each into the nearest with one — with none, or for the squad leader, the unit drops its post and stands free). Every `FIELD.scanEvery` ticks an idle field unit looks for the nearest hostile outdoor fighter within `engageRadius` of himself and `chaseLimit` of his post (`outdoorFighters`, cached per tick); archers `shoot` it from range, melee fighters run the `engage` task (closes in with an inserted `goto` until side by side, diagonals included, links `opponent`; when both engage each other only the lower id's task drives the duel, an assailant called out stands like a defender) and duel by the same `duelTick`. Garrison archers also shoot field units near their building (`fieldUnitsNear`). **Squad leader** (`leader`, `combat.leads: { radius, morale }`): `moraleOf` multiplies the damage (`hitDamage`) of own fighters within `radius` of a living leader (`leaders`, cached per tick; not the leader himself; S4 gives the bonus to his control group — the radius is our stand-in); the barracks makes him by order from his `tool` (armour, the weaponsmith's third `OUTPUT_SHARES` output) plus `kit` (extra goods a recruit needs: a sword and 3 gold, `recruitNeeds`), first of all orders it can pay (rank 4); he neither captures nor goes into a garrison (`fieldOnly`). Field state is plain data on the settler (saved). **Control groups and donkeys (UI):** `GameState.groups[1..9]` (not saved) — Ctrl/⌘+digit stores the selection, a digit recalls it (dead/lost ids drop out; a second press within `DOUBLE_TAP_MS` centres the camera); a digit picks a build-menu building only when no group is stored under it. Group numbers are drawn as pooled `Text` badges over selected units (`markUnits`). Selected fighters (units or the single `selectedSettler`) and wounded fighters in a fight (`inFight`, collected in `syncSettlers`) get `healthBar` over their heads: hp / `maxHp` between corner brackets, green → yellow → red, level pips above, placed at `rankY`. Pack donkeys (drawn by `AnimalLayer`) are pickable through `AnimalLayer.unitAt`/`unitsInRect`, which `settlerAt`/`settlersInRect` merge by depth; a donkey opens the settler window (route `load` → `unload`, load) or, several in a box with no fighters/specialists, the selection window; they take no orders (`LOOK_ONLY` in input.ts).
- **Computer players** (`ai.ts`, `World.ai`, enabled per player with `new World(seed, { ai: [ids] })`): the hard rules are (1) act only through the public player commands with the AI's own player id — never mutate world state directly or call internal helpers that do; (2) see only what that player could see — ore counts only where its own geologists prospected; enemy buildings exist for it only once their door tile is explored (`knownEnemies`), their garrison is counted only while in its buildings' sight (`inBuildingSight`), else guessed as `AI.unseenGarrison` × capacity; resources beyond its border count only on explored tiles. It reads only fog state that survives a load (explored bits, building sight — never `isVisible`, whose settler part is not saved); `World.step` calls `ensureVision` first so a loaded game rebuilds sight before the AI thinks. While it knows no enemy building it scouts: towers lean towards foreign land in sight, else (`Context.scoutingStarts`) towards the other start positions it has not explored — `startPositions` follows from the map size and player count, public like the map size — in a line (score `fromCastle·0.3 − distance`), and frontier outposts stop at `AI.maxScoutOutposts` until an enemy is known. **Room for the military:** workshops and houses keep off a band of own tiles within `AI.borderReserve` (3: a 2×2 tower and its door are three rows deep) steps of the border (`Context.band`; a preference — a workshop with no other spot may take it, houses and eyecatchers may not); a plan building that finds no spot sets `crampedUntil` (`AI.crampedTicks`): while cramped it pushes the border with any fighter it can spare (no `frontierSoldiers` wait), builds no eyecatchers, and for buildings in `AI.makeRoomFor` (barracks, smelters, smiths) `makeRoom` demolishes an eyecatcher or a second finished workshop of a type whose ground, with the free own ground beside it, takes the wanted footprint (`roomFor`: a 3×3 barracks over a 2×2 workshop), and places the wanted building in the same think (one per `RETRY_TICKS`, the victim's type held back for a while). Military buildings may take a slope a digger must level (up to `BUILD_DIG_SLOPE`, scored `AI.slopePenalty` lower); everything else keeps to level ground. Siege and frontier placements try the military types largest first until one fits (`placeMilitary`: a 4×4 fortress often finds no room where a tower does). **Specialists** (`useSpecialists`, every `AI.specialistEvery` ticks): with `AI.pioneerShovels` shovels it orders a pioneer and sends him to the claimable spot around its military buildings with the most explored unclaimed resources (leaning to unexplored starts; `pioneerSpots` best first, up to `AI.pioneerTries` — `sendPioneer` refuses a spot whose claimable tiles he cannot walk to); with `AI.thiefIdle` idle carriers it orders a thief and sends him at a known, robbable enemy store within `AI.thiefRange`. **Settlers 4's attack trigger** (`AI.s4Attack`, `attackTriggered`, `AiState.trigger`): a new offensive needs at least `minFighters` fighters and a roll every `every` ticks that comes up with `start` per cent, `step` more per miss up to `max` — the roll a hash of tick, player and attacks so far (no RNG of its own); after a capture it presses on without one. **Counterattack** (`counterAttack`, before its own attacks; `AiState.held`/`counter`): a military building of its own in an enemy's hands is attacked at once with up to `AI.counterAttackers`, again every `AI.counterEvery` for `AI.counterTicks`, peace time and cooldown aside. Its infirmary goes next to its rally point (`Context.rally`). Its attack estimate sums its party's `duelWorth` (hp × damage per tick at its attack strength, in level-1-swordsman units — what one-on-one duels trade) against one unit per defender (their make-up and strength it cannot see), and it attacks at most every `AI.attackCooldown` ticks — `AI.followUpCooldown` after an attack that took its target (`AiState.lastTarget`). **Assault tactics:** the target is the best-scored known enemy military building it outnumbers — that enemy's heart first (`knownCastles`: of its known military buildings the one nearest the start position nearest its known buildings — the start tower while it stands), then by depth towards that heart (`AI.depthWeight` per tile to its `siegeGoals` point), minus `AI.reinforceWeight` per other known building of that enemy within `ATTACK_RANGE`; the party is `partySize` (what the target takes × `AI.overkill`, at least `AI.minAttackers`; everything when decisive — the enemy's last known military building), so the rest stay in their garrisons and defend. **Siege** (`siege`, before the plan each think): `siegeGoals` gives each enemy it knows a goal — its heart once one of its military buildings is explored, else its presumed home: the start position nearest the enemy's known buildings (start positions are public) — and while it knows no enemy building at all the siege aims at the nearest unexplored start (`unexploredStarts`), since its scouting towers may stop at their cap before ever seeing foreign land; and while fewer than `AI.siegeBuildings` of its military buildings stand within `ATTACK_RANGE` of a seen heart (always, for an unseen one) it places, ignoring enemies in reach and up to `AI.maxMilitary + AI.siegeExtra`, first (unseen goal) a lookout within `land + 3` of the goal and only where the presumed home lies `AI.siegeLookoutSight` inside its sight (`land` = how close its land already comes; only if none of its lookouts already stands within `land + AI.siegeLookoutSlack` — one per edge; siege scoring comes before the plain lookout score in `Context.score`, so a siege lookout never lands elsewhere), then the largest military building it can pay for and man within `ATTACK_RANGE − AI.siegeMargin` of a seen heart, or anywhere its land would reach `AI.siegeStep` closer (`Context.siege`, scored in `score`). **Scouting on foot** (`scoutIfStuck`, `sendScout`/`updateScout` in aiField.ts): once that siege towards a goal it has not seen has found no spot for `AI.scoutAfter` ticks (`AiState.siegeStuck`, set on a failed siege placement, cleared on a successful one — forest, water or swamp in the way), one spare fighter is released and `orderMove`d to the presumed home (`AiState.scout`, at most every `AI.scoutEvery`, back with `orderGarrison(null)` after `AI.scoutTimeout` or once an enemy heart is known); what he sees lands in the ordinary saved explored bits. Attacks still need the target's door explored (fog rule). A mine it cannot place sets `wantOre` (towers weigh mountains more, a geologist goes to the nearest unprospected own mountain); gatherers of `AI.exhaustible` resources (stone) with nothing left in range are demolished so the plan rebuilds them elsewhere; no new outposts while a known enemy military building is within `ATTACK_RANGE` (soldiers are kept for the attack); it sets its weapon shares (`AI.weaponShares`) and its recruit orders (endless, `AI.recruitKinds` at levels 1 to `AI_LEVELS[level].recruitLevels` — S4's AI: level 1, on «normal» and «hard» 2 and 3 as well) once through `setShare`/`orderRecruits`, attacks only with a capturing fighter in the party (enemy fighters it sees standing outdoors within `AI.guardRadius` of the target count as defenders), scouts with lookout towers (`LOOKOUTS`, up to `AI.maxLookouts`: while it knows no enemy building but sees foreign land — `Context.scoutingBorder` — it places them as close to that land as possible and only within their sight of it, while its towers then go in a line towards that land as towards unexplored starts, since its towers stop at the other's border too far to see the enemy home), and keeps `AI.reserve` of a material nothing of its own produces any more (stone with worked-out deposits: only producers of it may spend the reserve, border-pushing military buildings down to `AI.reserveFloor` — a floor every non-producer keeps even while it still produces the material, so losing its last quarry at 0 stone never leaves it unable to pay for a new one —, towers weigh deposits ×4 and the frontier takes the cheapest in it); (3) be deterministic and keep all state in the plain-data, saved `AiState` (no RNG of its own, ties broken by tile index); (4) bounded cost — think every `AI.thinkEvery` ticks, score only own territory tiles with cheap checks (`fits`) and spend `canPlace` on the best `AI.placeTries` spots, back off `RETRY_TICKS` after a failed search (`blockedUntil`). **Garrisons and rally** (`muster` in `aiField.ts`, every think, Settlers 4's garrison rules): military buildings within `AI.fillRange` of a known enemy military building or at its border (`frontline`: land not its own at one of `AI.borderSamples` points just beyond their reach) are filled (`fillGarrison`); every military building that wishes more than it has inside and coming — an empty one at least one — is sent the nearest idle fighter of the kind it lacks (`orderGarrison`, from anywhere: S4's own calls reach only 27 tiles), and a wish it cannot fill is lowered with `changeGarrison` (otherwise its own towers would call back attackers marching past — a tower calls any outdoor fighter without a home, `isCallable`, as in S4); the other idle fighters (`idleFighters`: outdoors, free or idle at a post, in none of its squads) gather with `orderMove` at its rally point (`rallyPoint`: `AI.rallyBack` tiles behind the door of its manned military building nearest an enemy goal, `AiState.rally`, regrouped when it moves `AI.rallySlack` tiles), where `World.attack` finds them. Squads (`takeFighters`) take idle fighters first, then garrison spares; done, they are simply let go and `muster` brings them back to the rally. **Field orders** (`aiField.ts`): with `AI.stageStrike` (off by default: it cost decisive games on 128×128 4-player maps) an attack's party (`attackerComposition`) leaves its garrisons through `releaseFighters` (ids found by diffing the garrison lists) and joins its members already outdoors (a free squad leader of its own nearby comes along), gathers with `orderMove` on the line from the target's door back towards its buildings — on the first own tile at least `AI.stageDistance` from the door, else at that distance (out on enemy land the defender would meet it at home strength) — (`AiState.strike`) and, once `AI.stageArrived` of it stands at its posts or after `AI.stageTimeout`, goes in with `orderAttack`; a party starting closer than `stageDistance + stageMinWalk` (or with no room to form) attacks straight from its buildings (`World.attack`, the fallback). `defend` (with `AI.fieldDefense`) meets hostile field units (`post` set) on its land (or within `AI.defendMargin` of it) and in its buildings' sight with `⌈n × AI.defendRatio⌉` idle fighters and spares within `AI.defendRange` — only if those at least match them, else it stays behind its walls (`AiState.defense`) — and lets them go back to the rally when none are left; `hunt` (`AI.huntRatio`, `AI.huntMin`) goes after an enemy's last fighters: outdoor fighters in its buildings' sight of a player it knows no military building of (explored doors) and whose presumed home — the start position nearest them that is not its own or an ally's — it has explored (S4's fighters stand free round their towers; field units near its land are `defend`'s) get a field squad, `orderMove`d to the nearest (`AiState.hunt`), let go when none are left in sight — so games end under `DEFEAT.fighters`. **Economy first** (`AI.economyFirst`): while a step of `AI_PLAN` waits only for materials (none short for good) and it is not cramped, later plan steps with a garrison and frontier outposts wait — a big start army (S4's 14 fighters) would otherwise turn every plank into a tower. **Markets** (`tradeCheck`, `placeTrade`, every `AI.tradeEvery` ticks): `Context.fits` places buildings only on pieces of land with a finished warehouse or a served market (the destination of one of its routes); a cut-off site still empty at two checks is demolished; the first cut-off piece with a workplace (or a site with materials) becomes `AiState.trade.anchor` and gets a home market, a donkey ranch (`breeds`) and a market on that piece (`Context.onPiece`); then `orderTrade` sends what the piece's sites and workplaces lack (`TRADE_INPUTS` per input, minus orders, donkey loads on the way and the far market's pile), and the far market sends home, `ENDLESS`, what the piece makes and does not use. Behaviour is data: `AI_PLAN` (ordered build targets with `after` prerequisites) and the `AI` tuning table (houses by idle + still-to-come carriers (strikers do not count; any striker calls for a house), `staffable` counting jobless workers of the profession before tools, tool reserve `keepTools` so the first building of a type keeps the last tool — this prevents the coal-mine/pickaxe deadlock, manning discipline `homeGuard` (counting spares in every military building, its idle fighters outdoors and weapons in stock), frontier outposts towards the nearest enemy once it has `frontierSoldiers` — the largest garrison type it can afford and man —, attack after `peaceTicks` when the worth of the party `attackerComposition` would send beats `attackRatio` × defenders + 1).
- **War statistics** (`World.stats.war[player]`, saved: `killed`/`fallen` by kind — `strike` counts the hitter's kill, `killSettler` every death —, `captured`/`lostBuildings` in `conquer`). A last defender struck down by an attacker who can capture (his `assault` at the head) is replaced by him at once inside `killSettler` (S4's `InsertTowerGuard`), so the emptied building never loses its land and burns first; `assaultTick` never conquers a removed building.
- **Victory/defeat** (`DEFEAT`): every `DEFEAT.checkEvery` ticks after `DEFEAT.afterTick`, `World.checkDefeats` puts out every player with no occupied military building (Settlers 4's `DefaultPlayerLostCheck`) and — `DEFEAT.fighters`, the project owner's rule, not confirmed by any S4 source — no living fighter either (anywhere: field, homeless, infirmary; a recruit in training does not count; `World.holdsOn`) (`defeatPlayer`): it goes to `World.defeated` (saved), its buildings burn (`removeBuilding(b, 'burn')`, their goods stay on the ground), its land goes back to nobody (`clearLand`, then `recomputeTerritory` lets others' towers take what they cover), its settlers drop their jobs and flee (see Stranded settlers) until they die; its AI stops thinking. The AI hunts an enemy's last fighters (`hunt`, Computer players). The demolish button warns before the last occupied tower goes (its fighters come out homeless). `World.outcome(player)` is `'won'` once every other (non-allied) player is defeated. The HUD shows the end screen once `outcome(LOCAL_PLAYER)` leaves `'playing'`.
- **Stranded settlers** (`flee.ts`, `FLEE`, Settlers 4's `CFleeRole`): called first in `idle()`; a free settler whose behaviour is in `FLEE.behaviors` (carrier, builder, digger — fighters are exempt) or a ready-made worker without a workplace (`isReadyWorker`) standing outdoors on land not his owner's or an ally's — or any settler of a defeated player — walks a leg towards the nearest own tile within `FLEE.seek` he can reach (`sameRegion`), else to a random reachable spot within `FLEE.wander`, after a `FLEE.pause` wait (`World.idleRng`); back on own land `Settler.fled` (saved leg count) is cleared, after `FLEE.legs` legs he dies through `killSettler`.
- **Fog of war** (`fog.ts`, per player): `map.explored` is the saved bitmask of what each player has ever seen; current sight is derived (`World.fog`, never saved): `vision` (bit per player) — as Settlers 4's `CFogging`: every own tile plus a `FOG.landBand` band round each border tile, a manned military building's `BuildingDef.sight`, a lookout's `vision` (`seeing`) — rebuilt only when `World.buildingsVersion` (bumped in `addBuilding`/`removeBuilding`), `territoryVersion` or the signature of buildings seeing now (`sighted`) changed, plus per-player `seenUntil` ticks that outdoor settlers stamp around themselves every `FOG.settlerEvery` ticks, `FOG.settlerRadius` (7) tiles or their profession's `sight` (the thief's 10). Cost: O(settlers × disc) every few ticks plus O(map) per change of buildings or land. Query with `World.isExplored` / `isVisible`; `inBuildingSight` is the building part alone (what the AI may use). **Allies share sight:** all three test the player's `sightMask` — its own bit and its allies' (derived from the saved teams, cached per `players` array and reset by `resetSightMasks` after teams are set) — so a player sees what its team's buildings and settlers see and knows what its team explored; the renderer, minimap and AI need nothing else, and nothing new is saved.
- **Removing settlers:** only through `killSettler`: it aborts the settler's jobs, frees its opponent, and clears every reference (`garrison`, `workerId`, `builderIds`/`diggerIds`). The settler stays in `World.settlers` (skipped by `step`) until `removeDead` at the end of the tick, so loops never splice under iteration. A new field that references settlers must be cleared there too.
- **Territory** (`territory.ts`, `TERRITORY`, Settlers 4's `CWorldManager::SetOwner`): `map.owner` holds the owning player per tile and is real, saved state — land stays its owner's when the building that claimed it goes. A building that `claimsTerritory` (worker-less ones once done, workplaces once staffed, military buildings while garrisoned or always with `claimsWhenEmpty`) gives each tile of its disc an influence of `TERRITORY.influence − perTile × distance` (S4: 50 − distance in its tiles; ours are `S4_TILES_PER_TILE` of them), summed per player up to `cap`; `settleTerritory(cx, cy, r)` gives a tile to the greatest influence (ties: the lower player id) only when it is nobody's or its owner has no influence on it left, keeps every claiming building's own footprint and door its owner's, burns buildings on tiles that changed hands, and bumps `territoryVersion` (polled by the renderer, `land.ts` and fog) only on a change. Whenever a building starts or stops claiming, changes owner or is removed, `claimChanged(w, b)` settles only its disc (O(disc × claiming buildings near it), per event, never per tick); `recomputeTerritory` settles every claiming building's disc (a new world, the dev showcase, tests). So a new tower does not take foreign land a foreign tower still covers, a conquered one takes only what its former owner covers no more, and pioneers' land (no influence) goes to whoever's tower covers it. `canPlace` requires the footprint and door to be owned; `isGatherTarget` and `canPlant` only accept owned tiles, so gatherers and foresters never work outside the border.
- `addBuilding` moves any outdoor settler standing on the new footprint to the door tile, so nobody is walled in by a site placed on top of them.
- Building costs are multi-resource (`cost: Partial<Stock>`); always read them through `costOf()` / `totalCost()`. Construction takes one work shift (`BUILD_TICKS_PER_UNIT`, one builder's work) per delivered unit of any material; several builders shorten it.
- **Save/load** (`save.ts`): `saveWorld` snapshots everything to plain JSON (map layers as base64, `Rng.state`, buildings in id order); `World.load` restores it, and `tests/save.test.ts` asserts a loaded world continues bit-for-bit like the original. When you add simulation state, add it to `SaveData` and bump `SAVE_VERSION` if old saves can no longer load. Keep sim state plain data (no closures, class instances or functions) so it stays serializable.
- **Wild animals** (`animals.ts`, `ANIMALS` in `config.ts`: habitat `meadow`/`forest`/`shore`, speed, herd size, `herds` per 64×64 scaled by area, `roam`, `rest`): owner-less plain data in `World.animals` (saved with `nextAnimalId` and `animalRng`), spawned by `spawnAnimals` at generation away from every start (`ANIMAL_START_CLEARANCE`) and off owned land. During play Settlers 4's animal manager (`spawnGame`, `ANIMAL_SPAWN`, `CAnimalMgr::Update`/`SpawnAnimal`) makes ≈ 1.41 attempts a tick (one per S4 tick): a random square of `square` (5) tiles with no animal and no building gets a newborn of a kind whose `AnimalDef.spawn` lists the square's forest density (mature trees ≥ 1/4/8), on a habitable tile by a tree, while the kinds with `spawn` number below `animalCap` (S4's LAND_POP 8 × land % × squares / 10000, ≤ 1000; non-game ≤ `otherShare`). `updateAnimals` runs every tick: resting is a counter, walking a straight leg towards a habitable spot within `roam` of the herd's home (`habitable`: forest = grass near trees, shore = water next to land or land next to water; habitat is re-checked only on entering another tile, and an animal whose tile became unfit walks out). Animals occupy no tiles and block nothing. All their randomness comes from `World.animalRng`, a stream of their own, so they never shift the economy (a test plays a world with and without animals identically). The hunter (`hunting.ts`) takes deer (`AnimalDef.game`) from this list.
- **Economy settings** (`economy.ts`, `Player.economy`, saved, Settlers 4's settlers and production menus): `orders` — builders, diggers and specialists (`ORDERABLE`) are recruited by the dispatcher only up to the ordered totals (`World.orderWorkers`; defaults = the start level's), counted by `workersOf` once per tick (a derived per-world cache, recounted after a recruitment; dying settlers do not count); a lower order dismisses as in S4 (`RecruiteWorker`): an idle builder or digger over it turns back into a carrier and drops his tool on the ground (`dismissedOverOrder` in settlers.ts), one at a time; `toolOrders` — the toolsmith queue (`World.orderTool`, a count or `ENDLESS`); `minCarriers` — the carrier reserve (`World.setCarrierReserve`, settlers menu, see Logistics); `transport` — the transport priority (`World.moveTransport`, goods menu «Перевозка», `TransportView`); `distribution` — per good, weights per consumer type (`consumersOf` derives the types from recipes; `World.setDistribution`); for every good with several consumer types the demand loop serves the type with the lowest units-handed-out / weight first (`distributionKey` over `tally`; unset weights are `defaultWeight`: `DISTRIBUTION_DEFAULTS` — S4's bread → coal mine 85, the rest of bread shared equally [оценка] — else `DEFAULT_WEIGHT`), weight 0 gets none. Warehouses take in only the goods listed in `Building.accept` — as in Settlers 4 a new one takes nothing (`World.setAccepts`; the window shows «Принимает»/«Не принимает» lists of big icons, a click moves a good across — `ui/goodsLists.ts`, shared with the market window so both always look and behave the same); `nearestStorage(…, res)` skips them for surplus and returns; `setAccepts(…, false)` calls `redirectDeliveries`, which turns carriers already bringing that good there (their `drop`, its `inbound` and the `goto` before it) to the nearest accepting warehouse with room on the same land piece, or lets them finish when there is none — never through `abort`, whose failed return trip would lose the good. The AI sets nothing here except through these commands. **Start levels:** `START_CONDITIONS` (`low`/`medium`/`high`: S4's Roman piles and people — carriers 16/32/50, builders and diggers 3/5/2, swordsmen 6/10/12, archers 2/4/6, geologists 2/3/5, ready-made `workers` (smiths 1/2/3 as toolsmiths, miners 2/4/6, a hunter on high), donkeys 0/0/3; `new World(seed, { start })`, `?start=` in the browser). **House size** is Settlers 4's 10/20/50 on every map (`residence.capacity`); read it through `residentsOf(def)` / `residents(w, b)` (`buildings.ts`). **Hunter** (`hunting.ts`, behavior `hunt`, `HuntDef`): stalks the nearest unclaimed `AnimalDef.game` animal within `radius` of the lodge (reserved via `Animal.hunter`, released by `abort`), closes in up to `chases` times, shoots from `range`, removes the animal and carries the game home; game comes back through the animal manager (see Wild animals). **Paths** (`paths.ts`, `PATHS`): every step a settler completes onto a tile (`move`) adds wear in `map.wear` (saved layer) on `PATHS.terrains`; from `levels[k].wear` it is a dusty path, then a road, walked `speed` times faster (Settlers 4's 9/8 and 9/7) by professions with `roads` — carriers and donkeys only, as in S4 (`pathSpeed`, applied in `move`; A* ignores it); every `decayEvery` ticks each tile in `World.worn` (derived, rebuilt on load) loses `decay`. Level changes `touch` the tile; the renderer draws `path:<level>:<variant>` ground decals under the fields (`syncPath`).
- **Specialists** (`specialists.ts`, `PIONEER`, `GEOLOGIST`, `THIEF`, `INTRUDERS`): geologists (hammer), pioneers (shovel) and thieves are `ORDERABLE` like builders and diggers (`World.orderSpecialist` = the same orders, the settlers menu's «Заказ рабочих»), recruited by the dispatcher (the tool is used up on `retool`), then sent with `World.sendGeologist(x, y)` / `sendPioneer(x, y)` / `sendThief(buildingId)`; the errand lives in `Settler.errand` (saved: `n` tiles worked, `skip` unreachable tiles) and the idle behaviours `prospect`/`pioneer`/`thief` turn it into tasks; without one (or a post) they wait in the idle crowd. **Geologist and pioneer work like S4's `CGeologistRole`/`CPioneerRole`:** `nextTile` → `searchTile` looks out from where he stands (from the spot before his first tile) over a distance-sorted spiral (`spiral`, cached per reach) in windows of `window` offsets — the first window holding any tile decides, there the least d²(spot) + 3·d²(him) —, up to `reach`; tiles another specialist of the player is heading for are skipped (`takenBy`), and only tiles in his region (`sameRegion`). With nothing left in reach `finishErrand` drops the errand and posts him where he stands (`Settler.post`), waiting for orders; on open land a pioneer goes on a long time, as in S4. `isFreeSpecialist` (no errand; idle, or only `wait`/`goto` at his post) decides who `sendGeologist`/`sendPioneer`/`sendThief`, `dismissSpecialist` and the AI may use. A pioneer claims `claimable` tiles (neutral and passable; S4 needs no contact with his owner's land, so islands are possible), one per `claim` task; a claim writes `map.owner` at once and bumps `territoryVersion`; the tile is then ordinary land without influence (see Territory): it stays his owner's until another player's tower covers it. A thief (`THIEF`, S4's `CThiefRole`) is sent to a spot (`errand` {x, y}; `sendThief(b)` = its door); `lootAt` gives the first stack in a `lootRadius` spiral round it on explored tiles — a non-allied building's output (unreserved), input (a market's minus `trade.loading`), a site's `sitePile` at its door, or goods on the ground; on own or allied land only goods on the ground —; the `steal` task at that tile takes one unit after `stealTicks` and he carries it to his home point (`Settler.homeAt`: where he retooled, moved by any order to a spot on own/allied land, `orderedTo`) and puts it down there (`carryBack`), then goes back while there is loot (`robbable(b)`: loot at its door is its own). **Intruders** (`intruders.ts`, `INTRUDERS`, Settlers 4): every `scanEvery` ticks each specialist (`SPECIALIST_KINDS`) outdoors on land of a non-allied player is that player's intruder (`intruders`, cached per tick); a loaded donkey (`ProfessionDef.dropsLoad`) is one too, and a blow or shot on it (`strike`) is `donkeyHit`: both packs go on the ground where it stands, it is unhurt and goes home; a `cloaked` profession (the thief) is no target until unmasked (`checkMask`, every `scanEvery` ticks: any hostile outdoor fighter within `decloakRadius`, on any land, buildings never; disguised again every `recloakEvery` ticks on land not hostile with no hostile fighter within `recloakRadius`; `Settler.exposed`, saved); for each exposed intruder chased by fewer than `responders`, the nearest own military building with its door within `respondRadius` sends a spare melee fighter (above `keepOf`; `sendOut`) on a `chase` task, field melee units take intruders in `engageRadius` themselves after enemy fighters, field archers shoot them (`nearestIntruder`). `chase`: walks up (inserted `goto`), within `seizeRadius` pins the intruder (`e.opponent`; he stands), adjacent links both and strikes at his own cadence with ordinary blows (`duelTick` with `strikesBack` false) — specialists never strike back; his load is lost (`killSettler` counts whatever a dying settler carried in `stats.lost`), `stats.intrudersKilled`; it ends when he is dead, indoors, cloaked again or off the fighter's owner's land, then the fighter stands free (`soldierIdle`) until a building calls him. Free and field melee fighters go for an intruder in reach only while fewer than `responders` chase him (`chasers`). `abort` releases the pin; `updateSettler` drops an opponent that died. Specialists' `hp` is in `PROFESSIONS` (S4's: geologist and pioneer 25, thief 20); recruits get it on `retool`. `World.dismissSpecialist(kind)` turns an idle one on own land back into a carrier, putting the tool down on the ground (`toCarrier` → `carryBack`, S4's `CSettler::ChangeType`), and lowers the order. **Direct control of specialists** (as fighters, S4): `SPECIALIST_KINDS` (geologist, pioneer, thief) are selectable on the map; `World.orderSpecialists(ids, x, y, targetId)` gives each the action of its kind from `SPECIALIST_ORDERS` (`can`, `apply` — the cursor hint is the UI's `order.<kind>`, `orderLabel`: geologist — an `errand` on any mountain with something to examine in reach (`canProspect`); pioneer — `errand` where land is claimable in reach (`pioneerSpot`); thief — `errand` at a `robbable` building or a spot with `lootAt`) where `can` holds, else a `Settler.post` (spread with `formationSpots`) where `specialistPostIdle` keeps him waiting (checked first in the `pioneer`/`thief`/`prospect` idle behaviours, so a geologist with a post does not turn back into a carrier). `holdSpecialists` posts them where they stand, `dismissUnits` turns those on own land back into carriers (`toCarrier`). `clearSpecialist` drops errand, post and tasks via `abort`, keeping the specialist's own tool in hand (only an old save's geologist still holds one).
- **Land pieces, donkeys and markets** (`land.ts`, `trade.ts`, `TRADE`, Settlers 4 logistics): carriers carry only on their player's own land. `World.land` gives every owned tile the id of its piece (8-connected tiles of one owner), derived, rebuilt lazily by `ensureLand` whenever `territoryVersion` moved (also after pioneer claims), never saved; `landAt`/`landOf` (a building's piece = the piece at its door), `isCutOff` (no finished warehouse on the piece and not the owner's home piece, `Player.home`; cached per `buildingsVersion`, which a finished warehouse bumps). `dispatchFor` hands a job only when source, destination and carrier share a piece (idle carriers counted per piece, a piece without any skipped before searching, a piece with no supply drops all its consumers at once — with one piece this is the old behaviour); `nearestSupply`/`nearestStorage(…, piece)` filter by piece; a piece with work but no free carrier gets one from another piece (`relocate`: a plain `goto`; settlers walk anywhere; idle crowds prefer anchors on their own piece). A* itself is not restricted to own land. Donkeys are settlers with behavior `donkey`, bred by a building with `breeds` (the ranch's recipe releases one per cycle with its `outputChance` — S4's 25 % a feeding —, started only while `wantsDonkeys`: fewer than markets × `donkeysPerMarket`). A market (`def.market`) has `Building.trade = { to, orders, loading }` (saved; `World.setTradeRoute`, `World.orderTrade` with a count, `ENDLESS` or 0 — cancelling aborts carriers' `drop`s of that good already on their way (their load goes back to a warehouse) and moves waiting input to the output pile; a carrier's `drop` at a finished market without an order for the good (`marketOrdered`, checked by `wantedAt` in settlers.ts) lands on the output pile, never in the input, so nothing sits there with no donkey to take it); `marketWants` (part of `demand`) brings ordered goods up to `TRADE.stock` (24, S4's three piles); `dispatchTrade` (after `dispatchFor`, per player) fills the nearest idle donkey's `TRADE.packs` packs of up to `donkeyLoad` (S4: 2 × 8; one good per pack, a good may fill both) with ordered goods in the transport priority (`packLoads`) and sends it with `goto`/`load` per pack/`goto`/`unload` once its packs are full or no ordered good it has room for has more inbound, reserving `loading` (released by `releaseLoad` from `abort`); `load` takes up to n from the input and counts the order down — the first pack is `carrying` × `Settler.load`, the second `Settler.pack2` (read both with `packsOf`; `killSettler` counts both as lost) —, `unload` puts them on the destination market's output, where that piece's carriers take over; then the donkey walks back to where it stood when hired (`Settler.hiredAt`, saved; S4's `TryToGoHome`) if that spot is on the piece of land it stands on. A route may also lead to a market site (`routeTarget`): unloading there first counts what the site still lacks as delivered (`unloadTick`), so a market on a cut-off piece can be built at all (the building window still lists only finished markets as destinations). A donkey whose trip fails goes to the nearest own market with its load (`donkeyAbort`; none left → `stats.lost`). Rendering: `UNIT_ANIMALS` (animalArt.ts) maps settler kinds drawn as animals; `AnimalLayer.syncUnit` draws them from the animal sheets with the `pack` saddle and the carried ware, called from `syncSettlers` instead of a figure. Local buildings on a piece without a warehouse get the `cutoff` marker over the roof; `ui/tradeView.ts` adds the market's route and the ranch's herd to the building window (markets are named «Рынок №k» by `marketName`: k-th of the owner's markets by building id; destinations show the door-to-door distance in tiles); `render/tradeRoutes.ts` (`TradeRouteLayer`, one `Graphics` after the work-area overlay, under the objects) draws the local player's routes as terrain-following dashes with chevrons in the player's colour over a dark rim — bright for the selected market's route (either end), faint for the rest — redrawn only when routes or selection change; the goods go in two warehouse-style lists (carried / not carried, a click moves a good across and orders `ENDLESS`; a finite AI order shows its remainder in the item's corner).
- **Fighting strength** (`strength.ts`, `STRENGTH`, after S4): settlement value = materials in a player's finished buildings (`points` per plank/log/stone, `goldPoints` per gold, × `eyecatcher` for `def.eyecatcher` buildings); attack strength starts at `start − perPlayer × (players − 1)` (≥ `min`) and climbs `steps` (diminishing returns) up to `max`; defence is 100 % until attack passes it, then half its pace. Cached per world per tick (derived, never saved). `fieldFactor` multiplies a fighter's damage (`hitDamage`, blows and shots alike): attack strength on land not his owner's or an ally's, defence strength at home. `World.strengthOf(player)` for the HUD. Eyecatchers are ordinary worker-less, territory-less buildings (`decor` category); the AI weighs its party at its attack strength (it assumes the enemy's defence at 100 %) and builds eyecatchers from spare materials (`AI.decorEvery`, `AI.decorSpare`).
- **Work areas** (`workArea.ts`, `WORK_AREA`, Settlers 4): a building's work radius comes from the data — its worker's `gather`/`plant`/`hunt` radius or `def.mine.radius` (`workRadius`); the centre is the door, a mine's footprint centre (`defaultWorkCentre`), or `Building.workAt` (saved with the building) once the owner moves it with `World.setWorkArea(id, point | null)` — within `WORK_AREA.maxShift` × radius of the door, mines not movable (`movableWorkArea`). Gather/plant/hunt target searches (`findGatherTarget`, `hasGatherTargetNear`, `plantingsNear`, `findPlotFor`, `findGame`) measure from `workCentre(b)`; never from `b.door` directly.
- Tunables (timings, caps, costs, start resources) live in `config.ts`. **Timings follow Settlers 4 in real seconds at 1×, distances its proportions** (one of our tiles is `S4_TILES_PER_TILE` = 3 S4 tiles long, so sourced S4 distances — radii, archer range, sight — are divided by 3, and `SETTLER_SPEED` is S4's 9 ticks a tile over that: 0.52 tiles/s; `docs/PROPORTIONS.md`) (walking pace `SETTLER_SPEED`, `ProfessionDef.speed` for the riding squad leader, `BUILD_TICKS_PER_UNIT`, recipe ticks, gatherers' work/rest): the comparison table with sources and what is still unverified is `docs/TIMINGS.md` — keep it current when a timing changes.

### Rendering (`src/render`)
- Isometric projection is in `iso.ts`: tile center `(x, y)` maps to screen `((x-y)*32, (x+y)*16)`. Depth equals `x + y`. `objects` is a single `sortableChildren` container keyed by `zIndex`. Buildings use the depth of their footprint center plus 0.25, the door pile and flag use the door tile's depth minus 0.05, and settlers use their interpolated depth.
- **Terrain heights:** ground is one `MeshSimple` per chunk whose vertices are the tile corners raised by `map.height` (shared corners, so no seams), textured from the ground sprites in the atlas (they must all sit on one atlas page, which the builder asserts). **Transitions:** after each tile's own quad come overlay quads of its higher-priority neighbours (`GROUND_PRIORITY`: water < ford < swamp < sand < desert < grass < mountain < rock), using `edge:<kind>:<dir>` sprites (`paintGroundEdge`: the neighbour's ground faded in from that edge/corner with a ragged border, `EDGE_DIRS`); corner overlays are skipped where an edge neighbour of the same kind already covers them. Each chunk also gets a `Graphics` with slope shading lit from the top-left (`slopeLight`, quantised levels). Everything standing on the ground is placed with `surface(x, y)` (screen point minus `heightAt`), outlines (territory, hover, ghost, selection, geologist area) use `corner()` per tile corner, chunk culling bounds are lifted by the chunk's highest corner, and `pickTile` refines the flat inverse projection a few times by the height under the guess. Never place a world object with plain `toScreen` any more. **Runtime height changes:** `syncHeights` (throttled) rebuilds the ground (`buildChunkGround`), territory overlay and culling bounds of chunks whose `heightVersion` changed and re-seats their static objects (`addStatic` records each object's tile and offset from the surface) and field decals.
- `GameRenderer.sync()` reconciles by **polling sim state every frame** (view maps keyed by building and settler id; trees/deposits only in chunks whose `chunkVersion` changed; territory only in chunks whose owners changed). The sim emits no events, so new sim state only needs a matching branch in `sync*`.
- **Culling by chunk** (`CHUNK` = 16 tiles): ground, territory overlay and static objects (trees, rocks, deposits, buildings) are registered per chunk via `addStatic`/`removeStatic` and sit in the scene only while their chunk intersects the camera's `viewRect`; settlers join `objects` only while on screen. Per-frame sorting and drawing therefore follow the screen, not the map. New world objects must go through `addStatic` rather than `objects.addChild`.
- **Chunk unloading** (what makes 1024×1024 hold): `unloadHiddenChunks` (twice a second) gives back the render data of built chunks out of view for `UNLOAD_AFTER_MS` — or of any hidden ones while more than `MAX_READY_CHUNKS` are built — down to `KEEP_CHUNKS`: ground layer, boulders (`boulders[c]`), trees, deposits, signs, field and path decals (their per-tile states reset so `syncChangedTiles` recreates them; `chunkSeen[c] = −1`), the territory `Graphics` (replaced by a fresh one, `territoryPending`), the fog mesh/texture/canvas and the water glints (`Effects.unloadChunk`); `chunkReady[c] = 0` and `ensureChunk` rebuilds on sight. Buildings and settlers stay. **Pixi frees less than it seems:** `mesh.destroy()` keeps the geometry and its GPU buffers, `graphics.destroy({ children: true })` keeps the drawing context — free them with `disposeMesh` (geometry `destroy(true)`) and `disposeLayer` (`destroy({ context: true })`). Anything per-chunk you add must be released in `unloadChunk` too.
- **Lazy chunks** (what makes 512×512 start fast): `buildGround` only records heights; a chunk's ground mesh, boulders and territory are built by `ensureChunk` the first time it becomes visible (`chunkReady`), at most `CHUNK_BUILDS_PER_FRAME` per frame so a zoom-out never hitches. Tile objects (trees, deposits, fields) are synced only for visible chunks — `syncChangedTiles` leaves a hidden chunk's version stale and catches up when it scrolls in; territory for unbuilt chunks is deferred via `territoryPending`. Anything per-chunk you add must be built in `ensureChunk` and tolerate a chunk that was never built.
- **Classic art** (`?art=classic`, and the fallback for anything without a 3D image): procedural painters in `sprites.ts` draw with Canvas 2D, and `SpriteAtlas` (`atlas.ts`) packs them into 2× resolution canvas pages (a new page starts when one fills; the last page is cut to the rows it uses) with `defaultAnchor` set per frame. Most buildings are described by a `Style` in `STYLES` (walls, roof, floors, decorations like chimney/well/pen) painted by `paintStyled`; only special shapes (mill, tower, fortress…) have hand-written painters. Fields are flat decals added to their chunk's ground container. Building painters draw around the **footprint center as origin** and use the `P(dx, dy, z)` helper (tile-unit offsets plus pixel height); their canvas size and anchor live in `BUILDING_CANVAS`. Construction progress is shown by cropping the building texture from the top (`bottomPart`). To add a sprite, write a painter and register it in the `SpriteAtlas` constructor.
- **3D art** (the default; `?art=classic` keeps the procedural painters above): `art/blender/build.py` (helpers in `lib.py`) builds models with bpy and renders them with an orthographic camera matching `iso.ts` (rot 60°/0/45°, world X = tile x, world Y = −tile y, `PX_PER_UNIT` logical px per tile unit, 2× resolution, Cycles, shadow catcher on a transparent background, palette written in sRGB and converted by `lib.lin`) into `public/art/3d`; run `npm run art:render [-- names]` (Blender 5.x on PATH). Each sprite keeps the size/anchor convention of the procedural sprite it replaces (`ART3D_SPRITES` in `art3d.ts` must match `SINGLE` in `build.py`). `main.ts` loads them (`loadArt3d`) and `SpriteAtlas` re-registers them under the procedural keys (every `building:<type>` and its stages, `tree:*`, `deposit:*`, `prop:*`, `ware:*`, `pile:*`, ground and decals), so the rest of the renderer is art-agnostic; **Settlers** (`art/blender/figures.py`, `npm run art:settlers`: renders on the CPU, ~15 min, caches each pose group in `art/.tmp/settlers-cache` so an interrupted run resumes, then `art/tools/quantize.py` (Pillow) turns the pages into 256-colour PNGs, ~6× smaller; one Blender at a time): one stocky figure on pivots (hips, shoulders, a tool grip per hand) posed per group — `hold:<tool>` (walk frames, then standing) for every `TOOLS` shape incl. `carry`, `work:<action>` (4 frames) for every `ACTIONS` entry; the tables at the top of figures.py mirror `animConfig.ts` (tool per action, arm angles). **Outfits:** a profession's `SettlerStyle.outfit` (`legion`, `archer`, `leader`, `healer`, `watch`; `OUTFITS` in figures.py lists each one's tools and actions) gets its own pose groups `hold:<tool>@<outfit>` / `work:<action>@<outfit>` with the outfit's parts shown (`build_outfits`: banded steel armour and a curved scutum, leather armour and quiver, gilded cuirass, round golden shield and cloak; the healer's linen robe with a stole in the player's colour, satchel of herbs and flask, worn with the `coif` hat; the watchman's wool shoulder cape with the hood down and a horn at the hip, bare-headed, holding the `spear` tool upright — both work indoors, so they have hold groups only); civilians with the same tool (the hunter's bow) keep the plain groups. `settler3d.ts` resolves them with `holdFrames`/`workFrames(s3d, …, outfit)` (falling back to the plain group). Outfit groups are cached with `-r<LOOK_REV[outfit]>` in the name: bump `LOOK_REV` when an outfit's look changes. **Fighter levels** are shown by the helmet: `SettlerStyle.levelHats` (galea1/2/3: no crest, small crest, big crest) replaces `hatStyle` by `Settler.level`; the 3D path draws fighters' hats untinted (steel, gold) and hides the `chevrons` badge, which stays for `?art=classic`. Each frame renders twice: full colour, and a mask pass (material override with an emission of the object property `mask`: tunic, sleeves, shield face) that becomes the tintable copy; hats are a separate layer per `HAT_STYLES` style and direction (rendered with the body as a holdout). Frames are trimmed and shelf-packed into `settlers-<k>.png` pages; `settlers.json` has each frame's rect and anchor, the group tables, hats, `carryAt`/`carryBehind` and `rankY`. `settler3d.ts` turns it into textures once (`buildSettler3d`, `ImageSource` per page); `syncSettlers` then draws body = full frame, tunic sprite = tint frame (owner's colour for everyone in the 3D art, as in S4), hat = hat layer (profession colour), all 8 directions painted (no mirroring), swapping textures with `setFrame` (copies the anchor). A new profession needs no rendering unless it brings a new tool or action. **Bent poses:** everything above the belt hangs from a `waist` pivot; an action in `BEND` (figures.py, mirrored by `ActionDef.bend`) bows it forward per frame (the tunic then splits into a skirt that stays with the legs and a bodice that bends; the free hand rests forward, feet apart); `head_offset` records where the head went against standing in `settlers.json` `heads[group][dir][frame]` (logical px), `Frame3d.hatAt` carries it and `syncSettlers` moves the hat layer there; the arm-over-hat cut follows the head down. `settlers:add` (`build_settlers(add=True)`) renders only the groups `settlers.json` lacks and packs them after the last page's frames, leaving every existing frame and page as it is (re-quantize that last page). Work groups have a third frame, the arm-over-hat layer (`render_over`: only arms and tools render, body/head and a hat-sized proxy are holdouts, rows below the neck cleared); the 3D path draws it in the `arm` sprite above the hat. Read hand positions from the evaluated depsgraph, and call `view_layer.update()` before parenting parts to pivots, or offsets double. The look follows Settlers 4 (reference: in-game shots at settlers4-hd.com, kept out of the repo): `mat_stones` (Voronoi fieldstone), `mat_tiles` (terracotta), `mat_grain` (wood, thatch, bark, earth), `mat_leaves`, `apply_ao` (base colour × AO in every material) and `clean_alpha` post-processing (saturation, contrast, unsharp); buildings stand on a trodden-earth `pad` (solid core, then a noisy alpha fringe from a per-vertex `edge` attribute plus two noises, so the earth breaks up into the game's grass instead of ending in a line); `transform_apply` must keep location (`location=False`), or origins jump to the world origin. **Animals** (`art/blender/animals.py`, `npm run art:animals`, CPU, 4 threads): one sheet per kind, `animal-<kind>.png`, 8 rows in `DIRS` order × `ANIMAL_COLUMNS` (walk 0..3, stand, graze), cells = `ANIMAL_CELLS` in `animalArt.ts`, quantised to 256 colours; loading is optional, a kind without a sheet uses the procedural painter (`paintAnimal`), which is also the default art. `AnimalLayer` (`render/animals.ts`) draws one sprite per animal among the objects, only on screen and (fog on) only where the local player has sight. Style notes from the original (and what we deliberately do not copy, e.g. outlines) live in `docs/ART-STYLE.md`; reference screenshots stay in the git-ignored `examples/`. Quarry stone is `lib.spire` columns with `mat_crystal`. Narrow water (land on two opposite sides, or little water around) gets pebbles along its non-swamp banks (`streamBanks`, render-only, in the chunk's ground layer). Animals are drawn at `ANIMAL_SCALE` per kind (animalArt.ts) to keep proportions with the scaled settlers. Building models other than the woodcutter (in build.py) live in `art/blender/buildings.py` (shared helpers such as `log_cabin`, `plank_roof`, `stakes`, `timber_frame` are reached through `__main__`, i.e. build.py), modelled after close-ups of the original buildings (git-ignored `examples/ref-<type>.png`), with `stone_course` (rugged blocks of mixed tones over a dark core), `quoins` (staggered corner stones), `coping_line` (wall-top stones), `plank_walls`, `panel_slope` (riveted plank panels) and `scale_roof` (rounded slate scales or square terracotta tiles), plus general roof pieces — `place_on` (orient an object by two axes), `tile_face` (scales/tiles over any quad or triangle roof face, kept inside its edges), `hip_roof`, `cone_tiles` —, `round_tower`, `stepped_gable_x/_y`, `rivet_vault` (riveted furnace), mine pieces (`rock_pad`, `hill`, `adit`, `rails`, `cart`) and `scale_scene(k, kz=)` (scales the model built so far by parenting it to a scaled empty and returns the point mapping for `note_banner`: the medium house is the three-block house scaled to 2×2; barracks, pig farm and donkey ranch are scaled from 2×2 to their 3×3, the fortress (S4's castle) from 3×3 to 4×4, a little more in height); eyecatchers use the 1-tile `DECOR` canvas (80×120); `ART3D_BUILDINGS` in `art3d.ts` lists every 3D building with its canvas (= `BUILDING_CANVAS`, = `SINGLE` in build.py), and all of them have stages. Live-effect anchors of 3D buildings (chimney smoke, oven glow, the mill's sail hub) are recorded by `note_fx` while rendering and copied into `ART3D_FX`, which `Effects.anchorsOf` prefers to `buildingFxAnchors` in the 3D art. The 3D warehouse is an open paved yard (`ART3D_YARDS`): `syncYard` draws its stock on the platform — the `YARD_KINDS` most plentiful goods, one `pile:<res>:<n>` each, round the ring (pile sprites live in the building's `front` container, which chunk unloading keeps). A 3D military building records where its banner pole stands (`note_banner` prints it while rendering) in `ART3D_BANNERS`, which overrides `BANNERS` in the 3D art (tower, bigtower, fortress; the lookout has no garrison and shows only the roof flag). Every building type is now 3D; the military/HQ models use `battlements` (merlons along chosen edges), `square_keep` (faced block with quoins), `slit`, `gate` and `scaffold` (stage-1 poles). **Geologist's signs** (`art/blender/signs.py`, `-- signs`): a small board of warm planks on a stake (two board shapes, `VARIANTS`, each at its own lean) with painted symbols (outlined flat shapes with a little emission: coal lumps, rust-red iron-ore lumps, gold bars, white stone blocks), 1–3 of them, or bare; a fill light from the camera side keeps the face lit; one strip `signs.png` + `signs.json` (frame, variants, levels, ore order; `signFrame` in art3d.ts), optional — without it the classic `paintSign`. The renderer (`syncSign`) draws `sign:<variant>:<ore code>:<symbols>` for the local player's live signs (`signBy`), an `addStatic` object per tile at a hash offset from the centre, depth-sorted at that point, `SIGN_SCALE`, none under a building; `liveSigns` is re-checked every `SIGN_SWEEP_TICKS` (expiry touches no chunk; mines change the amount) and a sign fades over its last `SIGN_FADE_TICKS`; `unloadChunk` drops them with the chunk. The mill's sails in the 3D art are pre-rendered too: `buildings.render_mill_sails` (`npm run art:render -- millsails`) renders `MILL_SAIL_FRAMES` frames of a quarter turn on the mill's own canvas into the strip `millsails.png`; the atlas registers them as `sails3d:<k>` and `Effects` flips through them by the sails' angle instead of rotating the flat `fx:sails` sprite. 3D settler figures are rendered large for detail and drawn at `SETTLER_3D_SCALE` (art3d.ts) so they keep S4 proportions next to buildings (a settler about a third as tall as a small house). Building heights follow Settlers 4 in settler heights (sprite bounds ÷ ≈ 30 px, `docs/PROPORTIONS.md`): the small tower about as tall as a small house (≈ 4), the big tower a house plus 10–20 % and wider (≈ 4.5), the lookout lower than the small tower (≈ 3.5), the fortress (S4's castle, «Замок» in the game) ≈ 7.1. HTML icons (`buildingIcon`, `wareIcon`, `settlerIcon` in `atlas.ts`) use the 3D images when loaded, cropped to their opaque bounds, drawn by `imageIcon` into a canvas of `size` CSS px backed by round(size × devicePixelRatio) pixels (`iconCanvas`; never set a CSS size on these canvases other than the one they were made for — make the icon at the size it is shown), on whole pixels, large reductions halved step by step (`drawReduced`); building pictures and settler portraits are never enlarged past their own pixels (`maxScale` 1). `wareIcon` takes the resource's menu icon from `icons.png` (`Art3d.icons`, optional; else the carried ware, else `paintWare`); the pack donkey's portrait comes from `animal-donkey-portrait.png` (`animals.py` `portraits`, `PORTRAIT_SCALE` × a cell, for the kinds in `PORTRAITS` = `UNIT_ANIMALS`; optional, else the sheet's standing frame). **Ground textures** (`art/textures/ground.py`, `npm run art:ground`, runs in Blender for numpy): `KINDS` maps every ground kind to a generator and a period (grass 8 tiles, the rest 4 — every ground diamond plus the transition overlays must fit one atlas page); `ground.json` lists `kinds` with their periods, plus the `fields` decal strips (`fields-<crop>.png`, a 66×40 frame per stage, registered as `field:<crop>:<stage>`; grain has 5: sown … ripe, then the stubble of `CROP_STUBBLE`, drawn from its own RNG stream so the path decals after it stay the same — a strip without that frame gets `paintStubble` over its sown frame, which `?art=classic` always uses) and the `paths` strips (`path-<level>.png`, 80×44 frames, `path:<level>:<v>`), all generated here too. Trees and ground props come from `art/blender/nature.py` (`-- trees`, `-- props`): `tree:0..ART3D_TREES-1` (three conifers, three broadleaf; the renderer picks `hash % atlas.treeVariants`) and `prop:<k>` (`ART3D_PROPS`), which `scatterProps` places on about one grass tile in `PROP_EVERY` (by tile hash, skipping occupied tiles) inside the chunk's ground layer, so they are render-only, sit under everything standing and unload with the layer. Grass is combed tapered strokes along a slowly swaying direction field over band-limited broad swells of light and shade; a texture periodic over `PERIOD`×`PERIOD` tiles, sliced into diamonds exactly as `quadOf` samples them; the atlas registers them as `ground:<kind>:<v>` (`groundPeriod`), the renderer picks variant (x mod p) + p·(y mod p) so tiles join seamlessly, and transition overlays keep the procedural ragged mask filled with the texture. **Goods** (`art/blender/goods.py`): `GOODS` maps every resource, in `RESOURCES` order, to an item builder (one ware at ~0.3 tile, lying or standing around the origin) and a pile layout (`rows`, `layers`, `grid`, `spread`, `heap`, `bundle`: `PILE_MAX` placements, a pile of n uses the first n); it renders `piles-<res>.png` (strip of `PILE_MAX` frames of `PILE` size) and `wares.png` + `wares.json` (one carried ware per resource, centred, no shadow). **Menu icons** (`-- icons`, `icons:axe,saw` re-renders only those into the existing sheet): `ICONS` (every resource, `GOODS` order) says how each is shown — `ground` (a small group lying with a contact shadow, e.g. a heap of coal, stacked bars, a bucket) or `upright` (stood up with its broad side to the camera, long axis rolled diagonal, working end up-right, no shadow) — and may give an icon-only `build` (chunkier tools with `prism`-extruded heads and blades so axe, pickaxe and hammer differ in silhouette, a cuirass, a sheaf, an open flour sack, gold ore with nuggets, a bow with an arrow); each renders into its own `ICON`² (96 px) square with an orthographic camera fitted to the item (`fit_camera`, shadow included, `ICON_MARGIN`), light from the upper left-front (`icon_light`) and a bright-sky/dark-ground world (`icon_world`) so metal shows highlights, into `icons.png` (`ICON_COLUMNS` a row) + `icons.json` (`size`, `columns`, `order`). They render on the CPU (tiny frames; keeps the GPU free). A new resource needs a `GOODS` entry and an `ICONS` entry.
- Player colours live in `PLAYER_COLORS` (`sprites.ts`); the only per-player atlas variants are `flag:<player>` (the occupied-building flag, set on the roof at `SpriteAtlas.topOf` — the highest drawn pixel in the middle half of the building sprite; hidden where a banner is) and `banner:<player>` (`paintBanner`: the owner's banner with an eagle on a crossbar over military buildings, at `BANNERS`) (fighters wear their owner's colour as a tint, see below). A fighter's level is drawn by his helmet (`levelHats`) and, under `?art=classic`, as a `chevrons:<level>` sprite above the head, and arrows (`World.shots`) as arcs in the `shots` Graphics layer above the objects. Territory chunks dim land that is not the local player's and draw every player's border as in Settlers 4: a post topped with a cube in the player's colour two per border edge, at ¼ and ¾ (`drawBorder`). Settler views whose settler died are destroyed on the next sync; building flags follow ownership changes, and so do roof banners (`BANNERS` in `sprites.ts`: where the `flag:<owner>` sprite sits on every military building — building painters must not paint owner colours themselves). Duelling pairs are drawn at `FIGHT_SPOTS` offsets so simultaneous fights at one door stay apart.

- **Burnt ruins** (render-only): `removeBuilding(b, 'burn')` pushes `{x, y, w, h, type, owner, tick, until}` onto `World.ruins` (a visual list like `World.shots`: nothing in the sim reads it, not saved — a loaded game shows none —, pruned in `step` once `until` = tick + `RUIN.ticks` has passed); `syncRuins` draws one `ruin:<side>` sprite each (side = the footprint's, 1…`RUIN_SIZES`; 3D `ruin<n>` from `art/blender/ruins.py` on the canvas of a building that size, `ART3D_RUINS`; classic `paintRuin`), an `addStatic` object at the footprint centre just under what stands there, dropped at once when a building is placed on the footprint; `Effects.attachRuin`/`setRuinHeat` puff dark smoke (and sparks while hot) from a few spots over it, thinner as it cools, and the sprite fades over the last `RUIN_FADE` of its time. The showcase keeps one of every size smoking (`until` frozen).
- **Fog rendering** (local player, off with `?fog=off`): a `fog` container above `objects` and the arrow layer holds, per chunk, a soft-edged mesh: a (CHUNK+2)² canvas with one pixel per tile (one-tile margin) whose alpha is the tile's darkness (unexplored 1, explored out of sight 0.42), stretched over the chunk's height-raised tile corners with linear filtering, so darkness fades across tiles as in Settlers 4. `syncFog` (every 150 ms) compares each visible chunk's states (margin included, `fogPrev`) and redraws the canvas only on change; the mesh is rebuilt when the chunk's heights change. It also hides static objects standing on unexplored tiles (and `addStatic` hides new ones there). Other players' settlers are drawn only where the local player has sight; the minimap and the building info panel follow the same rules, and buildings under unexplored fog cannot be selected.
- **Settler animation** (`anim.ts` pure helpers, `animConfig.ts` data, `settlerArt.ts` painters): a settler is a container of layered sprites — `body` (shadow, legs, far arm), `tunic` and `hat` (painted grey, tinted per profession from `styleOf(kind)` or with the owner's colour for `fighter` styles), `head`, the near `arm` with its tool, the carried `ware` and the rank badge. Five directions are painted (`PAINTED_DIR`: E, SE, S, NE, N); W, SW and NW mirror them (`MIRRORED`, `root.scale.x = -1`); facing away (`FACES_AWAY`) the arm and goods go behind the body. Direction comes from the tick velocity (`dirFromTileVelocity`), the opponent or the work target (`workTarget`); walk frames from the distance walked (`walkFrame`, no foot sliding), work frames from time with a per-id offset (`workFrame`), idle settlers glance around (`idleDir`). Atlas keys: `sb:<pd>:<frame>`, `st:<pd>`, `shd:<pd>`, `sht:<hat>:<pd>`, `sa:hold:<tool>:<pd>:<frame>`, `sa:work:<action>:<pd>:<frame>`; identical arm poses are painted once and aliased. Textures for each layer are resolved once (`SpriteAtlas.settlerTextures()`), so the per-frame loop does no string lookups. **To add a profession look:** a `STYLES` entry in `animConfig.ts` (tunic, hat colour and `HatStyle`, `work` action, held tool). **To add a work animation:** an `ACTIONS` entry (tool, four arm angles in turns of π, loop length, optional sound on a frame; `bend` bows the 3D figure's torso, see 3D art) — the atlas paints it automatically; map tasks to it in `PLANT_ACTION`/`GATHER_ACTION` if it depends on what is gathered or planted, or in `TASK_ACTION` by task kind (`prospect` → `knock`: the geologist bent over the rock, knocking it with his hammer). The 3D figure needs the pose group (`npm run art:render -- settlers:add`); until it is rendered, `buildSettler3d` shows the action's tool held still. A new tool shape needs a case in `paintArm`.
- **Live effects** (`effects.ts`, painters in `fxArt.ts`): one `Effects` instance owns `fxLayer` (smoke, dust, leaves, sparks, hit flashes; above `objects`/arrows, under the fog) and `waterLayer` (sun glints, right above the ground meshes; a separate layer, the ground meshes are untouched). Particles are a fixed pool of `MAX_PARTICLES` sprites with typed-array state, recycled round-robin — nothing is allocated per frame. A unit that dies on screen gives up `soul`: a puff of its owner's colour with a light additive core that rises slowly and holds for most of `SOUL_MS` before fading (`emit`'s fade exponent, `SOUL_FADE`). Building effects are data (`BUILDING_FX` in `animConfig.ts`: smoke always/while working, fire glow, mill sails, ambient sound) placed at anchors the building painters export (`buildingFxAnchors`, `MILL_HUB` in `sprites.ts`); glows and sails are children of the building's body container, so they cull with it. A workshop counts as working while its recipe `timer` moved within `WORKING_GRACE_MS` (render-side, no sim flag). A mature tree that disappears is handed to `fellTree` (topples and fades, then is destroyed); trees in visible chunks sway (skew) unless zoomed far out. Everything runs only for on-screen buildings and visible chunks.
- **Sound** (`src/audio`): `GameRenderer.onSound(id, x, y)` is called for sound-worthy changes on screen (an action's `sound` frame, building ambience, tree falls, sword blows when hp drops, new arrows, finished buildings); `main.ts` forwards it to `AudioEngine.at`, which attenuates by distance to the camera centre, pans, and rate-limits (`mix.ts`: `attenuation`, `panOf`, `RateLimiter` — pure, unit-tested). Every sound is a WebAudio recipe in `sounds.ts`; the music is a generative pad + pentatonic plucks + birds scheduled in `AudioEngine.update()`. The context is created on the first pointer/key gesture; mute/volume/music persist under `localStorage['settlers.audio']` (all storage access guarded). **To add a sound:** a `SoundId`, a recipe in `RECIPES`, and a trigger (an `ActionDef.sound`, a `BuildingFx.sound`, or a renderer `sound(...)` call). The controls (`ui/audioControls.ts`) live in the options menu (passed to `Hud` from `main.ts`); `M` toggles mute.
- `Sprite.anchor` is taken from `texture.defaultAnchor` only at construction time. After you swap a texture with a different anchor, copy the anchor explicitly.
- Pixi gotcha: `container.removeChildren(begin)` throws when the range is empty. This once froze the whole game loop, because an exception inside the ticker stops it.
