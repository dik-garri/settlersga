# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Browser prototype of a Settlers 3/4-style economy game: isometric 2D, sprites, TypeScript + Vite + PixiJS 8. UI text is in Russian. Original prototype spec (historical, describes only the first version): `docs/superpowers/specs/2026-10-06-settlers-prototype-design.md`. Long-term plan toward Settlers 4 parity, with phases and known tech debt: `docs/ROADMAP.md` — check it before starting a new feature and keep it current. Feature-by-feature comparison with Settlers 3/4 (sourced; what matches, what deliberately differs, what needs fixing, what is excluded): `docs/S4-PARITY.md` — check it when designing a mechanic that exists in S4, and update it with the roadmap. Timings (walking, construction, digging, production) against the original, with sources: `docs/TIMINGS.md`. Out of scope by decision: magic (temples, priests, mana — and with it wine, whose only S4 use is magic), the Dark Tribe, a map editor, seasons and weather; for now also ships and harbours, and war machines. The developer handbook (setup, tests, headless tools, `?demo`, every URL parameter, browser debugging, the art pipeline, the release workflow) is `docs/DEVELOPMENT.md` (Russian, for humans); keep it current when a command, tool flag or URL parameter changes.

## Workflow

Once a change is verified (tests and typecheck pass, and the game has been checked in the browser when rendering or UI changed), commit and push to `origin main` without asking. Update `README.md` (player-facing, in Russian) and this file in the same commit whenever the change affects them.

## Scalability is a hard requirement

The target is Settlers 4 scale, so every change must scale along three axes:
- **Content:** a new building, profession, resource or recipe is a data entry in `config.ts` (plus a sprite), never a new `if (type === ...)` branch in sim logic. If a feature cannot be expressed as data, extend the data model (a new `Behavior`, a new rule table) rather than special-casing a type.
- **Players:** everything that belongs to someone carries an `owner` (`PlayerId`); logic filters by owner and never assumes a single player. `LOCAL_PLAYER` is only a default for UI-facing calls.
- **Size:** no hard-coded map dimensions or population assumptions; per-tick work must stay roughly proportional to active entities, not to map area or to entities squared. Measure with the hour-long probe before and after.

## Deployment

Every push to `main` builds the game and publishes it to GitHub Pages (`.github/workflows/pages.yml`: `npm ci`, `npm run build`, deploy `dist/`) at https://dik-garri.github.io/settlersga/. `vite.config.ts` uses a relative `base` so the build works under the repo sub-path. Tests do not gate the deployment, so run them before pushing as described above.

## Commands

```bash
npm run dev            # Vite dev server
npm test               # Vitest, all tests (tests/*.test.ts)
npx vitest run tests/world.test.ts          # single file
npx vitest run -t "builds a site"           # single test by name
npm run typecheck      # tsc --noEmit (strict, noUnusedLocals/Parameters)
npm run build          # typecheck + vite build
npm run sim:probe      # economy health: standard opening, 60 min on 4 seeds (--seeds= --minutes= --size=)
npm run sim:bench      # sim performance: 256×256 map, 1000 settlers (--size= --settlers= --ticks=)
npm run sim:ai         # computer players, headless: AI vs AI or vs a passive player 1 (--passive=1 --seeds= --minutes= --cost=1 --levels=easy,hard)
npm run art:render     # Blender: re-render 3D sprites into public/art/3d (no names = everything; -- <building> deposit trees props piles piles:fish,coal wares millsails settlers)
npm run art:quantize   # after any art:render: shrink every 3D sprite to a 256-colour PNG (Pillow)
npm run art:settlers   # Blender: re-render the settler figures (CPU, ~15 min, cached in art/.tmp) and quantize them
npm run art:ground     # Blender: regenerate the seamless ground textures of every kind, field and path decals into public/art/3d
npm run art:animals    # Blender: re-render the animal sheets into public/art/3d (-- deer donkey duck chicken)
```

Long simulations need more than Vitest's 5 s default; `vitest.config.ts` sets a 60 s test timeout and excludes `.claude/` (agent worktrees). Run `sim:probe` before and after any change to economy logic or balance, and `sim:bench` before and after anything that touches per-tick work. Reference numbers (Apple Silicon): 256×256 with 1000 settlers ≈ 1.0 ms/tick (the bench supplies every profession's tool so every workplace is staffed), 3000 settlers ≈ 2.9 ms/tick; a 64×64 hour of play ≈ 0.02 ms/tick; a 512×512 map with 4 AI players generates in ≈ 0.2–0.4 s and plays at ≈ 0.4–0.6 ms/tick in its first minutes; 1024×1024 generates in ≈ 0.5 s, and `sim:bench -- --size=1024` (12k buildings, 1000 settlers) runs ≈ 3 ms/tick — since swamps became impassable, A* searches there explore ~10× more nodes (detours), still far within budget.

Run `sim:ai` after any change to the AI, the economy or combat (it shows whether computer players still grow and still finish games). Append `?seed=N` to the dev URL for a reproducible map (the seed is logged to the console) and `?size=N` for another map size (up to 1024); `?players=N` sets the number of players (browser default 2, every player but 1 computer-controlled; `?ai=off` keeps them passive); `?fog=off` hides the fog of war; `?load=1` restores the latest save (`?load=<id>` a given slot); `?start=low|high` picks the start level, `?teams=1,1,2,2` the teams, `?levels=easy,hard` the AI difficulty per player, `?art=classic` the procedural art, `?menu` forces the main menu (the full list is in `docs/DEVELOPMENT.md`). Without game parameters the page opens the intro (first visit) and the main menu. `?demo` opens the dev showcase (`src/dev/showcase.ts`, loaded lazily): a 128×128 world (a second, passive player far away, for the thief) that builds itself up (extra soldiers, carriers and diggers spawned, two tower rings, every buildable type placed and fast-forwarded), then adds construction sites frozen at each stage, finished huts with goods piles of every resource, a pioneer at the border and a thief at a warehouse of player 2's, a field squad of fighters formed round a squad leader — frozen by `unreachableUntil = MAX_SAFE_INTEGER`, which logistics, builders and diggers skip; it defaults to no fog (`?fog=on`), a manned tower out on its own (land cut off from every warehouse) with a market to which donkeys carry planks and stone from the market by the castle, and `tests/showcase.test.ts` keeps it complete. When you add a building, resource or visual state, make sure the showcase shows it. `window.world` (plus `state`, `renderer`, `camera`, `audio`) exposes the live game for poking from DevTools, e.g. `world.placeBuilding('sawmill', x, y)` or calling `world.step()` in a loop to fast-forward.

## Architecture

Three layers with one-way dependencies: `ui → render → sim`, plus `src/audio` (WebAudio, imports only render-side data types) wired up in `main.ts`. `src/sim` must stay free of DOM/Pixi imports so it runs headless in Vitest.

### Simulation (`src/sim`)
- `World` (`world.ts`) holds all state and the public API and advances with `step()` at a fixed 10 ticks/s (`TICKS_PER_SECOND`). Logic lives in sibling modules that take the world as first argument: `buildings.ts` (creation, workshop recipes, territory), `settlers.ts` (task execution, per-behavior idle logic, `abort`), `logistics.ts` (dispatcher, demand), `nature.ts` (trees, planting, gather rules), `military.ts` (garrisons, recruiting, attacks, duels, conquest, `killSettler`), `combat.ts` (blows, shots and duel timing). Fields those modules mutate are public on `World` under "Internal state shared by the sim modules".
- It is deterministic: all randomness goes through the seeded `Rng` (`rng.ts`). Never use `Math.random` in sim code.
- Tile coordinates are integers, and a tile's center is the integer point. Settlers store float `x/y` plus `px/py` (the position at the previous tick) so the renderer can interpolate.
- `GameMap` (`map.ts`) is flat typed arrays indexed by `idx(x, y)`: `terrain`, `tree` (0 means none, 1..`TREE_MATURE` are growth stages, and any tree blocks movement), `stone` (units left in a deposit; blocks while > 0), `owner` (player id, 0 = nobody), `building`, and `door` (both hold building ids, 0 means none). `height` is different: one value per tile **corner**, (w+1)×(h+1), in screen pixels; vertex (vx, vy) is the corner at tile coordinates (vx − ½, vy − ½). Read it through `vertexHeight`, `heightAt` (bilinear, fractional tile coordinates; a tile center is the mean of its corners) and `heightRange`. Heights are generated from the terrain and the height noise (`elevate` in `map.ts`, no RNG use); at runtime only diggers change them, through `setVertexHeight`, which bumps the `heightVersion` of every chunk touching the corner.
- Every building has a **door tile** (`doorOf`: `(x+w-1, y+h)`, in front of the lower-left wall). It is walkable but not buildable. All pickups and drops happen there. For warehouses (`storage: true`, e.g. the castle), `output` is the stock.
- **Settlers run a task queue** (`Settler.tasks`, union type `Task` in `types.ts`). `updateSettler` executes the head task each tick. An empty queue calls `idle()`, which switches on the profession's `Behavior` from the `PROFESSIONS` table (carrier, builder, digger, gather, plant, farm = harvest if ripe else sow, workshop, garrison, prospect, soldier). Workers are carriers converted by the `become` task.
- **Reservation invariant:** jobs reserve resources up front (`outReserved` on the source, `inbound` on the destination, `reservedTargets`, `reservedPlots`, `builderIds`, `diggerIds`, `workerRequested`). Any job that can fail must go through `abort()`, which walks the *remaining* tasks and releases what they hold. When you add a task type that reserves something, add its release to `abort()`. `tests/world.test.ts` checks that counters never go negative and that planks and stone are conserved.
- **Connectivity invariant:** anything that turns a walkable tile into a blocked one at runtime (forester planting, natural tree spread, building footprints via `canPlace`) must first pass `staysConnected` (`pathfinding.ts`): a conservative local check that blocking the tile does not cut any route. `regions.ts` relies on it: walkable regions are a union-find that never needs splitting, so `findPath` rejects unreachable goals in O(1) instead of flooding the map. Anything that makes a tile walkable at runtime must call `markWalkable` (harvest already does).
- **Terrain is data:** `TERRAIN` in `config.ts` holds per-terrain rules — `walkable`, `build` (`'ground'` for ordinary buildings, `'mountain'` for mines, or null), `plantable` (trees, fields, natural spread), `speed` (walking factor ≤ 1; A* charges `TERRAIN_COST` = 1/speed per entered tile, so the octile heuristic stays admissible; settlers spend their per-tick budget at that speed), `water` (wells, fish) and the minimap `rgb`. Sim code reads only the table: `map.isPassableTerrain`, `isBuildable(x, y, ground)` (a `Terrain` argument stands for the kind it accepts), `isPlantable`. **To add a terrain:** a `Terrain` code, a `TERRAIN` entry, a generation rule, and a ground sprite (`GROUND_COLORS`, `paintGround`, a place in `GROUND_PRIORITY` for transitions, `TERRAIN_KIND` in the renderer); `elevate` needs a height case.
- **Map generation** (`generateMap`): height/forest/ore noise from the main RNG, then features that use their own RNG streams so they never shift the rest of the generation: `addRidges` (mountain chains, strength grows with map size from nothing on 64×64) and `carveRivers` (`RIVERS_PER_64`, steepest descent with meander from high ground into water or a small lake, sandy banks, a `Terrain.Ford` — walkable shallow water — every `FORD_EVERY` tiles on a straight stretch, so rivers never cut land apart; they keep `RIVER_START_CLEARANCE` from every start), then `addBiomes` (its own RNG stream too: a moisture noise and a BFS distance to water turn dry grass far from water into `Terrain.Desert` and wet low ground near water into `Terrain.Swamp`, `BIOMES` thresholds, nothing within `startClearance` of a start). Start areas are prepared after that: `START_GUARANTEES` (data, the same for every start, offsets from the castle centre) — a near coal/iron mountain inside the castle's land, a far stone/gold/coal mountain just beyond it (lobes grow with the map via `guaranteeScale`, richer ore per tile, `oreAmount`), and quarries (the first from the main RNG as it always was, others from their own stream). Then `connectLand` keeps the land in one piece (swamp is impassable): two passes of `bridge` from the first castle — across swamps by terrain (a dried 4-connected track to every sizeable stretch of land a swamp separates; pockets under `POCKET` tiles drown into the swamp), then across forests (a felled track to every sizeable clearing); boulders are left alone. No RNG, O(map); `tests/biomes.test.ts` checks that no land swamps alone separate stays cut off.
- **Digging:** every site except mines (`needsDigger`) is placed with `levelled = false`: a digger first clears it, `clearStrokes(b)` spade strokes (`CLEAR_STROKES_PER_TILE` per footprint tile) counted in `b.dug`, after flattening it if needed — sites whose footprint + door corners vary by more than `BUILD_MAX_SLOPE` (up to `BUILD_DIG_SLOPE`) get a `levelTo` height, flat ones `levelTo = −1` (`digging.ts`). Carriers deliver materials meanwhile; builders and builder recruitment ignore uncleared sites. Players start with their start level's diggers; more come only as ordered (see Economy settings). As in Settlers 4 several diggers share a site: up to `diggersWanted` (one plus one per `DIG_STROKES_PER_DIGGER` strokes still to do, `strokesLeft`, at most `MAX_DIGGERS`) join its `diggerIds` and run the `dig` task, each moving one corner one pixel towards `levelTo` every `DIG_EVERY` ticks (`levelStep`), then sharing the clearing strokes. Builders likewise: up to `buildersOf(type)` (`SITE_BUILDERS`, Settlers 4's builder spots per building) in `builderIds`, every one adding a tick of `progress`. Both stand on `siteSpot` tiles along the front wall (door first, only tiles in the door's region). `abort` and `killSettler` release them with `leaveSite`.
- **Tile change tracking:** every runtime write to `map.tree`, `map.stone`, `map.crop`, `map.prospected`, `map.oreAmount` reaching 0, or `map.wear` crossing a path level must be followed by `map.touch(i)`, which bumps the tile's chunk version; the renderer re-scans only changed chunks.
- `findPath` reuses per-map scratch buffers (cost follows nodes explored, not map area) and counts work in `pathStats` for the bench.
- **Failure handling:** a `goto` with no route calls `routeFailed`: the job's target building gets `unreachableUntil` (logistics, builders and storage lookup skip it via `isReachable`), the job is aborted and the settler waits `PATH_FAIL_BACKOFF` ticks instead of retrying every tick. `abort()` sends goods in hand back to the nearest warehouse (`drop` with `back: true`); only if that trip fails too is the unit counted in `stats.lost`. Builders without material for `BUILDER_STALL_TICKS` move to a site that has some.
- **Logistics:** `dispatch()` runs every `DISPATCH_EVERY` ticks, per player, and hands work only to that player's idle carriers on the same piece of land as the job (see Land pieces below), in this priority: worker requests, then demands (`demand()`: site materials from `cost`, workshop inputs from `recipe.inputs`; served one unit per round to the least-stocked consumer so scarce goods are shared, each from the nearest supply), then producers' surplus carried to the nearest warehouse. Distances use straight lines; A* (`pathfinding.ts`, 8-way, no corner cutting, `adjacent` mode for blocked targets such as trees) runs lazily inside the `goto` task, and the route is recomputed when the next tile becomes blocked.
- **Buildings are data** (`BUILDINGS` in `config.ts`): `cost`, `worker`, `category` (build-menu tab), `storage` (warehouse), `recipe` (workshop inputs → outputs per `ticks`, run by `updateBuilding` while the worker is inside), `territory` (radius), `residence` (releases `capacity` carriers; the only source of population growth). **Gatherers and planters** share code paths: a profession's `gather` def plus `GATHER_RULES` in `nature.ts` (which tile yields a resource and what taking it does), and a `plant` def plus `PLANT_RULES` (`tree` blocks and must pass connectivity, `grain` fields stay walkable). A new gathering/planting profession is a `PROFESSIONS` entry plus, for a new resource or planting kind, a rule.
- **Mining:** `Terrain.Mountain` is walkable and only accepts buildings with `terrain: 'mountain'` (`canPlace` passes the terrain to `isBuildable`); `Terrain.Rock` stays impassable. Ore lives in `map.ore` (kind code = `ORE_RESOURCES` index + 1, decode with `oreOf`) and `map.oreAmount`. A mine is a workshop whose recipe uses `inputsAnyOf` (any one food; each food has its own pile of up to `INPUT_CAP` in `demand()`) plus `def.mine` (`res`, `radius`, `favourite` food); `updateBuilding` hands it to `runMine` (Settlers 4 rules, `MINING`): eating a food stores `Building.attempts` — `favourite` buys 10, any other 2 —; every `recipe.ticks` one attempt picks a random ore tile of its kind in range (world RNG) and yields a unit surely while the tile holds `sureAmount`+, else with `chancePerUnit` × units left. The geologist is a carrier on an errand (`sendGeologist` fetches his tool, a hammer, from the pile nearest the site — no hammer, no errand —, sets `kind = 'geologist'` and a list of `goto`/`prospect` tasks; when the errand ends he takes the hammer back to a warehouse; the `prospect` behavior turns him back into a carrier when the queue empties; unreachable tiles are skipped in `routeFailed`). Results go to the per-player bitmask `map.prospected`.
- **Idle crowds** (`idle.ts`, `IDLE` in `config.ts`): free carriers, and builders/diggers without a site, call `restIdle` instead of walking into a warehouse. After `IDLE_GO_HOME_TICKS` each picks a gathering building (`idleAt`: nearest warehouse/castle/house, `IDLE.gatherAt`, preferring one with fewer than `IDLE.groupSize` idle settlers) and stays outside near its door: every `IDLE.strollEvery` ticks it strolls to a free spot within `IDLE.radius` (walkable, owned, not a door, not water) or, with `IDLE.chatChance`, next to another idle settler of the group (`chatWith`, mutual; `chatPartner` validates it, so killed or busy partners need no clean-up; the renderer turns pairs to face each other). The stroll lives in `stroll` + `path`, never in `tasks`, so everything that treats `tasks.length === 0` as "idle" (dispatcher `take`, barracks, AI, geologist) is unchanged; `updateSettler` drops `stroll`, `path` and `chatWith` as soon as a task arrives. Settlers block no tiles, so crowds need no connectivity checks. Randomness comes from `World.idleRng` (saved), but where idle settlers stand changes which carrier the dispatcher picks, so the economy's outcome does shift (throughput measured, not identical).
- **Tools:** a profession's `tool` must be fetched before taking up the job: worker requests in `dispatchFor` add a `goto`/`pickup` of the tool from the nearest pile, and `become` (or `retool` for builders and diggers, recruited up to the player's orders) consumes it. A recipe with `outputChoice` (the toolsmith) makes whatever `chooseOutput` says is most awaited (`waitingFor`: staffing workplaces, ordered builders/diggers not there yet, garrison slots) or below `keepInStock`, and idles otherwise; with `orderable` the player's order queue goes first (`orderedOutput`, counted off by `toolMade`).
- **Player commands** live on `World` (`placeBuilding`, `sendGeologist`, `sendPioneer`, `sendThief`, `orderSpecialist`, `dismissSpecialist`, `setPriority`, `demolish`, `attack`, plus the `availableAttackers` and `strengthOf` queries) and take a `player`. `priority` puts a building first in the fair demand ordering and in builders' choice. `demolish` aborts every job referencing the building (goods in hands go back to storage), turns its worker back into a carrier, clears the tiles (with `markWalkable`) and lets the renderer drop the views on the next sync.
- **Surplus hauling:** producers' surplus goes to the nearest warehouse unless the player already stores `RESOURCE_INFO[res].storeLimit` units (only water has one); then goods wait at the producer, its full pile pauses it, and carriers stay free. Resource names, stock-panel groups and limits live in `RESOURCE_INFO`; the HUD draws resource icons with the ware painters (`wareIcon`), so a new resource needs no UI changes.
- Nature rates are expressed per 64×64 of map and scaled by area (`scaled()` in `nature.ts`), so a bigger map is not a slower world. Fields (grain; the mechanism is per kind, ready for other races' crops) are `map.crop` (stage) + `map.cropKind` (`CROP_KINDS` index), listed in `World.fields` (derived, rebuilt on load, iterated in sorted order to keep the RNG sequence identical after a load). Harvest rules (`GATHER_RULES`) decide what happens to the tile: grain is cleared (a perennial crop would drop back to an earlier stage instead).
- **Players:** `new World(seed, { players })` places one castle per player at `startPositions` (map center for one player — identical to the single-player map — otherwise on a circle); `generateMap` prepares the guaranteed start area (meadow, grove, quarry, coal/iron mountain, pond) around every start. Each player has its own castle (`castleOf`), settlers, dispatch round and territory.
- **Military** (`military.ts`): fighters are the professions with a `combat` def (`FIGHTERS`, `isFighter`; `soldier` = swordsman, `archer` with `combat.ranged`), each carrying a `level` (index into the profession's `combat.levels` — Settlers 4's hp and damage per level, read through `fighterLevel`/`hpOf`/`maxHp`, clamped to the last, so the one-level squad leader is always level 1 — and into `SOLDIER_LEVELS` for the `cost` in `LEVEL_RES` (gold) paid at recruitment; a recruit pays only for a level his profession has; levels never change afterwards — no promotion). Buildings with `def.garrison` hold them (`Building.garrison` ids; `garrisonInbound`/`garrisonArchersInbound` reservations released by `releaseJoin` from `abort` on `join`). The `GarrisonDef` is the whole defence rule set: `capacity`, `keep` (never given away — neither to man other buildings nor to attack; default `GARRISON_KEEP`; `spareSoldiers` respects it), `archers` (slots for ranged fighters; the other `capacity − archers` are for melee ones — slots have a kind, as in Settlers 4: `slotsFree(w, b, archer)` counts members and inbound of that kind, and staffing, `joinTick`, `soldierIdle` and the barracks respect it). As in S4 there is no defence bonus for the building itself (the door guard's extra damage is 0 in S4): defenders are stronger only by their defence strength at home (`fieldFactor`) and by the tower archers' bonus. Only fighters with `combat.captures` (swordsmen) conquer an emptied building; an archer's `assault` ends there and he looks for a garrison. `staffGarrisons` (called from the dispatcher) first gives every empty outpost one fighter from the nearest donor, then fills outposts from reserves and from outposts further from the enemy (rear → front only); it never creates fighters. **New fighters come only from a barracks** (`def.barracks: { ticks }`, worker profession `recruit`): `demand` brings it weapons (`weaponsWanted`, any fighter's tool up to `INPUT_CAP`); while `wantsRecruit` holds (a weapon in its pile whose fighters find a free slot of their kind, ≥ `BARRACKS_MIN_IDLE` idle carriers, more free garrison room than recruits in training — `armyRoom`) the dispatcher's ordinary worker request turns a carrier into the recruit; `updateBarracks` trains him for `ticks`, then (once a slot of some weapon's kind is free) he takes the weapon the player's army is shortest of among those, pays the gold of the level the player ordered (`World.setRecruitLevel`/`recruitLevel`, `Player.recruitLevel`, saved; falling back to the highest level the pile pays for; `goldWanted` makes `demand` bring two recruits' worth) and leaves as that fighter, homeless (`soldierIdle` sends him to the nearest garrison with a slot of his kind), counted in `stats.trained`. Weapons come from the weaponsmith's `outputChoice`; `waitingFor` counts empty garrison slots per weapon. **Weapon shares:** `OUTPUT_SHARES` (data: default weights, e.g. sword 60 / bow 40) marks share-controlled outputs; `World.setShare(res, weight, player)` / `shareOf` hold each player's weights (`Player.shares`, saved). `chooseOutput` first checks that something is awaited at all, then, when every choice is share-controlled, makes the one furthest below its share (`mostBehindShare`: holdings = units available plus fighters carrying it); the barracks picks the weapon the same way (holdings = fighters). `attack()` sends spares within `ATTACK_RANGE`, alternating melee and ranged; the attacker's `assault` task calls out one defender at a time (swordsmen first; `opponent` links both; defenders stand and fight in `updateSettler`). **Blows** (`combat.ts`, Settlers 4's rules, sources in `docs/TIMINGS.md`): every attack lands — no hit chance — for `hitDamage` = the level's `damage` × `fieldFactor` (rounded, ≥ 1), plus the squad leader's share (`moraleOf` − 1, its fraction rounded up with that probability via the world RNG), minus the target's `combat.armor` (≥ 1). In a duel both fighters strike independently every `combat.every` ticks (`s4Ticks` of S4's cadence, fractional; `Settler.reload` counts down and `rearm` carries the remainder): one side's task drives it (`duelTick` from `assault`, `engage`, `chase`), `startDuel` gives each a random phase, and when both are due on one tick a coin (world RNG) picks who strikes first — a fighter killed by that blow does not strike back; an archer in a duel shoots point-blank at his own damage and cadence. Ranged damage (`shoot`, same rules) is applied instantly: attacking archers shoot defenders busy duelling within `ranged.range`, garrison archers shoot assailants approaching their building (`assaultsByTarget`, built once per tick) with `ranged.tower` extra damage, `ranged.towerDoor` at an enemy at the door; `World.shots` is a visual-only list (not saved, pruned after `SHOT_TICKS`). **Infirmary** (`def.infirmary: { beds, healEvery, range }`): every `WOUNDED_CHECK_EVERY` ticks, while not under assault, `updateGarrison` sends fighters below `WOUNDED_AT` of their hp (keeping at least one and `keep`) to the nearest own infirmary in range with a free bed (`patients`, derived from `heal` tasks once per tick); the `heal` task lies inside (`s.inside`) and regains a hit point every `healEvery` ticks, then the fighter looks for a garrison. Nobody heals elsewhere. **Lookout tower:** `def.vision` (sight radius, no garrison or land); `fog.ts` rebuilds vision also when the number of finished `vision` buildings changes (`lookouts`). **Teams:** `WorldOptions.teams` (per player index) → `Player.team`; `World.allied(a, b)` gates `attackable`, `distancesToEnemy`, foreign land at conquest, `outcome` (allies win together) and the AI (`knownEnemies`, foreign land in sight); `?teams=1,1,2,2`, `sim:ai --teams=`. An empty enemy building is conquered: owner flips, territory is recomputed, and enemy non-military buildings on foreign land are removed via `World.removeBuilding`.
- **Direct army control** (`field.ts`, `FIELD` in `config.ts`, as in Settlers 3/4): a fighter with `Settler.post` (`FieldPost`: a tile, optionally `leader` + offset `dx`/`dy`) is a **field unit** — `soldierIdle` hands him to `fieldIdle` instead of looking for a garrison; armies are counted without field units (`armyRoom`) and `enterGarrison` clears the post. Player commands on `World` (the AI may use them too, with its own id): `releaseFighters(b, n)` (spares above `keepOf`, swordsmen first, to spots below the door), `orderMove(ids, x, y)` (a formation from `formationSpots`: a walkable, door-free spiral; the leader in the centre, then swordsmen, then archers; with a leader in the order, the others' posts follow him by offset — `postOf`), `orderHold`, `orderAttack(ids, building)` (post at the target's door, then `goto` + `assault` as in `attack`), `orderGarrison(ids, building | null)`. Every `FIELD.scanEvery` ticks an idle field unit looks for the nearest hostile outdoor fighter within `engageRadius` of himself and `chaseLimit` of his post (`outdoorFighters`, cached per tick); archers `shoot` it from range, melee fighters run the `engage` task (closes in with an inserted `goto` until side by side, diagonals included, links `opponent`; when both engage each other only the lower id's task drives the duel, an assailant called out stands like a defender) and duel by the same `duelTick`. Garrison archers also shoot field units near their building (`fieldUnitsNear`). **Squad leader** (`leader`, `combat.leads: { radius, morale }`): `moraleOf` multiplies the damage (`hitDamage`) of own fighters within `radius` of a living leader (`leaders`, cached per tick; not the leader himself; S4 gives the bonus to his control group — the radius is our stand-in); the barracks makes him from his `tool` (armour, the weaponsmith's third `OUTPUT_SHARES` output) plus `kit` (extra goods a recruit needs, here a sword: `kitReady`, spent in `updateBarracks`); he `captures`. Field state is plain data on the settler (saved). **Control groups and donkeys (UI):** `GameState.groups[1..9]` (not saved) — Ctrl/⌘+digit stores the selection, a digit recalls it (dead/lost ids drop out; a second press within `DOUBLE_TAP_MS` centres the camera); a digit picks a build-menu building only when no group is stored under it. Group numbers are drawn as pooled `Text` badges over selected units (`markUnits`). Selected fighters (units or the single `selectedSettler`) and wounded fighters in a fight (`inFight`, collected in `syncSettlers`) get `healthBar` over their heads: hp / `maxHp` between corner brackets, green → yellow → red, level pips above, placed at `rankY`. Pack donkeys (drawn by `AnimalLayer`) are pickable through `AnimalLayer.unitAt`/`unitsInRect`, which `settlerAt`/`settlersInRect` merge by depth; a donkey opens the settler window (route `load` → `unload`, load) or, several in a box with no fighters/specialists, the selection window; they take no orders (`LOOK_ONLY` in input.ts).
- **Computer players** (`ai.ts`, `World.ai`, enabled per player with `new World(seed, { ai: [ids] })`): the hard rules are (1) act only through the public player commands with the AI's own player id — never mutate world state directly or call internal helpers that do; (2) see only what that player could see — ore counts only where its own geologists prospected; enemy buildings exist for it only once their door tile is explored (`knownEnemies`), their garrison is counted only while in its buildings' sight (`inBuildingSight`), else guessed as `AI.unseenGarrison` × capacity; resources beyond its border count only on explored tiles. It reads only fog state that survives a load (explored bits, building sight — never `isVisible`, whose settler part is not saved); `World.step` calls `ensureVision` first so a loaded game rebuilds sight before the AI thinks. While it knows no enemy building it scouts: towers lean towards foreign land in sight, else (`Context.scoutingStarts`) towards the other start positions it has not explored — `startPositions` follows from the map size and player count, public like the map size — in a line (score `fromCastle·0.3 − distance`), and frontier outposts stop at `AI.maxScoutOutposts` until an enemy is known. **Room for the military:** workshops and houses keep off a band of own tiles within `AI.borderReserve` steps of the border (`Context.band`; a preference — a workshop with no other spot may take it, houses and eyecatchers may not); a plan building that finds no spot sets `crampedUntil` (`AI.crampedTicks`): while cramped it pushes the border with any fighter it can spare (no `frontierSoldiers` wait), builds no eyecatchers, and for buildings in `AI.makeRoomFor` (barracks, smelters, smiths) `makeRoom` demolishes an eyecatcher or a second workshop of a type at least as large (one per `RETRY_TICKS`, the victim's type held back for a while). **Specialists** (`useSpecialists`, every `AI.specialistEvery` ticks): with `AI.pioneerShovels` shovels it orders a pioneer and sends him to the claimable spot around its military buildings with the most explored unclaimed resources (leaning to unexplored starts); with `AI.thiefIdle` idle carriers it orders a thief and sends him at a known, robbable enemy store within `AI.thiefRange`. Its attack estimate sums its party's `duelWorth` (hp × damage per tick at its attack strength, in level-1-swordsman units — what one-on-one duels trade) against one unit per defender (their make-up and strength it cannot see), and it attacks at most every `AI.attackCooldown` ticks — `AI.followUpCooldown` after an attack that took its target (`AiState.lastTarget`). **Assault tactics:** the target is the best-scored known enemy military building it outnumbers — the castle first, then by depth towards that enemy's castle (`AI.depthWeight` per tile to its `siegeGoals` point), minus `AI.reinforceWeight` per other known building of that enemy within `ATTACK_RANGE`; the party is `partySize` (what the target takes × `AI.overkill`, at least `AI.minAttackers`; everything at a castle), so the rest stay in their garrisons and defend. **Siege** (`siege`, before the plan each think): `siegeGoals` gives each enemy it knows a goal — its castle once explored, else the presumed castle: the start position nearest the enemy's known buildings (start positions are public) — and while it knows no enemy building at all the siege aims at the nearest unexplored start (`unexploredStarts`), since its scouting towers may stop at their cap before ever seeing foreign land; and while fewer than `AI.siegeBuildings` of its military buildings stand within `ATTACK_RANGE` of a seen castle (always, for an unseen one) it places, ignoring enemies in reach and up to `AI.maxMilitary + AI.siegeExtra`, first (unseen castle) a lookout within `land + 3` of the goal (`land` = how close its land already comes; only if none of its lookouts already stands within `land + AI.siegeLookoutSlack` — one per edge; siege scoring comes before the plain lookout score in `Context.score`, so a siege lookout never lands elsewhere), then the largest military building it can pay for and man within `ATTACK_RANGE − AI.siegeMargin` of a seen castle, or anywhere its land would reach `AI.siegeStep` closer (`Context.siege`, scored in `score`). Attacks still need the target's door explored (fog rule). A mine it cannot place sets `wantOre` (towers weigh mountains more, a geologist goes to the nearest unprospected own mountain); gatherers of `AI.exhaustible` resources (stone) with nothing left in range are demolished so the plan rebuilds them elsewhere; no new outposts while a known enemy military building is within `ATTACK_RANGE` (soldiers are kept for the attack); it sets its weapon shares (`AI.weaponShares`) and recruit level (`AI.recruitLevel`) once through `setShare`/`setRecruitLevel`, attacks only with a capturing fighter in the party, scouts with lookout towers (`LOOKOUTS`, up to `AI.maxLookouts`: while it knows no enemy building but sees foreign land — `Context.scoutingBorder` — it places them as close to that land as possible, since its towers stop at the other's border too far to see a castle), and keeps `AI.reserve` of a material nothing of its own produces any more (stone with worked-out deposits: only producers of it may spend the reserve, border-pushing military buildings down to `AI.reserveFloor`, towers weigh deposits ×4 and the frontier takes the cheapest in it); (3) be deterministic and keep all state in the plain-data, saved `AiState` (no RNG of its own, ties broken by tile index); (4) bounded cost — think every `AI.thinkEvery` ticks, score only own territory tiles with cheap checks (`fits`) and spend `canPlace` on the best `AI.placeTries` spots, back off `RETRY_TICKS` after a failed search (`blockedUntil`). **Field orders** (`aiField.ts`): with `AI.stageStrike` (off by default: it cost decisive games on 128×128 4-player maps) an attack's party (`attackerComposition`) leaves its garrisons through `releaseFighters` (ids found by diffing the garrison lists; a squad leader comes along when he is among a source building's spares — `leaderCount` mirrors `releaseFighters`' order), gathers with `orderMove` on the line from the target's door back towards its buildings — on the first own tile at least `AI.stageDistance` from the door, else at that distance (out on enemy land the defender would meet it at home strength) — (`AiState.strike`) and, once `AI.stageArrived` of it stands at its posts or after `AI.stageTimeout`, goes in with `orderAttack`; a party starting closer than `stageDistance + stageMinWalk` (or with no room to form) attacks straight from its buildings (`World.attack`, the fallback). `defend` (with `AI.fieldDefense`) meets hostile field units (`post` set) on its land (or within `AI.defendMargin` of it) and in its buildings' sight with `⌈n × AI.defendRatio⌉` spares from military buildings within `AI.defendRange` — only if its spares at least match them, else it stays behind its walls (`AiState.defense`) — and sends them back with `orderGarrison(null)` when none are left; `sweep` sends any other idle own field unit back. **Markets** (`tradeCheck`, `placeTrade`, every `AI.tradeEvery` ticks): `Context.fits` places buildings only on pieces of land with a finished warehouse or a served market (the destination of one of its routes); a cut-off site still empty at two checks is demolished; the first cut-off piece with a workplace (or a site with materials) becomes `AiState.trade.anchor` and gets a home market, a donkey ranch (`breeds`) and a market on that piece (`Context.onPiece`); then `orderTrade` sends what the piece's sites and workplaces lack (`TRADE_INPUTS` per input, minus orders, donkey loads on the way and the far market's pile), and the far market sends home, `ENDLESS`, what the piece makes and does not use. Behaviour is data: `AI_PLAN` (ordered build targets with `after` prerequisites) and the `AI` tuning table (houses by idle + still-to-come carriers, tool reserve `keepTools` so the first building of a type keeps the last tool — this prevents the coal-mine/pickaxe deadlock, manning discipline `homeGuard` (counting spares in every military building plus weapons in stock), frontier outposts towards the nearest enemy once it has `frontierSoldiers` — the largest garrison type it can afford and man —, attack after `peaceTicks` when the worth of the party `attackerComposition` would send beats `attackRatio` × defenders + 1).
- **Victory/defeat:** losing one's castle (conquest in `military.ts`) calls `World.defeatPlayer`: the player goes to `World.defeated` (saved), its settlers die via `killSettler`, its buildings are removed and territory recomputed; its AI stops thinking. `World.outcome(player)` is `'won'` once every other player is defeated. The HUD shows the end screen once `outcome(LOCAL_PLAYER)` leaves `'playing'`. Note `castleOf(p)` of a defeated player returns the conqueror's building.
- **Fog of war** (`fog.ts`, per player): `map.explored` is the saved bitmask of what each player has ever seen; current sight is derived (`World.fog`, never saved): `vision` (bit per player) from buildings — finished ones see `territory + FOG.territoryMargin` (or `FOG.buildingRadius`), sites `FOG.buildingRadius` — rebuilt only when `World.buildingsVersion` (bumped in `addBuilding`/`removeBuilding`) or `territoryVersion` changed, plus per-player `seenUntil` ticks that outdoor settlers stamp around themselves every `FOG.settlerEvery` ticks. Cost: O(settlers × disc) every few ticks plus O(map) per building change. Query with `World.isExplored` / `isVisible`; `inBuildingSight` is the building part alone (what the AI may use). **Allies share sight:** all three test the player's `sightMask` — its own bit and its allies' (derived from the saved teams, cached per `players` array and reset by `resetSightMasks` after teams are set) — so a player sees what its team's buildings and settlers see and knows what its team explored; the renderer, minimap and AI need nothing else, and nothing new is saved.
- **Removing settlers:** only through `killSettler`: it aborts the settler's jobs, frees its opponent, and clears every reference (`garrison`, `workerId`, `builderIds`/`diggerIds`). The settler stays in `World.settlers` (skipped by `step`) until `removeDead` at the end of the tick, so loops never splice under iteration. A new field that references settlers must be cleared there too.
- **Territory:** `map.owner` holds the owning player per tile. `recomputeTerritory()` rebuilds it from scratch out of buildings that `claimsTerritory` (worker-less ones once done, workplaces once staffed, military buildings while garrisoned or always for the castle); where claims overlap the nearest claiming building wins (ties: the earlier one) and bumps `territoryVersion`, which the renderer polls to redraw the dimming and border. `canPlace` requires the footprint and door to be owned; `isGatherTarget` and `canPlant` only accept owned tiles, so gatherers and foresters never work outside the border.
- `addBuilding` moves any outdoor settler standing on the new footprint to the door tile, so nobody is walled in by a site placed on top of them.
- Building costs are multi-resource (`cost: Partial<Stock>`); always read them through `costOf()` / `totalCost()`. Construction takes one work shift (`BUILD_TICKS_PER_UNIT`, one builder's work) per delivered unit of any material; several builders shorten it.
- **Save/load** (`save.ts`): `saveWorld` snapshots everything to plain JSON (map layers as base64, `Rng.state`, buildings in id order); `World.load` restores it, and `tests/save.test.ts` asserts a loaded world continues bit-for-bit like the original. When you add simulation state, add it to `SaveData` and bump `SAVE_VERSION` if old saves can no longer load. Keep sim state plain data (no closures, class instances or functions) so it stays serializable.
- **Wild animals** (`animals.ts`, `ANIMALS` in `config.ts`: habitat `meadow`/`forest`/`shore`, speed, herd size, `herds` per 64×64 scaled by area, `roam`, `rest`): owner-less plain data in `World.animals` (saved with `nextAnimalId` and `animalRng`), spawned by `spawnAnimals` at generation away from every start (`ANIMAL_START_CLEARANCE`) and off owned land. `updateAnimals` runs every tick: resting is a counter, walking a straight leg towards a habitable spot within `roam` of the herd's home (`habitable`: forest = grass near trees, shore = water next to land or land next to water; habitat is re-checked only on entering another tile, and an animal whose tile became unfit walks out). Animals occupy no tiles and block nothing. All their randomness comes from `World.animalRng`, a stream of their own, so they never shift the economy (a test plays a world with and without animals identically). The hunter (`hunting.ts`) takes deer (`AnimalDef.game`) from this list.
- **Economy settings** (`economy.ts`, `Player.economy`, saved, Settlers 4's settlers and production menus): `orders` — builders and diggers (`ORDERABLE`) are recruited by the dispatcher only up to the ordered totals (`World.orderWorkers`; defaults = the start level's), counted by `workersOf` once per tick (a derived per-world cache, recounted after a recruitment); `toolOrders` — the toolsmith queue (`World.orderTool`, a count or `ENDLESS`); `distribution` — per good, weights per consumer type (`consumersOf` derives the types from recipes; `World.setDistribution`); the demand loop then serves the type with the lowest units-handed-out / weight first (`distributionKey` over `tally`), weight 0 gets none, and goods without an entry keep the fair least-stocked order. Warehouses refuse goods listed in `Building.refuse` (`World.setAccepts`; the window shows «Принимает»/«Не принимает» lists of big icons, a click moves a good across — `ui/goodsLists.ts`, shared with the market window so both always look and behave the same); `nearestStorage(…, res)` skips them for surplus and returns; `setAccepts(…, false)` calls `redirectDeliveries`, which turns carriers already bringing that good there (their `drop`, its `inbound` and the `goto` before it) to the nearest accepting warehouse on the same land piece, or lets them finish when there is none — never through `abort`, whose failed return trip would lose the good. The AI sets nothing here except through these commands. **Start levels:** `START_CONDITIONS` (`low`/`medium`/`high`: goods, carriers, builders, diggers, soldiers; `new World(seed, { start })`, `?start=` in the browser). **House size** is Settlers 4's 10/20/50 on every map (`residence.capacity`); read it through `residentsOf(def)` / `residents(w, b)` (`buildings.ts`). **Hunter** (`hunting.ts`, behavior `hunt`, `HuntDef`): stalks the nearest unclaimed `AnimalDef.game` animal within `radius` of the lodge (reserved via `Animal.hunter`, released by `abort`), closes in up to `chases` times, shoots from `range`, removes the animal and carries the game home; game kinds with `respawnEvery` grow back towards their initial stock (`stockOf`). **Paths** (`paths.ts`, `PATHS`): every step a settler completes onto a tile (`move`) adds wear in `map.wear` (saved layer) on `PATHS.terrains`; from `levels[k].wear` it is a dusty path, then a road, walked `speed` times faster (Settlers 4's 9/8 and 9/7) by professions with `roads` — carriers and donkeys only, as in S4 (`pathSpeed`, applied in `move`; A* ignores it); every `decayEvery` ticks each tile in `World.worn` (derived, rebuilt on load) loses `decay`. Level changes `touch` the tile; the renderer draws `path:<level>:<variant>` ground decals under the fields (`syncPath`).
- **Specialists** (`specialists.ts`, `PIONEER`, `THIEF`, `INTRUDERS`): pioneers (shovel) and thieves are `ORDERABLE` like builders and diggers (`World.orderSpecialist` = the same orders), recruited by the dispatcher, then sent with `World.sendPioneer(x, y)` / `sendThief(buildingId)`; the errand lives in `Settler.errand` (saved) and the idle behaviours `pioneer`/`thief` turn it into tasks. A pioneer claims `claimable` tiles (neutral, passable, 4-adjacent to his owner's land) within `PIONEER.radius` of the spot, nearest first, one per `claim` task; a claim writes `map.claimed` (saved layer) and `map.owner` at once and bumps `territoryVersion` (`World.pioneerLand` counts claims, derived, so `recomputeTerritory` can skip the pass). `recomputeTerritory` gives claimed tiles to their claimant wherever no military building claims them — military land always wins, and the claim returns when that building goes; defeated players' claims are cleared there. A thief may rob a done, explored building of a non-allied player that has goods (`robbable`); the `steal` task takes one unit of the most plentiful unreserved good and he carries it to his nearest warehouse (an ordinary `drop`, so `abort` releases it), then goes back while there is loot. **Intruders** (`intruders.ts`, `INTRUDERS`, Settlers 4): every `scanEvery` ticks each specialist (`SPECIALIST_KINDS`) outdoors on land of a non-allied player is that player's intruder (`intruders`, cached per tick); a `cloaked` profession (the thief) is no target until an outdoor fighter of that player or a garrisoned building of his has its door within `decloakRadius` (`Settler.exposedUntil`, saved, `exposedTicks`); for each exposed intruder chased by fewer than `responders`, the nearest own military building with its door within `respondRadius` sends a spare melee fighter (above `keepOf`; `leaveGarrison`) on a `chase` task, field melee units take intruders in `engageRadius` themselves after enemy fighters, field archers shoot them (`nearestIntruder`). `chase`: walks up (inserted `goto`), within `seizeRadius` pins the intruder (`e.opponent`; he stands), adjacent links both and strikes at his own cadence with ordinary blows (`duelTick` with `strikesBack` false) — specialists never strike back; his load is lost (`killSettler` counts whatever a dying settler carried in `stats.lost`), `stats.intrudersKilled`; it ends when he is dead, indoors, cloaked again or off the fighter's owner's land, then the fighter is homeless and finds a garrison (`soldierIdle`). `abort` releases the pin; `updateSettler` drops an opponent that died. Specialists' `hp` is in `PROFESSIONS` (thief 20 as in S4; geologist and pioneer 20, approximation); geologists get it in `geologistErrand`, recruits on `retool`. `World.dismissSpecialist(kind)` turns an idle one on own land back into a carrier, bringing the tool back, and lowers the order. **Direct control of specialists** (as fighters, S4): `SPECIALIST_KINDS` (geologist, pioneer, thief) are selectable on the map; `World.orderSpecialists(ids, x, y, targetId)` gives each the action of its kind from `SPECIALIST_ORDERS` (`label` for the cursor hint, `can`, `apply`: geologist — `geologistErrand` on an own mountain, fetching the hammer only if he has none in hand; pioneer — `errand` at a claimable spot; thief — `errand` at a `robbable` building) where `can` holds, else a `Settler.post` (spread with `formationSpots`) where `specialistPostIdle` keeps him waiting (checked first in the `pioneer`/`thief`/`prospect` idle behaviours, so a geologist with a post does not turn back into a carrier). `holdSpecialists` posts them where they stand, `dismissUnits` turns those on own land back into carriers (`toCarrier`). `clearSpecialist` drops errand, post and tasks via `abort`, keeping the specialist's own tool in hand.
- **Land pieces, donkeys and markets** (`land.ts`, `trade.ts`, `TRADE`, Settlers 4 logistics): carriers carry only on their player's own land. `World.land` gives every owned tile the id of its piece (8-connected tiles of one owner), derived, rebuilt lazily by `ensureLand` whenever `territoryVersion` moved (also after pioneer claims), never saved; `landAt`/`landOf` (a building's piece = the piece at its door), `isCutOff` (no finished warehouse on the piece; cached per `buildingsVersion`, which a finished warehouse bumps). `dispatchFor` hands a job only when source, destination and carrier share a piece (idle carriers counted per piece, a piece without any skipped before searching, a piece with no supply drops all its consumers at once — with one piece this is the old behaviour); `nearestSupply`/`nearestStorage(…, piece)` filter by piece; a piece with work but no free carrier gets one from another piece (`relocate`: a plain `goto`; settlers walk anywhere; idle crowds prefer anchors on their own piece). A* itself is not restricted to own land. Donkeys are settlers with behavior `donkey`, bred by a building with `breeds` (the ranch's recipe releases one per cycle, started only while `wantsDonkeys`: fewer than markets × `donkeysPerMarket`). A market (`def.market`) has `Building.trade = { to, orders, loading }` (saved; `World.setTradeRoute`, `World.orderTrade` with a count, `ENDLESS` or 0 — cancelling aborts carriers' `drop`s of that good already on their way (their load goes back to a warehouse) and moves waiting input to the output pile; a carrier's `drop` at a finished market without an order for the good (`marketOrdered`, checked by `wantedAt` in settlers.ts) lands on the output pile, never in the input, so nothing sits there with no donkey to take it); `marketWants` (part of `demand`) brings ordered goods up to `TRADE.stock`; `dispatchTrade` (after `dispatchFor`, per player) sends the nearest idle donkey with `goto`/`load`/`goto`/`unload` for a full load (`donkeyLoad`, or the order's rest, or what there is while nothing more is inbound), reserving `loading` (released by `releaseLoad` from `abort`); `load` takes up to n from the input and counts the order down, the donkey carries `carrying` × `Settler.load`, `unload` puts it on the destination market's output, where that piece's carriers take over. A route may also lead to a market site (`routeTarget`): unloading there first counts what the site still lacks as delivered (`unloadTick`), so a market on a cut-off piece can be built at all (the building window still lists only finished markets as destinations). A donkey whose trip fails goes to the nearest own market with its load (`donkeyAbort`; none left → `stats.lost`). Rendering: `UNIT_ANIMALS` (animalArt.ts) maps settler kinds drawn as animals; `AnimalLayer.syncUnit` draws them from the animal sheets with the `pack` saddle and the carried ware, called from `syncSettlers` instead of a figure. Local buildings on a piece without a warehouse get the `cutoff` marker over the roof; `ui/tradeView.ts` adds the market's route and the ranch's herd to the building window (markets are named «Рынок №k» by `marketName`: k-th of the owner's markets by building id; destinations show the door-to-door distance in tiles); `render/tradeRoutes.ts` (`TradeRouteLayer`, one `Graphics` after the work-area overlay, under the objects) draws the local player's routes as terrain-following dashes with chevrons in the player's colour over a dark rim — bright for the selected market's route (either end), faint for the rest — redrawn only when routes or selection change; the goods go in two warehouse-style lists (carried / not carried, a click moves a good across and orders `ENDLESS`; a finite AI order shows its remainder in the item's corner).
- **Fighting strength** (`strength.ts`, `STRENGTH`, after S4): settlement value = materials in a player's finished buildings (`points` per plank/log/stone, `goldPoints` per gold, × `eyecatcher` for `def.eyecatcher` buildings); attack strength starts at `start − perPlayer × (players − 1)` (≥ `min`) and climbs `steps` (diminishing returns) up to `max`; defence is 100 % until attack passes it, then half its pace. Cached per world per tick (derived, never saved). `fieldFactor` multiplies a fighter's damage (`hitDamage`, blows and shots alike): attack strength on land not his owner's or an ally's, defence strength at home. `World.strengthOf(player)` for the HUD. Eyecatchers are ordinary worker-less, territory-less buildings (`decor` category); the AI weighs its party at its attack strength (it assumes the enemy's defence at 100 %) and builds eyecatchers from spare materials (`AI.decorEvery`, `AI.decorSpare`).
- **Work areas** (`workArea.ts`, `WORK_AREA`, Settlers 4): a building's work radius comes from the data — its worker's `gather`/`plant`/`hunt` radius or `def.mine.radius` (`workRadius`); the centre is the door, a mine's footprint centre (`defaultWorkCentre`), or `Building.workAt` (saved with the building) once the owner moves it with `World.setWorkArea(id, point | null)` — within `WORK_AREA.maxShift` × radius of the door, mines not movable (`movableWorkArea`). Gather/plant/hunt target searches (`findGatherTarget`, `hasGatherTargetNear`, `plantingsNear`, `findPlotFor`, `findGame`) measure from `workCentre(b)`; never from `b.door` directly.
- Tunables (timings, caps, costs, start resources) live in `config.ts`. **Timings follow Settlers 4 in real seconds at 1×** (walking pace `SETTLER_SPEED`, `ProfessionDef.speed` for the riding squad leader, `BUILD_TICKS_PER_UNIT`, recipe ticks, gatherers' work/rest): the comparison table with sources and what is still unverified is `docs/TIMINGS.md` — keep it current when a timing changes.

### Rendering (`src/render`)
- Isometric projection is in `iso.ts`: tile center `(x, y)` maps to screen `((x-y)*32, (x+y)*16)`. Depth equals `x + y`. `objects` is a single `sortableChildren` container keyed by `zIndex`. Buildings use the depth of their footprint center plus 0.25, the door pile and flag use the door tile's depth minus 0.05, and settlers use their interpolated depth.
- **Terrain heights:** ground is one `MeshSimple` per chunk whose vertices are the tile corners raised by `map.height` (shared corners, so no seams), textured from the ground sprites in the atlas (they must all sit on one atlas page, which the builder asserts). **Transitions:** after each tile's own quad come overlay quads of its higher-priority neighbours (`GROUND_PRIORITY`: water < ford < swamp < sand < desert < grass < mountain < rock), using `edge:<kind>:<dir>` sprites (`paintGroundEdge`: the neighbour's ground faded in from that edge/corner with a ragged border, `EDGE_DIRS`); corner overlays are skipped where an edge neighbour of the same kind already covers them. Each chunk also gets a `Graphics` with slope shading lit from the top-left (`slopeLight`, quantised levels). Everything standing on the ground is placed with `surface(x, y)` (screen point minus `heightAt`), outlines (territory, hover, ghost, selection, geologist area) use `corner()` per tile corner, chunk culling bounds are lifted by the chunk's highest corner, and `pickTile` refines the flat inverse projection a few times by the height under the guess. Never place a world object with plain `toScreen` any more. **Runtime height changes:** `syncHeights` (throttled) rebuilds the ground (`buildChunkGround`), territory overlay and culling bounds of chunks whose `heightVersion` changed and re-seats their static objects (`addStatic` records each object's tile and offset from the surface) and field decals.
- `GameRenderer.sync()` reconciles by **polling sim state every frame** (view maps keyed by building and settler id; trees/deposits only in chunks whose `chunkVersion` changed; territory only in chunks whose owners changed). The sim emits no events, so new sim state only needs a matching branch in `sync*`.
- **Culling by chunk** (`CHUNK` = 16 tiles): ground, territory overlay and static objects (trees, rocks, deposits, buildings) are registered per chunk via `addStatic`/`removeStatic` and sit in the scene only while their chunk intersects the camera's `viewRect`; settlers join `objects` only while on screen. Per-frame sorting and drawing therefore follow the screen, not the map. New world objects must go through `addStatic` rather than `objects.addChild`.
- **Chunk unloading** (what makes 1024×1024 hold): `unloadHiddenChunks` (twice a second) gives back the render data of built chunks out of view for `UNLOAD_AFTER_MS` — or of any hidden ones while more than `MAX_READY_CHUNKS` are built — down to `KEEP_CHUNKS`: ground layer, boulders (`boulders[c]`), trees, deposits, signs, field and path decals (their per-tile states reset so `syncChangedTiles` recreates them; `chunkSeen[c] = −1`), the territory `Graphics` (replaced by a fresh one, `territoryPending`), the fog mesh/texture/canvas and the water glints (`Effects.unloadChunk`); `chunkReady[c] = 0` and `ensureChunk` rebuilds on sight. Buildings and settlers stay. **Pixi frees less than it seems:** `mesh.destroy()` keeps the geometry and its GPU buffers, `graphics.destroy({ children: true })` keeps the drawing context — free them with `disposeMesh` (geometry `destroy(true)`) and `disposeLayer` (`destroy({ context: true })`). Anything per-chunk you add must be released in `unloadChunk` too.
- **Lazy chunks** (what makes 512×512 start fast): `buildGround` only records heights; a chunk's ground mesh, boulders and territory are built by `ensureChunk` the first time it becomes visible (`chunkReady`), at most `CHUNK_BUILDS_PER_FRAME` per frame so a zoom-out never hitches. Tile objects (trees, deposits, fields) are synced only for visible chunks — `syncChangedTiles` leaves a hidden chunk's version stale and catches up when it scrolls in; territory for unbuilt chunks is deferred via `territoryPending`. Anything per-chunk you add must be built in `ensureChunk` and tolerate a chunk that was never built.
- **Classic art** (`?art=classic`, and the fallback for anything without a 3D image): procedural painters in `sprites.ts` draw with Canvas 2D, and `SpriteAtlas` (`atlas.ts`) packs them into 2× resolution canvas pages (a new page starts when one fills; the last page is cut to the rows it uses) with `defaultAnchor` set per frame. Most buildings are described by a `Style` in `STYLES` (walls, roof, floors, decorations like chimney/well/pen) painted by `paintStyled`; only special shapes (castle, mill, tower…) have hand-written painters. Fields are flat decals added to their chunk's ground container. Building painters draw around the **footprint center as origin** and use the `P(dx, dy, z)` helper (tile-unit offsets plus pixel height); their canvas size and anchor live in `BUILDING_CANVAS`. Construction progress is shown by cropping the building texture from the top (`bottomPart`). To add a sprite, write a painter and register it in the `SpriteAtlas` constructor.
- **3D art** (the default; `?art=classic` keeps the procedural painters above): `art/blender/build.py` (helpers in `lib.py`) builds models with bpy and renders them with an orthographic camera matching `iso.ts` (rot 60°/0/45°, world X = tile x, world Y = −tile y, `PX_PER_UNIT` logical px per tile unit, 2× resolution, Cycles, shadow catcher on a transparent background, palette written in sRGB and converted by `lib.lin`) into `public/art/3d`; run `npm run art:render [-- names]` (Blender 5.x on PATH). Each sprite keeps the size/anchor convention of the procedural sprite it replaces (`ART3D_SPRITES` in `art3d.ts` must match `SINGLE` in `build.py`). `main.ts` loads them (`loadArt3d`) and `SpriteAtlas` re-registers them under the procedural keys (every `building:<type>` and its stages, `tree:*`, `deposit:*`, `prop:*`, `ware:*`, `pile:*`, ground and decals), so the rest of the renderer is art-agnostic; **Settlers** (`art/blender/figures.py`, `npm run art:settlers`: renders on the CPU, ~15 min, caches each pose group in `art/.tmp/settlers-cache` so an interrupted run resumes, then `art/tools/quantize.py` (Pillow) turns the pages into 256-colour PNGs, ~6× smaller; one Blender at a time): one stocky figure on pivots (hips, shoulders, a tool grip per hand) posed per group — `hold:<tool>` (walk frames, then standing) for every `TOOLS` shape incl. `carry`, `work:<action>` (4 frames) for every `ACTIONS` entry; the tables at the top of figures.py mirror `animConfig.ts` (tool per action, arm angles). **Outfits:** a profession's `SettlerStyle.outfit` (`legion`, `archer`, `leader`; `OUTFITS` in figures.py lists each one's tools and actions) gets its own pose groups `hold:<tool>@<outfit>` / `work:<action>@<outfit>` with the outfit's parts shown (`build_outfits`: banded steel armour and a curved scutum, leather armour and quiver, gilded cuirass, round golden shield and cloak); civilians with the same tool (the hunter's bow) keep the plain groups. `settler3d.ts` resolves them with `holdFrames`/`workFrames(s3d, …, outfit)` (falling back to the plain group). Outfit groups are cached with `-r<LOOK_REV[outfit]>` in the name: bump `LOOK_REV` when an outfit's look changes. **Fighter levels** are shown by the helmet: `SettlerStyle.levelHats` (galea1/2/3: no crest, small crest, big crest) replaces `hatStyle` by `Settler.level`; the 3D path draws fighters' hats untinted (steel, gold) and hides the `chevrons` badge, which stays for `?art=classic`. Each frame renders twice: full colour, and a mask pass (material override with an emission of the object property `mask`: tunic, sleeves, shield face) that becomes the tintable copy; hats are a separate layer per `HAT_STYLES` style and direction (rendered with the body as a holdout). Frames are trimmed and shelf-packed into `settlers-<k>.png` pages; `settlers.json` has each frame's rect and anchor, the group tables, hats, `carryAt`/`carryBehind` and `rankY`. `settler3d.ts` turns it into textures once (`buildSettler3d`, `ImageSource` per page); `syncSettlers` then draws body = full frame, tunic sprite = tint frame (owner's colour for everyone in the 3D art, as in S4), hat = hat layer (profession colour), all 8 directions painted (no mirroring), swapping textures with `setFrame` (copies the anchor). A new profession needs no rendering unless it brings a new tool or action. Work groups have a third frame, the arm-over-hat layer (`render_over`: only arms and tools render, body/head and a hat-sized proxy are holdouts, rows below the neck cleared); the 3D path draws it in the `arm` sprite above the hat. Read hand positions from the evaluated depsgraph, and call `view_layer.update()` before parenting parts to pivots, or offsets double. The look follows Settlers 4 (reference: in-game shots at settlers4-hd.com, kept out of the repo): `mat_stones` (Voronoi fieldstone), `mat_tiles` (terracotta), `mat_grain` (wood, thatch, bark, earth), `mat_leaves`, `apply_ao` (base colour × AO in every material) and `clean_alpha` post-processing (saturation, contrast, unsharp); buildings stand on a trodden-earth `pad` (solid core, then a noisy alpha fringe from a per-vertex `edge` attribute plus two noises, so the earth breaks up into the game's grass instead of ending in a line); `transform_apply` must keep location (`location=False`), or origins jump to the world origin. **Animals** (`art/blender/animals.py`, `npm run art:animals`, CPU, 4 threads): one sheet per kind, `animal-<kind>.png`, 8 rows in `DIRS` order × `ANIMAL_COLUMNS` (walk 0..3, stand, graze), cells = `ANIMAL_CELLS` in `animalArt.ts`, quantised to 256 colours; loading is optional, a kind without a sheet uses the procedural painter (`paintAnimal`), which is also the default art. `AnimalLayer` (`render/animals.ts`) draws one sprite per animal among the objects, only on screen and (fog on) only where the local player has sight. Style notes from the original (and what we deliberately do not copy, e.g. outlines) live in `docs/ART-STYLE.md`; reference screenshots stay in the git-ignored `examples/`. Quarry stone is `lib.spire` columns with `mat_crystal`. Narrow water (land on two opposite sides, or little water around) gets pebbles along its non-swamp banks (`streamBanks`, render-only, in the chunk's ground layer). Animals are drawn at `ANIMAL_SCALE` per kind (animalArt.ts) to keep proportions with the scaled settlers. Building models other than the woodcutter (in build.py) live in `art/blender/buildings.py` (shared helpers such as `log_cabin`, `plank_roof`, `stakes`, `timber_frame` are reached through `__main__`, i.e. build.py), modelled after close-ups of the original buildings (git-ignored `examples/ref-<type>.png`), with `stone_course` (rugged blocks of mixed tones over a dark core), `quoins` (staggered corner stones), `coping_line` (wall-top stones), `plank_walls`, `panel_slope` (riveted plank panels) and `scale_roof` (rounded slate scales or square terracotta tiles), plus general roof pieces — `place_on` (orient an object by two axes), `tile_face` (scales/tiles over any quad or triangle roof face, kept inside its edges), `hip_roof`, `cone_tiles` —, `round_tower`, `stepped_gable_x/_y`, `rivet_vault` (riveted furnace), mine pieces (`rock_pad`, `hill`, `adit`, `rails`, `cart`) and `scale_scene` (the medium house is the old three-block house model scaled to 2×2 by parenting everything to a scaled empty); eyecatchers use the 1-tile `DECOR` canvas (80×120); `ART3D_BUILDINGS` in `art3d.ts` lists every 3D building with its canvas (= `BUILDING_CANVAS`, = `SINGLE` in build.py), and all of them have stages. Live-effect anchors of 3D buildings (chimney smoke, oven glow, the mill's sail hub) are recorded by `note_fx` while rendering and copied into `ART3D_FX`, which `Effects.anchorsOf` prefers to `buildingFxAnchors` in the 3D art. The 3D warehouse is an open paved yard (`ART3D_YARDS`): `syncYard` draws its stock on the platform — the `YARD_KINDS` most plentiful goods, one `pile:<res>:<n>` each, round the ring (pile sprites live in the building's `front` container, which chunk unloading keeps). A 3D military building records where its banner pole stands (`note_banner` prints it while rendering) in `ART3D_BANNERS`, which overrides `BANNERS` in the 3D art (tower, bigtower, fortress, castle; the lookout has no garrison and shows only the roof flag). Every building type is now 3D; the military/HQ models use `battlements` (merlons along chosen edges), `square_keep` (faced block with quoins), `slit`, `gate` and `scaffold` (stage-1 poles). The mill's sails in the 3D art are pre-rendered too: `buildings.render_mill_sails` (`npm run art:render -- millsails`) renders `MILL_SAIL_FRAMES` frames of a quarter turn on the mill's own canvas into the strip `millsails.png`; the atlas registers them as `sails3d:<k>` and `Effects` flips through them by the sails' angle instead of rotating the flat `fx:sails` sprite. 3D settler figures are rendered large for detail and drawn at `SETTLER_3D_SCALE` (art3d.ts) so they keep S4 proportions next to buildings (a settler about a third as tall as a small house); keep towers about 1.5–2× a house's height. HTML icons (`buildingIcon`, `wareIcon`, `settlerIcon` in `atlas.ts`) use the 3D images when loaded, cropped to their opaque bounds. **Ground textures** (`art/textures/ground.py`, `npm run art:ground`, runs in Blender for numpy): `KINDS` maps every ground kind to a generator and a period (grass 8 tiles, the rest 4 — every ground diamond plus the transition overlays must fit one atlas page); `ground.json` lists `kinds` with their periods, plus the `fields` decal strips (`fields-<crop>.png`, a 66×40 frame per growth stage, registered as `field:<crop>:<stage>`) and the `paths` strips (`path-<level>.png`, 80×44 frames, `path:<level>:<v>`), all generated here too. Trees and ground props come from `art/blender/nature.py` (`-- trees`, `-- props`): `tree:0..ART3D_TREES-1` (three conifers, three broadleaf; the renderer picks `hash % atlas.treeVariants`) and `prop:<k>` (`ART3D_PROPS`), which `scatterProps` places on about one grass tile in `PROP_EVERY` (by tile hash, skipping occupied tiles) inside the chunk's ground layer, so they are render-only, sit under everything standing and unload with the layer. Grass is combed tapered strokes along a slowly swaying direction field over band-limited broad swells of light and shade; a texture periodic over `PERIOD`×`PERIOD` tiles, sliced into diamonds exactly as `quadOf` samples them; the atlas registers them as `ground:<kind>:<v>` (`groundPeriod`), the renderer picks variant (x mod p) + p·(y mod p) so tiles join seamlessly, and transition overlays keep the procedural ragged mask filled with the texture. **Goods** (`art/blender/goods.py`): `GOODS` maps every resource, in `RESOURCES` order, to an item builder (one ware at ~0.3 tile, lying or standing around the origin) and a pile layout (`rows`, `layers`, `grid`, `spread`, `heap`, `bundle`: `PILE_MAX` placements, a pile of n uses the first n); it renders `piles-<res>.png` (strip of `PILE_MAX` frames of `PILE` size) and `wares.png` + `wares.json` (one carried ware per resource, centred, no shadow). They render on the CPU (tiny frames; keeps the GPU free). A new resource needs a `GOODS` entry.
- Player colours live in `PLAYER_COLORS` (`sprites.ts`); the only per-player atlas variants are `flag:<player>` (the occupied-building flag, set on the roof at `SpriteAtlas.topOf` — the highest drawn pixel in the middle half of the building sprite; hidden where a banner is) and `banner:<player>` (`paintBanner`: the owner's banner with an eagle on a crossbar over military buildings, at `BANNERS`) (fighters wear their owner's colour as a tint, see below). A fighter's level is drawn by his helmet (`levelHats`) and, under `?art=classic`, as a `chevrons:<level>` sprite above the head, and arrows (`World.shots`) as arcs in the `shots` Graphics layer above the objects. Territory chunks dim land that is not the local player's and draw every player's border as in Settlers 4: a post topped with a cube in the player's colour two per border edge, at ¼ and ¾ (`drawBorder`). Settler views whose settler died are destroyed on the next sync; building flags follow ownership changes, and so do roof banners (`BANNERS` in `sprites.ts`: where the `flag:<owner>` sprite sits on every military building — building painters must not paint owner colours themselves). Duelling pairs are drawn at `FIGHT_SPOTS` offsets so simultaneous fights at one door stay apart.

- **Fog rendering** (local player, off with `?fog=off`): a `fog` container above `objects` and the arrow layer holds, per chunk, a soft-edged mesh: a (CHUNK+2)² canvas with one pixel per tile (one-tile margin) whose alpha is the tile's darkness (unexplored 1, explored out of sight 0.42), stretched over the chunk's height-raised tile corners with linear filtering, so darkness fades across tiles as in Settlers 4. `syncFog` (every 150 ms) compares each visible chunk's states (margin included, `fogPrev`) and redraws the canvas only on change; the mesh is rebuilt when the chunk's heights change. It also hides static objects standing on unexplored tiles (and `addStatic` hides new ones there). Other players' settlers are drawn only where the local player has sight; the minimap and the building info panel follow the same rules, and buildings under unexplored fog cannot be selected.
- **Settler animation** (`anim.ts` pure helpers, `animConfig.ts` data, `settlerArt.ts` painters): a settler is a container of layered sprites — `body` (shadow, legs, far arm), `tunic` and `hat` (painted grey, tinted per profession from `styleOf(kind)` or with the owner's colour for `fighter` styles), `head`, the near `arm` with its tool, the carried `ware` and the rank badge. Five directions are painted (`PAINTED_DIR`: E, SE, S, NE, N); W, SW and NW mirror them (`MIRRORED`, `root.scale.x = -1`); facing away (`FACES_AWAY`) the arm and goods go behind the body. Direction comes from the tick velocity (`dirFromTileVelocity`), the opponent or the work target (`workTarget`); walk frames from the distance walked (`walkFrame`, no foot sliding), work frames from time with a per-id offset (`workFrame`), idle settlers glance around (`idleDir`). Atlas keys: `sb:<pd>:<frame>`, `st:<pd>`, `shd:<pd>`, `sht:<hat>:<pd>`, `sa:hold:<tool>:<pd>:<frame>`, `sa:work:<action>:<pd>:<frame>`; identical arm poses are painted once and aliased. Textures for each layer are resolved once (`SpriteAtlas.settlerTextures()`), so the per-frame loop does no string lookups. **To add a profession look:** a `STYLES` entry in `animConfig.ts` (tunic, hat colour and `HatStyle`, `work` action, held tool). **To add a work animation:** an `ACTIONS` entry (tool, four arm angles in turns of π, loop length, optional sound on a frame) — the atlas paints it automatically; map tasks to it in `PLANT_ACTION`/`GATHER_ACTION` if it depends on what is gathered or planted. A new tool shape needs a case in `paintArm`.
- **Live effects** (`effects.ts`, painters in `fxArt.ts`): one `Effects` instance owns `fxLayer` (smoke, dust, leaves, sparks, hit flashes; above `objects`/arrows, under the fog) and `waterLayer` (sun glints, right above the ground meshes; a separate layer, the ground meshes are untouched). Particles are a fixed pool of `MAX_PARTICLES` sprites with typed-array state, recycled round-robin — nothing is allocated per frame. Building effects are data (`BUILDING_FX` in `animConfig.ts`: smoke always/while working, fire glow, mill sails, ambient sound) placed at anchors the building painters export (`buildingFxAnchors`, `MILL_HUB` in `sprites.ts`); glows and sails are children of the building's body container, so they cull with it. A workshop counts as working while its recipe `timer` moved within `WORKING_GRACE_MS` (render-side, no sim flag). A mature tree that disappears is handed to `fellTree` (topples and fades, then is destroyed); trees in visible chunks sway (skew) unless zoomed far out. Everything runs only for on-screen buildings and visible chunks.
- **Sound** (`src/audio`): `GameRenderer.onSound(id, x, y)` is called for sound-worthy changes on screen (an action's `sound` frame, building ambience, tree falls, sword blows when hp drops, new arrows, finished buildings); `main.ts` forwards it to `AudioEngine.at`, which attenuates by distance to the camera centre, pans, and rate-limits (`mix.ts`: `attenuation`, `panOf`, `RateLimiter` — pure, unit-tested). Every sound is a WebAudio recipe in `sounds.ts`; the music is a generative pad + pentatonic plucks + birds scheduled in `AudioEngine.update()`. The context is created on the first pointer/key gesture; mute/volume/music persist under `localStorage['settlers.audio']` (all storage access guarded). **To add a sound:** a `SoundId`, a recipe in `RECIPES`, and a trigger (an `ActionDef.sound`, a `BuildingFx.sound`, or a renderer `sound(...)` call). The controls (`ui/audioControls.ts`) live in the options menu (passed to `Hud` from `main.ts`); `M` toggles mute.
- `Sprite.anchor` is taken from `texture.defaultAnchor` only at construction time. After you swap a texture with a different anchor, copy the anchor explicitly.
- Pixi gotcha: `container.removeChildren(begin)` throws when the range is empty. This once froze the whole game loop, because an exception inside the ticker stops it.

### UI and loop (`src/ui`, `src/main.ts`)
- **Start-up, menus and saves** (Settlers 4's flow, all art, words and music ours; roadmap 4.6): `main.ts` reads the address with `launchOf` (`ui/setup.ts`): no game parameter (or `?menu`) → `title()`: `TitleScene` (`ui/titleScene.ts`: a fixed-seed 64×64 world where the AI plays player 1, fast-forwarded `WARMUP_MINUTES` in slices, then rendered without fog with a slow camera drift; `flyIn` for the intro; `dispose` takes its renderer off the stage, the atlas stays), `Intro` (`ui/intro.ts`: a «click to begin» gate that unlocks audio and waits for the scene, then night → dawn CSS overlays, two captions and the wordmark over the camera flight, `AudioEngine.theme()` — our own horn tune; any click/key skips; shown on the first visit or when `Prefs.intro`), and `MainMenu` (`ui/menu.ts`, DOM over the scene, styles in `ui/menu.css`; arrow keys/Esc). «Новая игра» and «Сетевая игра» share `setupForm` (`ui/setupForm.ts`) over a `GameSetup` (pure, `ui/setup.ts`: `MAX_SLOTS` slots with `SlotKind` human/ai/remote/closed, team, `AiLevel`, race — `RACES`, only Romans `ready`; `setupProblem`, `worldArgs` → `World` options; `parseSetup` repairs JSON; the network mode allows `remote` slots and is not startable until phase 7). A game starts in the page (`game()`), without reload; quitting (`?menu`) and loading from the game (`?load=<id>`) reload. Game parameters (`DEV_PARAMS`: `?seed`, `?size`, `?players`, `?teams`, `?start`, `?levels`, `?ai`, `?fog`, `?art`, `?demo`, `?load`) skip the menu (`devWorldArgs`). **Saves:** `SaveSlots` (`ui/saves.ts`, over any `KeyValue`; `browserSlots()` = guarded localStorage): an index `settlers.saves` of `SlotMeta` plus one key per slot, gzip + base64 via `CompressionStream` (`pack`/`unpack`), `AUTO_ID` rewritten every `AUTOSAVE_MINUTES` of game time by `main.ts`, the old `settlers.save.v1` listed as `v1`; `savesPanel` lists them for loading or saving. **In-game menu:** `PauseMenu` (`ui/pauseMenu.ts`), opened by Esc when `InputController.cancel` has nothing to cancel (`onMenu`) or by the options page; sets `GameState.menu` (the input controller ignores keys and camera keys while it is set) and pauses, restoring the previous pause on close. `settingsPanel` (sound, art → `Prefs`, intro, language) is shared by both menus; `ui/prefs.ts` keeps `settlers.prefs` (art, intro). **AI difficulty** is sim data: `AI_LEVELS` in `config.ts` (multipliers on `AI.thinkEvery`, `attackRatio`, `peaceTicks`, `attackCooldown`, an `AI.maxOpenSites` offset, castle `bonus` goods), `WorldOptions.difficulty` per player index, saved as `AiState.level` (missing = medium); `ai.ts` reads the knobs through `tuning(ai)` — `medium` reproduces the `AI` table exactly (same games bit for bit).
- `main.ts` runs a fixed-step accumulator (`speed` multiplies real time, at most 20 ticks per frame) and passes `acc / TICK_MS` to the renderer as the interpolation alpha.
- `Minimap` (`ui/minimap.ts`) rasterises one pixel per tile (brightened by height) into an offscreen canvas, a slice of rows per frame so a full refresh takes about 2 s at any map size (`putImageData` of the dirty rows only), and draws it through the isometric transform; buildings and the camera frame are drawn every frame.
- **HUD layout** (Settlers 4's, our own art): `Hud` (`ui/hud.ts`) builds a fixed left panel `.side` (`--side-w`; `#game` starts right of it and Pixi `resizeTo`s it, so the panel never covers the map): the minimap framed on top (`Minimap` takes its width from `--mm-w`), gem buttons for the main menus, the content page and a readout (pinned goods, settlers, fighters, `strengthOf`). Each menu is a `View` (`ui/dom.ts`: `el`, `button`, `rowsTable`, `View { el, update(now) }`) mounted into the page and updated on the HUD throttle only while shown: `BuildView` (`buildMenu.ts`: category tabs, two-column grid with own-building counts, `typeAt` for digit hotkeys), `GoodsView` (`goodsView.ts`: stock + `DistributionView`), `SettlersView` (`settlersView.ts`: population, specialist commands — geologist/pioneer/thief are aimed from here, not the build menu — and `WorkersView`), `StatsView` (`statsView.ts`, samples `stats.produced` every game minute even while hidden), `ArmyView` (`armyPanel.ts`: strength bar, fighters by level, recruit level, weapon shares), `OptionsView` (`optionsView.ts`: speed, save/load/menu buttons that open `PauseMenu`, sound controls, help). Clicking a settler (`GameRenderer.settlerAt`: a screen-space hit test on the visible figures' body bounds, trimmed to the figure, front-most wins; checked before buildings in `InputController`) sets `GameState.selectedSettler` (exclusive with `selected`) and mounts `SettlerInfoView` (`ui/settlerInfo.ts`: portrait, owner, what it is doing from its head task in words, fighters' level and health, specialist send/dismiss); `markSettler` draws a ring and a bobbing marker over it in the `settlerMark` layer above the objects. Selecting a building mounts `InfoView` (`infoPanel.ts`: picture header, rows, all building commands; re-renders only when its key changes so its buttons stay clickable) in place of the menu, as in S4. Over the view: `.strip` top right (pause, speeds), `.hint`, and the `.ticker` (`Hud.toast`, last four messages, fade after 6 s). Styling is all CSS in `style.css` (wood/bronze frame, parchment from an SVG feTurbulence data URI, radial-gradient gems, Cinzel headings from Google Fonts with serif fallbacks) plus our own SVG glyphs (`ui/icons.ts`); never paste textures, icons or frames from the original's screenshots.
- **Economy UI** (`ui/economyPanel.ts`): `WorkersView` (worker orders, in the settlers menu) and `DistributionView` (distribution sliders, in the goods menu), plus building-window parts the info window appends — `toolOrderControls` (orderable recipes), `warehouseControls` (accepted goods), `economyRows` (mine favourite food and attempts, refused goods) and `economyKey` (part of the info window's re-render key).
- **Army selection** (`InputController`): with nothing being placed, a left drag draws the `.selbox` and selects own fighters whose feet are inside (`GameRenderer.settlersInRect`); a click on an own fighter or specialist selects him (shift toggles, a double click within `DOUBLE_CLICK_MS` takes every own unit of that kind on screen; `ownUnits`: fighters + `isSpecialist`); right/middle drag pans the camera; a right click without a drag orders the selection (`order`: fighters — explored hostile military building → `orderAttack`, own one → `orderGarrison`, else `orderMove`; specialists — `orderSpecialists` with the building under the cursor). While units are selected, `updateHint` shows next to the cursor what a right click would do (`.order-hint`, one label per distinct order, recomputed on tile/selection change). `GameState.selectedUnits` holds the ids; the renderer rings them (`markUnits`), the HUD mounts `UnitsView` (`ui/unitsView.ts`: counts by kind (fighters by level), fighters' health, specialists at work, hold / garrison / dismiss specialists / deselect; it drops dead ids). `InfoView` of a done military building has «Вывести бойцов» (`releaseFighters`). Weapon share controls (`shareControls` in `armyPanel.ts`) handle any number of share-controlled outputs.
- `GameState` (`ui/state.ts`) is the shared mutable UI state (placing mode, selection, hover, speed). `InputController` handles the camera, placement, and selection. `Hud` is plain DOM rebuilt on a throttle.
- **Placement hints:** while a building type is chosen, `GameRenderer.drawHints` marks every spot in view where it fits (footprint centre; green on level ground, yellow where `needsLevelling`), testing only owned tiles, recomputed on view/type/territory/building changes and every 600 ms. The roof flag shows only once a building is in use (`occupied`: worker moved in, garrisoned, or built for worker-less types). With the 3D art (the default), staged buildings (`ART3D_STAGED`) draw `stage:<type>:<k>` instead of the cropped texture — 0 while uncleared, then by build progress — and door piles use one `pile:<res>:<n>` sprite per count, for every resource (Blender `lib.tag`/`show_stage` render the stages from one tagged model). Each kind of goods at a door has its own spot (`syncPile`: output to the right of the door, inputs and site materials to the left along the front wall, a second row after four kinds).
- **Work-area overlay** (`render/workArea.ts`, `WorkAreaLayer`): one `Graphics` right above the field marks, under the objects — a soft fill of the tiles within the radius, a rim and a centre ring, redrawn only when type/centre/radius change. `GameRenderer.sync` shows, in that order, `workAreaPreview` (set by `InputController` while `GameState.movingWorkArea` waits for the click that calls `setWorkArea`), the placement ghost's would-be area, or the selected building's.
- Placement: `World.canPlace` checks the footprint and door (it is used for the green/red ghost): terrain, ownership, connectivity and, except for mines, ground that is flat or levellable (`heightRange` over footprint + door ≤ `BUILD_DIG_SLOPE`; above `BUILD_MAX_SLOPE` the site needs a digger first). `World.placeBuilding` additionally requires an A* path from the castle door.
