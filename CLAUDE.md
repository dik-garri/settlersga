# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Browser prototype of a Settlers 3/4-style economy game: isometric 2D, sprites, TypeScript + Vite + PixiJS 8. UI text is in Russian. Original prototype spec (historical, describes only the first version): `docs/superpowers/specs/2026-10-06-settlers-prototype-design.md`. Long-term plan toward Settlers 4 parity, with phases and known tech debt: `docs/ROADMAP.md` — check it before starting a new feature and keep it current. Feature-by-feature comparison with Settlers 3/4 (sourced; what matches, what deliberately differs, what needs fixing, what is excluded): `docs/S4-PARITY.md` — check it when designing a mechanic that exists in S4, and update it with the roadmap. Out of scope by decision: magic (temples, priests, mana — and with it wine, whose only S4 use is magic), the Dark Tribe, a map editor; for now also ships and harbours, and war machines.

## Workflow

Once a change is verified (tests and typecheck pass, and the game has been checked in the browser when rendering or UI changed), commit and push to `origin main` without asking. Update `README.md` (player-facing, in Russian) and this file in the same commit whenever the change affects them.

## Scalability is a hard requirement

The target is Settlers 4 scale, so every change must scale along three axes:
- **Content:** a new building, profession, resource or recipe is a data entry in `config.ts` (plus a sprite), never a new `if (type === ...)` branch in sim logic. If a feature cannot be expressed as data, extend the data model (a new `Behavior`, a new rule table) rather than special-casing a type.
- **Players:** everything that belongs to someone carries an `owner` (`PlayerId`); logic filters by owner and never assumes a single player. `LOCAL_PLAYER` is only a default for UI-facing calls.
- **Size:** no hard-coded map dimensions or population assumptions; per-tick work must stay roughly proportional to active entities, not to map area or to entities squared. Measure with the hour-long probe before and after.

## Deployment

Every push to `main` builds the game and publishes it to GitHub Pages (`.github/workflows/pages.yml`: `npm ci`, `npm run build`, deploy `dist/`) at https://dik-garri.github.io/settlersga/. `vite.config.ts` uses a relative `base` so the build works under the repo sub-path. Tests do not gate the deployment, so run them before pushing as described above.

## Commands

```bash
npm run dev            # Vite dev server
npm test               # Vitest, all tests (tests/*.test.ts)
npx vitest run tests/world.test.ts          # single file
npx vitest run -t "builds a site"           # single test by name
npm run typecheck      # tsc --noEmit (strict, noUnusedLocals/Parameters)
npm run build          # typecheck + vite build
npm run sim:probe      # economy health: standard opening, 60 min on 4 seeds (--seeds= --minutes= --size=)
npm run sim:bench      # sim performance: 256×256 map, 1000 settlers (--size= --settlers= --ticks=)
npm run sim:ai         # computer players, headless: AI vs AI or vs a passive player 1 (--passive=1 --seeds= --minutes= --cost=1)
npm run art:render     # Blender: re-render the 3D sprite pilot into public/art/3d (-- carrier woodcutter tree deposit log)
npm run art:ground     # Blender: regenerate the seamless ground textures (grass) into public/art/3d
```

Long simulations need more than Vitest's 5 s default; `vitest.config.ts` sets a 60 s test timeout and excludes `.claude/` (agent worktrees). Run `sim:probe` before and after any change to economy logic or balance, and `sim:bench` before and after anything that touches per-tick work. Reference numbers (Apple Silicon): 256×256 with 1000 settlers ≈ 1.0 ms/tick (the bench supplies every profession's tool so every workplace is staffed), 3000 settlers ≈ 2.9 ms/tick; a 64×64 hour of play ≈ 0.02 ms/tick; a 512×512 map with 4 AI players generates in ≈ 0.3–0.4 s and plays at ≈ 0.4–0.6 ms/tick in its first minutes.

Run `sim:ai` after any change to the AI, the economy or combat (it shows whether computer players still grow and still finish games). Append `?seed=N` to the dev URL for a reproducible map (the seed is logged to the console) and `?size=N` for another map size; `?players=N` sets the number of players (browser default 2, every player but 1 computer-controlled; `?ai=off` keeps them passive); `?fog=off` hides the fog of war; `?load=1` restores the browser save slot. `window.world` (plus `state`, `renderer`, `camera`, `audio`) exposes the live game for poking from DevTools, e.g. `world.placeBuilding('sawmill', x, y)` or calling `world.step()` in a loop to fast-forward.

## Architecture

Three layers with one-way dependencies: `ui → render → sim`, plus `src/audio` (WebAudio, imports only render-side data types) wired up in `main.ts`. `src/sim` must stay free of DOM/Pixi imports so it runs headless in Vitest.

### Simulation (`src/sim`)
- `World` (`world.ts`) holds all state and the public API and advances with `step()` at a fixed 10 ticks/s (`TICKS_PER_SECOND`). Logic lives in sibling modules that take the world as first argument: `buildings.ts` (creation, workshop recipes, territory), `settlers.ts` (task execution, per-behavior idle logic, `abort`), `logistics.ts` (dispatcher, demand), `nature.ts` (trees, planting, gather rules), `military.ts` (garrisons, recruiting, attacks, duels, conquest, `killSettler`). Fields those modules mutate are public on `World` under "Internal state shared by the sim modules".
- It is deterministic: all randomness goes through the seeded `Rng` (`rng.ts`). Never use `Math.random` in sim code.
- Tile coordinates are integers, and a tile's center is the integer point. Settlers store float `x/y` plus `px/py` (the position at the previous tick) so the renderer can interpolate.
- `GameMap` (`map.ts`) is flat typed arrays indexed by `idx(x, y)`: `terrain`, `tree` (0 means none, 1..`TREE_MATURE` are growth stages, and any tree blocks movement), `stone` (units left in a deposit; blocks while > 0), `owner` (player id, 0 = nobody), `building`, and `door` (both hold building ids, 0 means none). `height` is different: one value per tile **corner**, (w+1)×(h+1), in screen pixels; vertex (vx, vy) is the corner at tile coordinates (vx − ½, vy − ½). Read it through `vertexHeight`, `heightAt` (bilinear, fractional tile coordinates; a tile center is the mean of its corners) and `heightRange`. Heights are generated from the terrain and the height noise (`elevate` in `map.ts`, no RNG use); at runtime only diggers change them, through `setVertexHeight`, which bumps the `heightVersion` of every chunk touching the corner.
- Every building has a **door tile** (`doorOf`: `(x+w-1, y+h)`, in front of the lower-left wall). It is walkable but not buildable. All pickups and drops happen there. For warehouses (`storage: true`, e.g. the castle), `output` is the stock.
- **Settlers run a task queue** (`Settler.tasks`, union type `Task` in `types.ts`). `updateSettler` executes the head task each tick. An empty queue calls `idle()`, which switches on the profession's `Behavior` from the `PROFESSIONS` table (carrier, builder, digger, gather, plant, farm = harvest if ripe else sow, workshop, garrison, prospect, soldier). Workers are carriers converted by the `become` task.
- **Reservation invariant:** jobs reserve resources up front (`outReserved` on the source, `inbound` on the destination, `reservedTargets`, `reservedPlots`, `builderId`, `diggerId`, `workerRequested`). Any job that can fail must go through `abort()`, which walks the *remaining* tasks and releases what they hold. When you add a task type that reserves something, add its release to `abort()`. `tests/world.test.ts` checks that counters never go negative and that planks and stone are conserved.
- **Connectivity invariant:** anything that turns a walkable tile into a blocked one at runtime (forester planting, natural tree spread, building footprints via `canPlace`) must first pass `staysConnected` (`pathfinding.ts`): a conservative local check that blocking the tile does not cut any route. `regions.ts` relies on it: walkable regions are a union-find that never needs splitting, so `findPath` rejects unreachable goals in O(1) instead of flooding the map. Anything that makes a tile walkable at runtime must call `markWalkable` (harvest already does).
- **Terrain is data:** `TERRAIN` in `config.ts` holds per-terrain rules — `walkable`, `build` (`'ground'` for ordinary buildings, `'mountain'` for mines, or null), `plantable` (trees, fields, natural spread), `speed` (walking factor ≤ 1; A* charges `TERRAIN_COST` = 1/speed per entered tile, so the octile heuristic stays admissible; settlers spend their per-tick budget at that speed), `water` (wells, fish) and the minimap `rgb`. Sim code reads only the table: `map.isPassableTerrain`, `isBuildable(x, y, ground)` (a `Terrain` argument stands for the kind it accepts), `isPlantable`. **To add a terrain:** a `Terrain` code, a `TERRAIN` entry, a generation rule, and a ground sprite (`GROUND_COLORS`, `paintGround`, a place in `GROUND_PRIORITY` for transitions, `TERRAIN_KIND` in the renderer); `elevate` needs a height case.
- **Map generation** (`generateMap`): height/forest/ore noise from the main RNG, then features that use their own RNG streams so they never shift the rest of the generation: `addRidges` (mountain chains, strength grows with map size from nothing on 64×64) and `carveRivers` (`RIVERS_PER_64`, steepest descent with meander from high ground into water or a small lake, sandy banks, a `Terrain.Ford` — walkable shallow water — every `FORD_EVERY` tiles on a straight stretch, so rivers never cut land apart; they keep `RIVER_START_CLEARANCE` from every start), then `addBiomes` (its own RNG stream too: a moisture noise and a BFS distance to water turn dry grass far from water into `Terrain.Desert` and wet low ground near water into `Terrain.Swamp`, `BIOMES` thresholds, nothing within `startClearance` of a start). Start areas are prepared after that.
- **Digging:** every site except mines (`needsDigger`) is placed with `levelled = false`: a digger first clears it, `clearStrokes(b)` spade strokes (`CLEAR_STROKES_PER_TILE` per footprint tile) counted in `b.dug`, after flattening it if needed — sites whose footprint + door corners vary by more than `BUILD_MAX_SLOPE` (up to `BUILD_DIG_SLOPE`) get a `levelTo` height, flat ones `levelTo = −1` (`digging.ts`). Carriers deliver materials meanwhile; builders and builder recruitment ignore uncleared sites. Players start with `START_DIGGERS`; carriers are recruited as extra diggers (with a shovel, in `dispatchFor`, like builders) only for sloped sites, so clearing never eats the foresters' shovels. Diggers take a site via `diggerId` and run the `dig` task, moving one corner one pixel towards `levelTo` every `DIG_EVERY` ticks (`levelStep`), then clearing. `abort` releases `diggerId`.
- **Tile change tracking:** every runtime write to `map.tree`, `map.stone`, `map.crop`, `map.prospected`, or `map.oreAmount` reaching 0 must be followed by `map.touch(i)`, which bumps the tile's chunk version; the renderer re-scans only changed chunks.
- `findPath` reuses per-map scratch buffers (cost follows nodes explored, not map area) and counts work in `pathStats` for the bench.
- **Failure handling:** a `goto` with no route calls `routeFailed`: the job's target building gets `unreachableUntil` (logistics, builders and storage lookup skip it via `isReachable`), the job is aborted and the settler waits `PATH_FAIL_BACKOFF` ticks instead of retrying every tick. `abort()` sends goods in hand back to the nearest warehouse (`drop` with `back: true`); only if that trip fails too is the unit counted in `stats.lost`. Builders without material for `BUILDER_STALL_TICKS` move to a site that has some.
- **Logistics:** `dispatch()` runs every `DISPATCH_EVERY` ticks, per player, and hands work only to that player's idle carriers, in this priority: worker requests, then demands (`demand()`: site materials from `cost`, workshop inputs from `recipe.inputs`; served one unit per round to the least-stocked consumer so scarce goods are shared, each from the nearest supply), then producers' surplus carried to the nearest warehouse. Distances use straight lines; A* (`pathfinding.ts`, 8-way, no corner cutting, `adjacent` mode for blocked targets such as trees) runs lazily inside the `goto` task, and the route is recomputed when the next tile becomes blocked.
- **Buildings are data** (`BUILDINGS` in `config.ts`): `cost`, `worker`, `category` (build-menu tab), `storage` (warehouse), `recipe` (workshop inputs → outputs per `ticks`, run by `updateBuilding` while the worker is inside), `territory` (radius), `residence` (releases `capacity` carriers; the only source of population growth). **Gatherers and planters** share code paths: a profession's `gather` def plus `GATHER_RULES` in `nature.ts` (which tile yields a resource and what taking it does), and a `plant` def plus `PLANT_RULES` (`tree` blocks and must pass connectivity, `grain` fields stay walkable). A new gathering/planting profession is a `PROFESSIONS` entry plus, for a new resource or planting kind, a rule.
- **Mining:** `Terrain.Mountain` is walkable and only accepts buildings with `terrain: 'mountain'` (`canPlace` passes the terrain to `isBuildable`); `Terrain.Rock` stays impassable. Ore lives in `map.ore` (kind code = `ORE_RESOURCES` index + 1, decode with `oreOf`) and `map.oreAmount`. A mine is a workshop whose recipe uses `inputsAnyOf` (any one food; alternatives share one input pile limit in `demand()`) plus `def.mine`, which makes each cycle take one ore unit from the nearest matching tile in range (`findOreTile`). The geologist is a carrier on an errand (`sendGeologist` sets `kind = 'geologist'` and a list of `goto`/`prospect` tasks; the `prospect` behavior turns him back into a carrier when the queue empties; unreachable tiles are skipped in `routeFailed`). Results go to the per-player bitmask `map.prospected`.
- **Tools:** a profession's `tool` must be fetched before taking up the job: worker requests in `dispatchFor` add a `goto`/`pickup` of the tool from the nearest pile, and `become` (or `retool` for builders, recruited when sites outnumber builders) consumes it. A recipe with `outputChoice` (the toolsmith) makes whatever `chooseOutput` says is most awaited (`waitingFor`) or below `keepInStock`, and idles otherwise.
- **Player commands** live on `World` (`placeBuilding`, `sendGeologist`, `setPriority`, `demolish`, `attack`, plus the `availableAttackers` query) and take a `player`. `priority` puts a building first in the fair demand ordering and in builders' choice. `demolish` aborts every job referencing the building (goods in hands go back to storage), turns its worker back into a carrier, clears the tiles (with `markWalkable`) and lets the renderer drop the views on the next sync.
- **Surplus hauling:** producers' surplus goes to the nearest warehouse unless the player already stores `RESOURCE_INFO[res].storeLimit` units (only water has one); then goods wait at the producer, its full pile pauses it, and carriers stay free. Resource names, stock-panel groups and limits live in `RESOURCE_INFO`; the HUD draws resource icons with the ware painters (`wareIcon`), so a new resource needs no UI changes.
- Nature rates are expressed per 64×64 of map and scaled by area (`scaled()` in `nature.ts`), so a bigger map is not a slower world. Fields (grain; the mechanism is per kind, ready for other races' crops) are `map.crop` (stage) + `map.cropKind` (`CROP_KINDS` index), listed in `World.fields` (derived, rebuilt on load, iterated in sorted order to keep the RNG sequence identical after a load). Harvest rules (`GATHER_RULES`) decide what happens to the tile: grain is cleared (a perennial crop would drop back to an earlier stage instead).
- **Players:** `new World(seed, { players })` places one castle per player at `startPositions` (map center for one player — identical to the single-player map — otherwise on a circle); `generateMap` prepares the guaranteed start area (meadow, grove, quarry, coal/iron mountain, pond) around every start. Each player has its own castle (`castleOf`), settlers, dispatch round and territory.
- **Military** (`military.ts`): fighters are the professions with a `combat` def (`FIGHTERS`, `isFighter`; `soldier` = swordsman, `archer` with `combat.ranged`), each carrying a `level` (index into `SOLDIER_LEVELS`: hp and damage multipliers, `maxHp`). Buildings with `def.garrison` hold them (`Building.garrison` ids; `garrisonInbound`/`garrisonArchersInbound` reservations released by `releaseJoin` from `abort` on `join`). The `GarrisonDef` is the whole defence rule set: `capacity`, `keep` (never given away — neither to man other buildings nor to attack; default `GARRISON_KEEP`; `spareSoldiers` respects it), `archers` (slots reserved for ranged fighters), `defense` (damage multiplier for defenders at their own door), `trains` (promotes with gold). `staffGarrisons` (called from the dispatcher) first gives every empty outpost one fighter from the nearest donor, then fills outposts from reserves and from outposts further from the enemy (rear → front only); it never creates fighters. **New fighters come only from a barracks** (`def.barracks: { ticks }`, worker profession `recruit`): `demand` brings it weapons (`weaponsWanted`, any fighter's tool up to `INPUT_CAP`); while `wantsRecruit` holds (a weapon in its pile, ≥ `BARRACKS_MIN_IDLE` idle carriers, more free garrison room than fighters already looking for one) the dispatcher's ordinary worker request turns a carrier into the recruit; `updateBarracks` trains him for `ticks`, then he takes the weapon the player's army is shortest of and leaves as that fighter, homeless (`soldierIdle` sends him to the nearest garrison with room), counted in `stats.trained`. Weapons come from the weaponsmith's `outputChoice`; `waitingFor` counts empty garrison slots per weapon. **Weapon shares:** `OUTPUT_SHARES` (data: default weights, e.g. sword 60 / bow 40) marks share-controlled outputs; `World.setShare(res, weight, player)` / `shareOf` hold each player's weights (`Player.shares`, saved). `chooseOutput` first checks that something is awaited at all, then, when every choice is share-controlled, makes the one furthest below its share (`mostBehindShare`: holdings = units available plus fighters carrying it); the barracks picks the weapon the same way (holdings = fighters). `attack()` sends spares within `ATTACK_RANGE`, alternating melee and ranged; the attacker's `assault` task calls out one defender at a time (swordsmen first; `opponent` links both; defenders stand and fight in `updateSettler`), blows land every `FIGHT_EVERY` ticks via the world RNG with probability proportional to strength (`blow`: level damage × `combat.melee`, × `defense` for the defender). Ranged damage (`shoot`) is applied instantly: attacking archers shoot defenders busy duelling within `ranged.range`, garrison archers shoot assailants approaching their building (`assaultsByTarget`, built once per tick); `World.shots` is a visual-only list (not saved, pruned after `SHOT_TICKS`). `updateGarrison` heals fighters inside every `HEAL_EVERY` ticks and, in `trains` buildings, spends `PROMOTE_COST` × `PROMOTE_RES` every `PROMOTE_TICKS` to raise the weakest fighter one level (castles from their own stock, others from gold that `demand` requests via `goldWanted`). An empty enemy building is conquered: owner flips, territory is recomputed, and enemy non-military buildings on foreign land are removed via `World.removeBuilding`.
- **Computer players** (`ai.ts`, `World.ai`, enabled per player with `new World(seed, { ai: [ids] })`): the hard rules are (1) act only through the public player commands with the AI's own player id — never mutate world state directly or call internal helpers that do; (2) see only what that player could see — ore counts only where its own geologists prospected; enemy buildings exist for it only once their door tile is explored (`knownEnemies`), their garrison is counted only while in its buildings' sight (`inBuildingSight`), else guessed as `AI.unseenGarrison` × capacity; resources beyond its border count only on explored tiles. It reads only fog state that survives a load (explored bits, building sight — never `isVisible`, whose settler part is not saved); `World.step` calls `ensureVision` first so a loaded game rebuilds sight before the AI thinks. While it knows no enemy building it scouts: towers lean towards foreign land in sight, else towards unexplored land and the map center (`AI.scoutCenter`). A mine it cannot place sets `wantOre` (towers weigh mountains more, a geologist goes to the nearest unprospected own mountain); gatherers of `AI.exhaustible` resources (stone) with nothing left in range are demolished so the plan rebuilds them elsewhere; no new outposts while a known enemy military building is within `ATTACK_RANGE` (soldiers are kept for the attack); it sets its weapon shares once (`AI.weaponShares`) through `setShare`; (3) be deterministic and keep all state in the plain-data, saved `AiState` (no RNG of its own, ties broken by tile index); (4) bounded cost — think every `AI.thinkEvery` ticks, score only own territory tiles with cheap checks (`fits`) and spend `canPlace` on the best `AI.placeTries` spots, back off `RETRY_TICKS` after a failed search (`blockedUntil`). Behaviour is data: `AI_PLAN` (ordered build targets with `after` prerequisites) and the `AI` tuning table (houses by idle + still-to-come carriers, tool reserve `keepTools` so the first building of a type keeps the last tool — this prevents the coal-mine/pickaxe deadlock, manning discipline `homeGuard` (counting spares in every military building plus weapons in stock), frontier outposts towards the nearest enemy once it has `frontierSoldiers` — the largest garrison type it can afford and man —, attack after `peaceTicks` when the strength of the party `attackerComposition` would send (level damage × `combat.melee`) beats `attackRatio` × defenders × the target's `defense`).
- **Victory/defeat:** losing one's castle (conquest in `military.ts`) calls `World.defeatPlayer`: the player goes to `World.defeated` (saved), its settlers die via `killSettler`, its buildings are removed and territory recomputed; its AI stops thinking. `World.outcome(player)` is `'won'` once every other player is defeated. The HUD shows the end screen once `outcome(LOCAL_PLAYER)` leaves `'playing'`. Note `castleOf(p)` of a defeated player returns the conqueror's building.
- **Fog of war** (`fog.ts`, per player): `map.explored` is the saved bitmask of what each player has ever seen; current sight is derived (`World.fog`, never saved): `vision` (bit per player) from buildings — finished ones see `territory + FOG.territoryMargin` (or `FOG.buildingRadius`), sites `FOG.buildingRadius` — rebuilt only when `World.buildingsVersion` (bumped in `addBuilding`/`removeBuilding`) or `territoryVersion` changed, plus per-player `seenUntil` ticks that outdoor settlers stamp around themselves every `FOG.settlerEvery` ticks. Cost: O(settlers × disc) every few ticks plus O(map) per building change. Query with `World.isExplored` / `isVisible`; `inBuildingSight` is the building part alone (what the AI may use).
- **Removing settlers:** only through `killSettler`: it aborts the settler's jobs, frees its opponent, and clears every reference (`garrison`, `workerId`, `builderId`). The settler stays in `World.settlers` (skipped by `step`) until `removeDead` at the end of the tick, so loops never splice under iteration. A new field that references settlers must be cleared there too.
- **Territory:** `map.owner` holds the owning player per tile. `recomputeTerritory()` rebuilds it from scratch out of buildings that `claimsTerritory` (worker-less ones once done, workplaces once staffed, military buildings while garrisoned or always for the castle); where claims overlap the nearest claiming building wins (ties: the earlier one) and bumps `territoryVersion`, which the renderer polls to redraw the dimming and border. `canPlace` requires the footprint and door to be owned; `isGatherTarget` and `canPlant` only accept owned tiles, so gatherers and foresters never work outside the border.
- `addBuilding` moves any outdoor settler standing on the new footprint to the door tile, so nobody is walled in by a site placed on top of them.
- Building costs are multi-resource (`cost: Partial<Stock>`); always read them through `costOf()` / `totalCost()`. Construction takes one work shift per delivered unit of any material.
- **Save/load** (`save.ts`): `saveWorld` snapshots everything to plain JSON (map layers as base64, `Rng.state`, buildings in id order); `World.load` restores it, and `tests/save.test.ts` asserts a loaded world continues bit-for-bit like the original. When you add simulation state, add it to `SaveData` and bump `SAVE_VERSION` if old saves can no longer load. Keep sim state plain data (no closures, class instances or functions) so it stays serializable.
- Tunables (timings, caps, costs, start resources) live in `config.ts`.

### Rendering (`src/render`)
- Isometric projection is in `iso.ts`: tile center `(x, y)` maps to screen `((x-y)*32, (x+y)*16)`. Depth equals `x + y`. `objects` is a single `sortableChildren` container keyed by `zIndex`. Buildings use the depth of their footprint center plus 0.25, the door pile and flag use the door tile's depth minus 0.05, and settlers use their interpolated depth.
- **Terrain heights:** ground is one `MeshSimple` per chunk whose vertices are the tile corners raised by `map.height` (shared corners, so no seams), textured from the ground sprites in the atlas (they must all sit on one atlas page, which the builder asserts). **Transitions:** after each tile's own quad come overlay quads of its higher-priority neighbours (`GROUND_PRIORITY`: water < ford < swamp < sand < desert < grass < mountain < rock), using `edge:<kind>:<dir>` sprites (`paintGroundEdge`: the neighbour's ground faded in from that edge/corner with a ragged border, `EDGE_DIRS`); corner overlays are skipped where an edge neighbour of the same kind already covers them. Each chunk also gets a `Graphics` with slope shading lit from the top-left (`slopeLight`, quantised levels). Everything standing on the ground is placed with `surface(x, y)` (screen point minus `heightAt`), outlines (territory, hover, ghost, selection, geologist area) use `corner()` per tile corner, chunk culling bounds are lifted by the chunk's highest corner, and `pickTile` refines the flat inverse projection a few times by the height under the guess. Never place a world object with plain `toScreen` any more. **Runtime height changes:** `syncHeights` (throttled) rebuilds the ground (`buildChunkGround`), territory overlay and culling bounds of chunks whose `heightVersion` changed and re-seats their static objects (`addStatic` records each object's tile and offset from the surface) and field decals.
- `GameRenderer.sync()` reconciles by **polling sim state every frame** (view maps keyed by building and settler id; trees/deposits only in chunks whose `chunkVersion` changed; territory only in chunks whose owners changed). The sim emits no events, so new sim state only needs a matching branch in `sync*`.
- **Culling by chunk** (`CHUNK` = 16 tiles): ground, territory overlay and static objects (trees, rocks, deposits, buildings) are registered per chunk via `addStatic`/`removeStatic` and sit in the scene only while their chunk intersects the camera's `viewRect`; settlers join `objects` only while on screen. Per-frame sorting and drawing therefore follow the screen, not the map. New world objects must go through `addStatic` rather than `objects.addChild`.
- **Lazy chunks** (what makes 512×512 start fast): `buildGround` only records heights; a chunk's ground mesh, boulders and territory are built by `ensureChunk` the first time it becomes visible (`chunkReady`), at most `CHUNK_BUILDS_PER_FRAME` per frame so a zoom-out never hitches. Tile objects (trees, deposits, fields) are synced only for visible chunks — `syncChangedTiles` leaves a hidden chunk's version stale and catches up when it scrolls in; territory for unbuilt chunks is deferred via `territoryPending`. Anything per-chunk you add must be built in `ensureChunk` and tolerate a chunk that was never built.
- All art is procedural: painters in `sprites.ts` draw with Canvas 2D, and `SpriteAtlas` (`atlas.ts`) packs them into 2× resolution canvas pages (a new page starts when one fills; the last page is cut to the rows it uses) with `defaultAnchor` set per frame. Most buildings are described by a `Style` in `STYLES` (walls, roof, floors, decorations like chimney/well/pen) painted by `paintStyled`; only special shapes (castle, mill, tower…) have hand-written painters. Fields are flat decals added to their chunk's ground container. Building painters draw around the **footprint center as origin** and use the `P(dx, dy, z)` helper (tile-unit offsets plus pixel height); their canvas size and anchor live in `BUILDING_CANVAS`. Construction progress is shown by cropping the building texture from the top (`bottomPart`). To add a sprite, write a painter and register it in the `SpriteAtlas` constructor.
- **3D sprite pilot** (`?art=3d`): `art/blender/build.py` (helpers in `lib.py`) builds models with bpy and renders them with an orthographic camera matching `iso.ts` (rot 60°/0/45°, world X = tile x, world Y = −tile y, `PX_PER_UNIT` logical px per tile unit, 2× resolution, Cycles, shadow catcher on a transparent background, palette written in sRGB and converted by `lib.lin`) into `public/art/3d`; run `npm run art:render [-- names]` (Blender 5.x on PATH). Each sprite keeps the size/anchor convention of the procedural sprite it replaces (`ART3D_SPRITES` in `art3d.ts` must match `SINGLE` in `build.py`). `main.ts` loads them (`loadArt3d`) and `SpriteAtlas` re-registers them under the procedural keys (`building:woodcutter`, `tree:*`, `deposit:*`, `ware:log`); the carrier is a sheet `c3d:<dir>:<column>` in `DIRS` order (no mirroring; walk frames, stand, then the same carrying) with `carryAt`/`carryBehind` from `carrier.json`, used by `syncSettlers` instead of the layered figure. Read hand positions from the evaluated depsgraph (`hand_point`), and call `view_layer.update()` before parenting parts to pivots, or offsets double. The look follows Settlers 4 (reference: in-game shots at settlers4-hd.com, kept out of the repo): `mat_stones` (Voronoi fieldstone), `mat_tiles` (terracotta), `mat_grain` (wood, thatch, bark, earth), `mat_leaves`, `apply_ao` (base colour × AO in every material) and `clean_alpha` post-processing (saturation, contrast, unsharp); buildings stand on a trodden-earth `pad` (solid core, then a noisy alpha fringe from a per-vertex `edge` attribute plus two noises, so the earth breaks up into the game's grass instead of ending in a line); `transform_apply` must keep location (`location=False`), or origins jump to the world origin. Style notes from the original (and what we deliberately do not copy, e.g. outlines) live in `docs/ART-STYLE.md`; reference screenshots stay in the git-ignored `examples/`. Quarry stone is `lib.spire` columns with `mat_crystal`. Building models beyond the woodcutter live in `art/blender/buildings.py` (sawmill, stonecutter, tower, house_large; shared helpers such as `log_cabin`, `plank_roof`, `stakes`, `timber_frame` are reached through `__main__`, i.e. build.py), with `stone_course` (rugged blocks of mixed tones over a dark core) and `slate_roof`; `ART3D_BUILDINGS` in `art3d.ts` lists every 3D building with its canvas (= `BUILDING_CANVAS`, = `SINGLE` in build.py), and all of them have stages. A 3D military building records where its banner pole stands (`note_banner` prints it while rendering) in `ART3D_BANNERS`, which overrides `BANNERS` under `?art=3d`. HTML icons (`buildingIcon`, `wareIcon`, `settlerIcon` in `atlas.ts`) use the 3D images when loaded, cropped to their opaque bounds. **Ground textures** (`art/textures/ground.py`, `npm run art:ground`, runs in Blender for numpy): grass is combed tapered strokes along a slowly swaying direction field over band-limited broad swells of light and shade; a texture periodic over `PERIOD`×`PERIOD` tiles, sliced into diamonds exactly as `quadOf` samples them; the atlas registers them as `ground:<kind>:<v>` (`groundPeriod`), the renderer picks variant (x mod p) + p·(y mod p) so tiles join seamlessly, and transition overlays keep the procedural ragged mask filled with the texture.
- Player colours live in `PLAYER_COLORS` (`sprites.ts`); the only per-player atlas variants are `flag:<player>` (door flags) and `banner:<player>` (`paintBanner`: the owner's banner with an eagle on a crossbar over military buildings, at `BANNERS`) (fighters wear their owner's colour as a tint, see below). A fighter's level is drawn as a `chevrons:<level>` sprite above the head, and arrows (`World.shots`) as arcs in the `shots` Graphics layer above the objects. Territory chunks dim land that is not the local player's and draw every player's border as in Settlers 4: a post topped with a cube in the player's colour on every border edge (`drawBorder`). Settler views whose settler died are destroyed on the next sync; building flags follow ownership changes, and so do roof banners (`BANNERS` in `sprites.ts`: where the `flag:<owner>` sprite sits on every military building — building painters must not paint owner colours themselves). Duelling pairs are drawn at `FIGHT_SPOTS` offsets so simultaneous fights at one door stay apart.
- **Fog rendering** (local player, off with `?fog=off`): a `fog` container above `objects` and the arrow layer holds, per chunk, a soft-edged mesh: a (CHUNK+2)² canvas with one pixel per tile (one-tile margin) whose alpha is the tile's darkness (unexplored 1, explored out of sight 0.42), stretched over the chunk's height-raised tile corners with linear filtering, so darkness fades across tiles as in Settlers 4. `syncFog` (every 150 ms) compares each visible chunk's states (margin included, `fogPrev`) and redraws the canvas only on change; the mesh is rebuilt when the chunk's heights change. It also hides static objects standing on unexplored tiles (and `addStatic` hides new ones there). Other players' settlers are drawn only where the local player has sight; the minimap and the building info panel follow the same rules, and buildings under unexplored fog cannot be selected.
- **Settler animation** (`anim.ts` pure helpers, `animConfig.ts` data, `settlerArt.ts` painters): a settler is a container of layered sprites — `body` (shadow, legs, far arm), `tunic` and `hat` (painted grey, tinted per profession from `styleOf(kind)` or with the owner's colour for `fighter` styles), `head`, the near `arm` with its tool, the carried `ware` and the rank badge. Five directions are painted (`PAINTED_DIR`: E, SE, S, NE, N); W, SW and NW mirror them (`MIRRORED`, `root.scale.x = -1`); facing away (`FACES_AWAY`) the arm and goods go behind the body. Direction comes from the tick velocity (`dirFromTileVelocity`), the opponent or the work target (`workTarget`); walk frames from the distance walked (`walkFrame`, no foot sliding), work frames from time with a per-id offset (`workFrame`), idle settlers glance around (`idleDir`). Atlas keys: `sb:<pd>:<frame>`, `st:<pd>`, `shd:<pd>`, `sht:<hat>:<pd>`, `sa:hold:<tool>:<pd>:<frame>`, `sa:work:<action>:<pd>:<frame>`; identical arm poses are painted once and aliased. Textures for each layer are resolved once (`SpriteAtlas.settlerTextures()`), so the per-frame loop does no string lookups. **To add a profession look:** a `STYLES` entry in `animConfig.ts` (tunic, hat colour and `HatStyle`, `work` action, held tool). **To add a work animation:** an `ACTIONS` entry (tool, four arm angles in turns of π, loop length, optional sound on a frame) — the atlas paints it automatically; map tasks to it in `PLANT_ACTION`/`GATHER_ACTION` if it depends on what is gathered or planted. A new tool shape needs a case in `paintArm`.
- **Live effects** (`effects.ts`, painters in `fxArt.ts`): one `Effects` instance owns `fxLayer` (smoke, dust, leaves, sparks, hit flashes; above `objects`/arrows, under the fog) and `waterLayer` (sun glints, right above the ground meshes; a separate layer, the ground meshes are untouched). Particles are a fixed pool of `MAX_PARTICLES` sprites with typed-array state, recycled round-robin — nothing is allocated per frame. Building effects are data (`BUILDING_FX` in `animConfig.ts`: smoke always/while working, fire glow, mill sails, ambient sound) placed at anchors the building painters export (`buildingFxAnchors`, `MILL_HUB` in `sprites.ts`); glows and sails are children of the building's body container, so they cull with it. A workshop counts as working while its recipe `timer` moved within `WORKING_GRACE_MS` (render-side, no sim flag). A mature tree that disappears is handed to `fellTree` (topples and fades, then is destroyed); trees in visible chunks sway (skew) unless zoomed far out. Everything runs only for on-screen buildings and visible chunks.
- **Sound** (`src/audio`): `GameRenderer.onSound(id, x, y)` is called for sound-worthy changes on screen (an action's `sound` frame, building ambience, tree falls, sword blows when hp drops, new arrows, finished buildings); `main.ts` forwards it to `AudioEngine.at`, which attenuates by distance to the camera centre, pans, and rate-limits (`mix.ts`: `attenuation`, `panOf`, `RateLimiter` — pure, unit-tested). Every sound is a WebAudio recipe in `sounds.ts`; the music is a generative pad + pentatonic plucks + birds scheduled in `AudioEngine.update()`. The context is created on the first pointer/key gesture; mute/volume/music persist under `localStorage['settlers.audio']` (all storage access guarded). **To add a sound:** a `SoundId`, a recipe in `RECIPES`, and a trigger (an `ActionDef.sound`, a `BuildingFx.sound`, or a renderer `sound(...)` call). The controls (`ui/audioControls.ts`) are appended to the speed panel from `main.ts`; `M` toggles mute.
- `Sprite.anchor` is taken from `texture.defaultAnchor` only at construction time. After you swap a texture with a different anchor, copy the anchor explicitly.
- Pixi gotcha: `container.removeChildren(begin)` throws when the range is empty. This once froze the whole game loop, because an exception inside the ticker stops it.

### UI and loop (`src/ui`, `src/main.ts`)
- `main.ts` runs a fixed-step accumulator (`speed` multiplies real time, at most 20 ticks per frame) and passes `acc / TICK_MS` to the renderer as the interpolation alpha.
- `Minimap` (`ui/minimap.ts`) rasterises one pixel per tile (brightened by height) into an offscreen canvas, a slice of rows per frame so a full refresh takes about 2 s at any map size (`putImageData` of the dirty rows only), and draws it through the isometric transform; buildings and the camera frame are drawn every frame. The statistics panel samples `stats.produced` once per game minute in the HUD (UI-only history).
- `GameState` (`ui/state.ts`) is the shared mutable UI state (placing mode, selection, hover, speed). `InputController` handles the camera, placement, and selection. `Hud` is plain DOM rebuilt on a throttle.
- **Placement hints:** while a building type is chosen, `GameRenderer.drawHints` marks every spot in view where it fits (footprint centre; green on level ground, yellow where `needsLevelling`), testing only owned tiles, recomputed on view/type/territory/building changes and every 600 ms. The door flag shows only once a building is in use (`occupied`: worker moved in, garrisoned, or built for worker-less types). With `?art=3d`, staged buildings (`ART3D_STAGED`) draw `stage:<type>:<k>` instead of the cropped texture — 0 while uncleared, then by build progress — and door piles of `log`/`plank`/`stone` use one `pile:<res>:<n>` sprite per count (Blender `lib.tag`/`show_stage` render the stages from one tagged model).
- Placement: `World.canPlace` checks the footprint and door (it is used for the green/red ghost): terrain, ownership, connectivity and, except for mines, ground that is flat or levellable (`heightRange` over footprint + door ≤ `BUILD_DIG_SLOPE`; above `BUILD_MAX_SLOPE` the site needs a digger first). `World.placeBuilding` additionally requires an A* path from the castle door.
